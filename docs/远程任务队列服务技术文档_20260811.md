# WT 自动化远程任务队列服务技术文档

> 整理日期：2026-08-11
> 适用范围：WT_Automation 项目远程任务队列服务、只读服务器监控、客户端集成与后续扩展。

## 1. 背景与演进

本功能沿以下需求链逐步落地：

1. Simple 界面新增“新增及配置元素”卡片，排在“新增气象数据”之后。
2. Simple 界面每个卡片板块自动默认加载上次导入的文件，无需重复导入。
3. 新增服务器日志远程查看功能：用户不需要进入服务器实际软件端，在客户端即可查看运行状态、报错信息，避免他人误操作或重复发送排队请求。
4. 新增远程任务队列服务：支持发送排队计算任务、继续计算、终止计算，显示当前队列任务与任务进度，并按用户区分任务。
5. 对远程任务队列服务做全量检查与落地优化：统一队列数据库、增强输入防护、补充服务日志、优化 SQLite 与日志读取、完善客户端可用性。

6. 完善任务提交：Simple 勾选板块可批量提交远程队列，并支持选择本地 JSON 流程文件上传后提交。

本文档用于记录当前实现的结构、接口、数据模型、优化记录、已知限制与后续扩展路线，供“Simple 本地排队迁移到远程队列”“流程文件上传”“多机任务分配”等后续工作回顾。

## 2. 总体架构

```text
┌──────────────────────────┐          HTTP（8768，Bearer 令牌）          ┌──────────────────────────────┐
│   本地客户端 WT_Launcher  │ ───────────────────────────────────────────▶ │       自动化主机（服务器）      │
│   TaskQueueWindow        │ ◀─────────────────────────────────────────── │   wt_task_server.py（队列服务）│
│   ServerMonitorWindow    │   GET /api/tasks、POST /api/tasks/submit...   │   wt_server_monitor.py（8767）│
└──────────────────────────┘                                               └──────────────┬───────────────┘
                                                                                          │ 子进程启动
                                                                                          ▼
                                                                               WT_AUT_recorded.py
                                                                               （实际执行自动化任务）
                                                                                          │ 回写
                                                                                          ▼
                                                                               logs/task_queue.db
                                                                               logs/tasks/{taskId}.log
                                                                               logs/run_reports/{runId}.json
```

关键约定：

- 自动化主机：运行 `WT_AUT_recorded.py`、`wt_task_server.py`（8768）、可选 `wt_server_monitor.py`（8767）的机器。
- 本地客户端：运行 `WT_Launcher.py`，通过 HTTP 提交、查询和控制任务，不直接操作服务器软件端。
- 任务队列服务与自动化脚本必须同机部署，队列服务通过子进程启动自动化任务，两者直接访问同一个 SQLite 数据库。
- 只读监控服务无令牌；任务队列服务除 `/api/health` 外全部要求 `Authorization: Bearer <token>`。
- 同一时刻只运行 1 个任务，其余任务按 FIFO 排队。

## 3. 模块清单与职责

| 文件 | 职责 |
| --- | --- |
| `wt_run_status.py` | 共享运行状态发布模块，将状态原子写入 `logs/run_status.json`（临时文件 + `os.replace`）；文件缺失或损坏时返回默认 `idle` 状态。 |
| `wt_server_monitor.py` | 只读 HTTP 监控服务，默认监听 `0.0.0.0:8767`；提供状态、日志、最近报告读取。 |
| `wt_task_queue.py` | SQLite 队列层：任务提交、列表、FIFO 单例取任务、进度回写、暂停/继续/终止/取消、任务日志文件管理、审计事件、日志保留清理。 |
| `wt_task_server.py` | 任务队列 HTTP 服务，默认监听 `0.0.0.0:8768`；认证、路由（含流程上传）、后台调度线程、worker 子进程启动、服务日志、Webhook 通知、审计查询、日志保留清理。 |
| `wt_task_queue_window.py` | 客户端任务队列窗口：连接参数、任务列表、进度、日志、提交与任务控制、本地 JSON 上传、Simple 批量提交、只看我的任务、状态/关键字筛选、报告查看与另存、断线指数退避、2 秒自动轮询。 |
| `WT_Launcher.py` | 主控制台集成：Simple 工具栏“任务与监控”“提交所选板块到远程队列”入口；“检查与日志”区域的启动/打开/停止按钮；连接参数持久化。 |
| `WT_AUT_recorded.py` | 自动化执行脚本，新增 `--task-id/--task-user/--task-db`，任务生命周期内回写队列状态与进度。 |

## 4. 数据模型

### 4.1 任务表 `logs/task_queue.db`

SQLite 表 `tasks`，主要字段：

| 字段 | 说明 |
| --- | --- |
| `task_id` | 主键，形如 `task_20260811_103000_xxxxxx` |
| `user` | 提交任务的用户名（客户端填写） |
| `source_ip` | 提交来源 IP（服务端自动记录） |
| `flow_path` | 服务器端流程文件绝对路径 |
| `steps_requested` | 请求执行的步骤 JSON 数组 |
| `notify_url` | 任务级 Webhook 回调地址，留空时使用服务端全局 `--webhook` |
| `from_step` / `to_step` | 起始/结束步骤 |
| `status` | `pending/running/paused/success/failed/canceled/terminated` |
| `progress_current` / `progress_total` / `progress_percent` | 进度信息 |
| `current_step_id` / `current_step_name` | 当前步骤 |
| `resume_from_step` | 暂停/继续时的恢复步骤 |
| `last_log` / `error` | 最近日志与错误信息 |
| `run_id` | 自动化产生的运行 ID，用于关联运行报告 |
| `pause_requested` / `terminate_requested` | 控制标记 |
| `attempts` | 已尝试次数 |
| `created_at` / `started_at` / `ended_at` / `updated_at` | 时间戳 |

队列层已启用 `PRAGMA busy_timeout = 15000`；文件数据库启用 WAL（内存库跳过）。

### 4.2 任务日志 `logs/tasks/{taskId}.log`

每个任务的完整日志独立落盘，由队列服务启动 worker 时重定向写入。HTTP 读取使用尾部倒读实现，只保留最后 N 行，避免大日志全量读入内存。

### 4.3 运行报告 `logs/run_reports/{runId}.json`

`GET /api/tasks/{id}/report` 按任务最新 `runId` 读取报告；文件不存在返回 404。

### 4.4 审计事件表 `audit_events`

SQLite 表 `audit_events`，记录提交与控制类操作，字段：`id`、`created_at`、`user`、`source_ip`、`action`（`submit/pause/resume/terminate/cancel/upload`）、`task_id`、`result`、`detail`。按 `task_id`、`user` 建索引。

### 4.5 状态发布 `logs/run_status.json`

监控服务读取的运行状态文件，字段包含 `status`、`isRunning`、`activity`、`lastLog`、`error`、`runId`、`startedAt`、`endedAt`、`updatedAt`、`source`。

### 4.6 客户端配置 `launcher_state.json`

保存 `serverMonitorUrl`、`taskQueueUrl`、`taskQueueUser`、`taskQueueToken` 等连接参数，启动时自动恢复。该文件含 API Key 与令牌，禁止进入验证输出或提交内容。

## 5. 任务状态机

```text
submit ──▶ pending ──claim──▶ running ──正常完成──▶ success
                │                │
                │                ├──异常──▶ failed ──resume──▶ pending
                │                │
                │                ├──pause 请求──▶ paused ──resume──▶ pending
                │                │
                │                └──terminate 请求──▶ terminated
                │
                ├──cancel──▶ canceled
                └──pause──▶ paused ──resume──▶ pending
```

行为说明：

- 运行中任务暂停：先设置 `pause_requested`，自动化在当前步骤完成后调用 `mark_paused`，并记录 `resumeFromStep`。
- 运行中任务终止：设置 `terminate_requested`，调度线程 kill 自动化子进程树并标记 `terminated`。
- 等待中任务暂停：直接转为 `paused`。
- `cancel` 仅对 `pending` 生效；`resume` 对 `paused/failed/terminated` 生效，重置后重新排队执行。
- 恢复执行时携带 `--from-step <resumeFromStep>` 和 `--skip-setup`，从上次断点继续。

## 6. HTTP API

### 6.1 只读监控服务（8767）

所有响应带 `Access-Control-Allow-Origin: *`；所有 POST/PUT/DELETE 均返回 405。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | `{"ok": true, "service": "wt_server_monitor"}` |
| GET | `/api/status` | 返回 `logs/run_status.json` 内容 |
| GET | `/api/logs?tail=300` | 返回 `{"lines": [...], "totalLines": N}`，默认读取 `wt_automation.log` 最后 300 行 |
| GET | `/api/report` | 返回 `logs/last_run_report.json`，缺失时 404 |

### 6.2 任务队列服务（8768）

除 `/api/health` 外全部要求 `Authorization: Bearer <token>`；所有响应带 CORS。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 公开健康检查，返回 `ok/service/version/uptimeSeconds/queueDb/runningCount/logRetentionDays` |
| GET | `/api/flows` | 列出服务器端 `flow_packages/*.json`（跳过 registry 与 `.bak` 文件） |
| POST | `/api/flows/upload` | 上传本地 JSON 流程到服务器 `flow_packages`（需令牌），返回 `flowPath/name` |
| GET | `/api/tasks?scope=all\|mine&user=xxx&limit=1..500` | 任务列表；`scope=mine` 必须带 `user` |
| GET | `/api/audit?taskId=&user=&limit=1..500` | 审计事件列表（默认最近 200 条），需令牌 |
| POST | `/api/tasks/submit` | 提交任务，body 含 `user/flowPath/steps?/fromStep?/toStep?/priority?/scheduledAt?/maxAttempts?/retryDelaySeconds?/timeoutSeconds?/notifyUrl?` |
| GET | `/api/tasks/{id}` | 任务详情 |
| GET | `/api/tasks/{id}/logs?tail=1..2000` | 任务日志尾部 |
| GET | `/api/tasks/{id}/report` | 按最新 `runId` 读 `logs/run_reports/{runId}.json`，缺失 404 |
| POST | `/api/tasks/{id}/pause` | 运行中标记暂停（当前步骤后停止），等待中直接暂停 |
| POST | `/api/tasks/{id}/resume` | 以 `resumeFromStep` 重新排队 |
| POST | `/api/tasks/{id}/terminate` | kill 自动化子进程树并标记 `terminated` |
| POST | `/api/tasks/{id}/cancel` | 仅对 `pending` 生效 |

错误码约定：

- `400`：参数/请求体非法（非法 JSON、非法 Content-Length、scope/limit/tail 非法、流程 JSON 无法解析、steps 类型非法等）。
- `401`：无令牌或令牌错误。
- `404`：路径或资源不存在。
- `405`：方法不允许。
- `409`：状态冲突（例如对非 running 任务 terminate）。
- `413`：请求体超过 1MB。

### 6.3 输入防护（本次优化新增）

- 请求体上限 1MB，超限返回 413；`Content-Length` 非法返回 400。
- `scope` 仅允许 `all/mine`，`mine` 必须带 `user`。
- `limit` 钳制到 1..500，非法返回 400。
- `tail` 钳制到 1..2000，非法返回 400。
- 提交前解析流程 JSON，非法文件返回 400。
- `steps` 仅接受逗号字符串或字符串/整数数组。
- 所有 POST 路由统一先校验请求体大小，控制端点同样受保护。
- 流程上传接口清洗文件名（保留中文与空格，去除路径分隔符/点号前缀），仅写入 `flow_packages`，防止路径穿越。
- 流程上传校验结构：`steps`/`flowPackages` 若存在必须是数组，避免把非流程 JSON 写入流程目录。
- 上传接口拒绝保留文件名：`flow_package_registry.json` 与含 `.bak` 的名称，防止覆盖注册表与备份文件。

### 6.4 Webhook、审计与日志保留（P0 可观测性）

- Webhook：支持全局 `--webhook <url>` 与任务级 `notifyUrl`；任务 `success/failed/terminated/canceled` 与服务停止时回调。
- 回调负载：`event/taskId/status/user/flowPath/error/progressPercent/runId/attempts/maxAttempts/reportPath/updatedAt`，`reportPath` 为只读报告 API 相对路径。
- 回调线程异步发送、超时 4 秒，失败只写服务日志，不影响任务状态。
- 审计：`submit`、`pause/resume/terminate/cancel` 控制操作与流程上传均写入 `audit_events`；`GET /api/audit` 可按 `taskId/user` 过滤。
- 日志保留：服务启动参数 `--log-retention-days`（默认 30），启动与调度循环每日清理一次过期 `logs/tasks/*.log`。
- `/api/health` 返回 `version/uptimeSeconds/queueDb/runningCount/logRetentionDays`，便于运维判断服务与清理配置。

## 7. 队列调度

- 使用标准库 `http.server.ThreadingHTTPServer` + 后台调度线程，默认 1 秒轮询。
- `claim_next_pending` 使用 `BEGIN IMMEDIATE` 保证单例运行：已有 `running` 任务时不再取任务。
- FIFO 顺序：`ORDER BY created_at ASC, rowid ASC`。
- worker 启动命令：

```text
python WT_AUT_recorded.py --no-monitor --task-id <id> --task-user <user> --task-db <db>
    [--steps ...] [--from-step ...] [--to-step ...] [--skip-setup]
```

- 调度异常、worker 启动失败、任务开始/结束均写入 `logs/task_server.log`，不记录令牌。
- `server_close` 设置停止事件后 join 调度线程（超时 3 秒），对运行任务加锁清理，避免关闭时与调度线程竞态。

## 8. 客户端使用

### 8.1 服务端启动

自动化主机：

```powershell
python wt_task_server.py --host 0.0.0.0 --port 8768 --auth-token <服务令牌> [--webhook <全局回调地址>] [--log-retention-days 30]
python wt_server_monitor.py --host 0.0.0.0 --port 8767
```

也可在 `WT_Launcher.py`“检查与日志”区域点击“启动任务队列服务”“启动服务器监控服务”；Launcher 会保存由它启动的本地进程句柄，并提供“停止任务队列服务”按钮，仅终止本控制台启动的进程，无远程停止接口。

### 8.2 客户端连接

1. 打开 `WT_Launcher.py`，Simple 工具栏点击“任务队列”。
2. 填写服务器地址（同机 `http://127.0.0.1:8768`，远程 `http://服务器IP:8768`）、用户名、服务令牌。
3. 连接参数自动保存到 `launcher_state.json`，下次打开自动恢复。

### 8.3 主要操作

- 提交任务：从服务器端流程列表选择，可填步骤/起始步骤/结束步骤，以及可选的通知 URL。
- 上传提交：任务队列窗口新增“提交本地 JSON 链路”按钮（Simple 工具栏也有同入口），选择自动化 JSON 链路文件，上传成功后弹出提交参数对话框再提交。
- Simple 批量提交：Simple 工具栏点“提交所选板块到远程队列”，会弹出确认对话框：可勾选要提交的板块、可追加多个自动化 JSON 链路文件、默认跳过服务器上内容未变化的流程（避免重复生成版本），确认后逐个上传并提交任务。
- 任务控制：列表选中任务后可“暂停/继续/终止/取消”。
- 查看进度：列表显示任务 ID、用户、状态、进度、当前步骤。
- 查看计划：任务列表新增“预约”列（scheduledAt），未预约显示 `-`，支持横向滚动查看全部列。
- 查看日志：选中任务后自动加载最后 300 行日志，带颜色分类。
- 查看报告：新增“查看报告”按钮，只读弹出 `/api/tasks/{id}/report` 的 JSON 内容。
- 只看我的任务：勾选后请求 `scope=mine&user=<当前用户名>`，缺用户名时提示并自动取消勾选。
- 状态筛选与关键字筛选：客户端本地过滤（任务 ID/用户/流程/步骤），不改变服务端数据。
- 报告另存为文件：“查看报告”窗口支持“另存为文件”，保存只读 JSON 报告。
- 断线指数退避：队列与监控轮询失败后按 1s/2s/4s/… 递增，上限 30s，服务恢复后自动回到 2 秒轮询。
- 自动刷新：默认 2 秒轮询。

## 9. 本次全量检查与优化记录（2026-08-11）

1. 统一 worker 与服务的队列库：`WT_AUT_recorded.py` 新增 `--task-db`，所有队列状态回写显式使用同一 DB；`TaskServer` 启动 worker 时把 `queue_db` 传给 launcher 并附加 `--task-db <path>`，修复自定义数据库时 worker 写错库的问题。
2. 请求体上限 1MB，超限返回 413；`Content-Length` 非法返回 400。
3. `/api/tasks` 校验 `scope` 与 `limit`，`scope=mine` 必须带 `user`。
4. 提交前校验流程 JSON 可解析；`steps` 仅接受逗号字符串或字符串/整数数组。
5. 新增 `logs/task_server.log` 服务日志，记录调度异常、worker 启动失败、任务开始/结束，不记录令牌。
6. `server_close` join 调度线程（3 秒超时），`_running` 操作加锁，避免关闭竞态。
7. SQLite 设置 `busy_timeout=15000`；文件库启用 WAL。
8. 任务日志 tail 改为从文件尾部按块倒读，只保留最后 N 行，API 不变。
9. 客户端新增“只看我的任务”复选框与“查看报告”按钮。
10. Launcher 保存任务队列服务 Popen 句柄，重复启动提示；新增“停止任务队列服务”按钮，仅终止本地由 Launcher 启动的进程。
11. Simple 远程模式加固：停止时在后台线程 terminate 远程任务，避免主界面阻塞；轮询停止后不再覆盖“已停止排队”状态；进度百分比兼容浮点；远程运行期间禁止再次提交板块，防止重复任务。
12. HTTP 稳定性修复：401/405/404/任务控制等路径先排空未读请求体再响应，避免 Windows 关闭连接时因残留 body 触发 RST，消除偶发 `ConnectionAbortedError`。

## 11. 已知限制与假设

- 服务为手动启动（客户端按钮或命令行），不自动注册 Windows 服务。
- v1 使用共享令牌 + 用户名，无 HTTPS、无用户权限分级、无令牌轮换；安全性依赖仅提供受限接口 + 令牌。
- 流程来源支持服务器端 `flow_packages/*.json` 与客户端 JSON 上传（`/api/flows/upload`）；同名上传自动生成新版本（`name.vN.json` 归档 + `.flow_versions.json` 台账），规范文件始终指向最新版本。
- Simple 本地排队保留为默认离线兜底；开启“远程模式”后，“运行所选板块”会改为批量提交远程任务并轮询进度，“停止”映射为 terminate。
- 停止服务只作用于本地由 Launcher 启动的进程，HTTP 端无 stop/start/queue 之外的写接口。
- 队列服务与自动化同机部署，SQLite 直接读写，不适合跨机共享。
- 全部使用 Python 标准库，不新增第三方依赖。

## 12. 后续扩展路线

### 12.1 Simple 本地排队迁移到远程队列

已落地（2026-08-11）：

- `WT_Launcher.py` Simple 工具栏新增“远程模式”开关，状态保存到 `launcher_state.json` 的 `simpleModeRemote`，启动时恢复。
- 开启远程模式后，“运行所选板块”改走 `_start_simple_remote`：逐个上传勾选板块的本地 JSON 流程并提交 `/api/tasks/submit`，收集 `taskId` 后按任务轮询进度，映射 `progressPercent/currentStepName` 到卡片状态。
- Simple“停止”在远程模式下映射 `POST /api/tasks/{id}/terminate`，并清理轮询状态。
- 未开启远程模式时保留原有本地顺序执行作为离线兜底；远程提交失败会汇总每个板块的成功/失败原因并提示。
- 用户名/令牌/服务器地址复用 `launcher_state.json` 中任务队列窗口保存的连接参数；未配置时提示先打开任务队列窗口。
- 新增 `submit_simple_sections(sections, completed_callback=None)`、`get_task_detail(task_id)`、`control_task(task_id, action)` 客户端方法，由 `WT_Launcher.py` 调用。
- “提交所选板块到远程队列”新增确认对话框：可调整勾选、附加本地 JSON 链路文件、跳过内容未变化流程的重复上传；任务队列窗口与 Simple 工具栏新增“提交本地 JSON 链路”直达入口。

后续可选增强：

1. 在 Simple 卡片内直接显示每个板块对应任务的实时进度，而非统一轮询列表。
2. 新增“批处理任务”字段，由服务端一次消费多个板块，减少客户端逐板块提交的请求数。
3. 提供 Simple 各板块“上次提交状态”记忆，下次打开自动回显。
4. 远程模式下允许选择提交目标节点或指定执行服务器。

### 12.3 多机任务分配

当前架构为单机：调度器与 worker 同机。多机扩展建议：

方案 A：调度器 + 节点注册

1. 保持 `wt_task_server.py` 作为调度中心（8768）。
2. 新增 worker 节点 agent（如 `wt_worker_agent.py`），启动后向调度中心注册并心跳：节点名、地址、能力、健康状态。
3. 任务表新增 `assigned_node` 字段；调度线程按节点空闲状态分配任务。
4. worker 节点本地执行 `WT_AUT_recorded.py --task-id ... --task-db <节点本地库>`，执行结果与报告回传调度中心。

方案 B：共享存储/消息队列

- SQLite 不适合跨机并发直连，可换 PostgreSQL/Redis 或消息队列存储任务与结果。
- 该方案改动较大，建议作为独立大版本。

建议：保留当前单机路径为默认，多机作为独立扩展；先落地节点注册表、心跳、任务分配与报告回传，再评估是否需要替换存储层。
