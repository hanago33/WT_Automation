模块由三个自包含文件组成，形成「配置/上下文 → 动作元数据 → 编排主类」的单向依赖链：
- `schemas.py`：纯数据层，集中声明 `ACTION_SCHEMAS`、`ACTION_DEFAULT_CONFIGS` 及 `get_action_names/get_action_schema/build_action_default_config` 等访问器，不依赖任何外部项目文件，作为 DSL 契约的唯一真相源。
- `skill_bridge.py`：Skill 加载桥，提供 `discover_skills` / `load_all_skills_text` 从文件系统（.md/.json/.xlsx/.csv/.pdf/.docx）扫描 Qoder Skill 定义，并内置 Windows UI Automation 最佳实践；输出 `SkillInfo.to_context_text()` 供 `DslContext.skill_context_text` 注入 System Prompt。
- `agent.py`：编排层，定义 `DslAgentConfig`（环境变量覆盖）、`DslContext`（控件库/示例/Skill 文本等运行时上下文），并通过 `_build_tools_definition` 把 `ACTION_SCHEMAS` 动态生成 OpenAI Function Calling 工具定义（`add_step`/`add_sequence`/`add_parameter_scan`）。LLM 调用走 `requests.Session` + urllib3 Retry 指数退避，响应经 `_parse_tool_calls` 解析为原始步骤，再由 `_raw_to_full_step` 补全为下游执行引擎所需的 `actionConfig` 结构，最后经 `validate_step` 校验。
依赖方向：`agent.py` → `schemas.py` + `skill_bridge.py`（后者仅被上层组装 `DslContext` 时消费），三者均不反向依赖 WT_Automation 工程。
