1. **18 项规划 + 30 个模式的"WT 现状"断言已全部回代码核实。** 方向全部成立；其中 11 处现状描述需校正（多为"落点另有其处"或"现状比文档描述更好"），见 §3。

## 4. 第一批落地要点（本次建议先实施）

### A.（P0-6'）指令目录生成器 + Agent 侧 schema 同源收敛

**目标**：schema 成为"面板/校验/文档/AI 语料"四合一唯一事实源；消除 Agent 副本漂移。

**核实依据**：`WT_AUTOMATION_Agent/schemas.py:2-4`（"完全自包含"声明）；漂移实证——Agent 版缺
`check_all_toggles`/`select_list_items`，`click_relative_anchor` 描述与默认值落后根版
（Agent 版 `waitAfter 0.12` vs 根版 `anchorAlign=right/waitBefore 0.3/waitAfter 0.8`）；
`skill_bridge.py:366` 调用点均不传 `additional_dirs`；`agent.py:185` 硬编码枚举。

**改动清单**（建议 2 个 commit）：

1. **commit 1：生成器 + 产物 + 一致性测试**
   - 新增 `tools/generate_command_catalog.py`：从 `wt_action_schema.py`（`ACTION_SCHEMAS` 为 **dict**，
     卷四示意代码的 `for s in ACTION_SCHEMAS` 会迭代键名，需修正）与 `wt_action_defaults.ACTION_DEFAULT_CONFIGS`
     生成 `WT_AUTOMATION_Agent/command_catalog.json`；
     枚举常量真实符号名：`ALLOWED_CONTINUE_WHEN_CONDITIONS` / `ALLOWED_ON_ERROR_MODES` /
     `STEP_POLICY_ON_FAIL_MODES`（卷四示意的 `STEP_POLICY`/`CONTINUE_WHEN_KINDS` 不存在）。
   - 新增 `tests/test_command_catalog.py`：① catalog 与 `ACTION_SCHEMAS` 双向一致；
     ② Agent 副本与根 schema 的差异白名单校验（防止再次静默漂移）。
2. **commit 2：Agent 侧消费与收敛**
   - Agent 系统提示消费 catalog（填充 `DslContext.action_schema_text` 空置钩子，`agent.py:129`）；
     收敛 `agent.py:185` 硬编码枚举；
   - 修复 skills 挂载：`skill_bridge.load_all_skills_text()` 增加 skills 目录（或在 `get_builtin_skills()`
     增第 4 个内置常量）；
   - `WT_AUTOMATION_Agent/schemas.py` 定位为"Agent 专属层"：根 schema 子集 + `foreach_param`/`run_flow_package`
     两个 Agent 专属动作 + `AGENT_ONLY_ACTIONS` 过滤逻辑，由一致性测试锁住差异白名单。

**验收**：`pytest tests/ -q` 全绿（含新增用例）；catalog 一键再生成后 git diff 为空；
Agent 生成提示词中可见 catalog 内容（可用现有 `parameter_scan` 相关用例观察 action 名来源）。

**风险**：低。**注意**：`ACTION_SCHEMAS` 有 19 项而 Agent 侧 21 项（含专属 2 项、缺 2 项）——同源方案必须
支持"根 + 覆盖层"，不能简单互相覆盖。

### B.（P0-5'）防休眠 + 卡死登记（含会话状态轻量告警）

**目标**：长跑任务不被系统休眠打断；卡死可归因。

**核实依据**：`SetThreadExecutionState` 0 命中；入口 `run_automation`（`WT_AUT_recorded.py:2585`）；
步骤执行主链 `_execute_step_by_id`（L2801 调用处）；已有探针 `_window_is_responsive`（`wt_flow_locator.py:8420`）；
队列侧已有 `check_desktop_interactive()`（`wt_task_queue.py:269-300`）。

**改动清单**（建议 2 个 commit）：

1. **commit 1：防休眠 + 会话告警**
   - 新增 `wt_run_guards.py`：`PreventSleep` 上下文（`SetThreadExecutionState(ES_CONTINUOUS|ES_SYSTEM_REQUIRED)`，
     退出恢复 `ES_CONTINUOUS`）；
   - `run_automation` 两路入口包裹 PreventSleep；
   - 运行前复用"桌面交互性检测"思路（可提取 `check_desktop_interactive` 的逻辑为公共函数，或调用队列侧函数），
     锁屏/非交互会话时记录 WARN 事件（不阻断）。
2. **commit 2：卡死登记**
   - `StuckRegistry`：步骤开始/结束登记 + 60s 看门狗，超时写 JSONL（复用 `wt_logging.start_jsonl` 设施，
     `wt_logging.py:254/305`），事件 `stuck_suspect` 含步骤 id、已耗时、主线程栈；
   - 登记点：`_execute_step_by_id` 或 executor 步骤包装层（二选一，倾向 executor 层，避免动 `WT_AUT_recorded` 大文件）。

**验收**：电源计划设"10 分钟睡眠"的机器跑 >1 小时任务不休眠；人为构造 >60s 步骤，JSONL 出现
`stuck_suspect` 且带完整栈；现有 1565 用例全绿。

**风险**：极低。

### C.（P1-6）步骤参数快照进运行报告

**目标**：报告可回答"这一步当时传了什么参数"。

**核实依据**：`wt_run_reporting.report_step_result(..., extra=)` 已支持（`wt_run_reporting.py:95-109`）；
调用点 7 处（`wt_flow_executor.py:1894/1898/1910/1931/2145`、`WT_AUT_recorded.py:1595/2779`）。

- 执行器在构造 `step_extra` 时填充 `inputs` 快照：`{name, value, type, isFullValue}`，

**验收**：故意失败一步，`logs/run_reports/*.json` 的该步记录内含 resolved 输入快照；
敏感字段不泄漏；全量测试绿。

**风险**：低（`extra` 为既有字段，纯追加）。
