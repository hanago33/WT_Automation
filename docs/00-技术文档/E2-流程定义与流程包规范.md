## 2. 顶层结构

```jsonc
{
  "version": 1.0,
  "project": "WT_Automation",
  "description": "…",
  "lastUpdated": "2026-07-15T15:23:34",

  "runtimeConfig": {              // 运行参数（${runtime.KEY} 的来源）
    "gmExe": "",
    "sourceFilePath": "",
    "outputDir": "",
    "projectionFilePath": ""
  },

  "flowPackages": [               // 步骤的引用聚合
    { "id": "气象数据录入", "name": "test", "description": "", "stepIds": ["step_1", …] }
  ],

  "steps": [ { /* 见 §3 */ } ]    // 扁平全量步骤
}
```

> 📌 `steps` 是**扁平全量**，`flowPackages[].stepIds` 只是引用。一个 step 可属于多个包、也可在顶层——这正是运行时"防重复执行"闸门存在的原因（A3 §3.1 第 4 道闸门）。

## 3. 步骤（step）

### 3.1 字段表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 步骤唯一 ID（`step_1`）。**重复即校验报错** |
| `name` | str | 步骤名（如 `点击-综合`） |
| `stage` | str | 来源标记：`custom` / `converted`（录制转换产物） |
| `strategy` | str | 策略标签（如 `action`） |
| `actionType` | str | **`script` / `action` / `flow_ref` / `placeholder`** |
| `topLevel` | bool | 是否顶层步骤 |
| `enabled` | bool | 停用则跳过（记 `skipped`） |
| `optional` | bool | `script` 未绑定执行函数时：true → `skipped`，否则 **`failed`** |
| `packageRef` | str | `flow_ref` 时引用流程包 ID |
| `codeSymbol` / `codeReference` | str | `script` 绑定的 Python 函数标识 |
| `description` | str | 说明 |
| `successLog` | str | 成功日志文案 |
| `windowTitle` | str | 目标窗口标题（可多候选） |
| `inspectHints` | dict | Inspect 提示：`controlName` / `className` / `automationId` / `controlType` / `uiPath` / `templateKey` |
| `controls` | list | **步骤级细分控件清单**（§4） |
| `actionConfig` | dict | 动作配置（卷 E1） |

### 3.2 完整示例（真实，节选自 `flow_definition_发送综合计算.json`）

```jsonc
{
  "id": "step_1",
  "name": "点击-综合",
  "stage": "custom",
  "strategy": "action",
  "actionType": "action",
  "topLevel": true,
  "enabled": true,
  "codeSymbol": "",
  "codeReference": "",
  "packageRef": "",
  "description": "通过流程链路匹配点击目标按钮。优先使用 automation_id + Button，名称仅作为补充。",
  "successLog": "",
  "windowTitle": "",
  "inspectHints": {
    "controlName": "综合",
    "className": "Button",
    "automationId": "TabItem_Header_Label",
    "controlType": "Button",
    "uiPath": "Window_Main > ... > 综合",
    "templateKey": ""
  },
  "controls": [ { /* 见 §4 */ } ],
  "actionConfig": {
    "timeoutSeconds": 2.5,
    "waitBefore": 0.0,
    "waitAfter": 0.12,
    "action": "click",
    "controlId": "control_map_439",
    "retryCount": 0,
    "retryInterval": 1.0,
    "onError": "continue"
  }
}
```

### 3.3 `actionType` 分派

| 值 | 运行时行为 |
|---|---|
| `action` | 走受控动作链路（precondition → 重试 → 降级链 → 模板 → AI） |
| `script` | 调用 `execution_plan_map[step_id]["func"](context)` |
| `flow_ref` | `run_flow_ref_step` 递归执行 `packageRef` 指向的包的 `stepIds` |
| `placeholder` | 记 `skipped`（占位未实现） |
| 未知 | 记 `skipped` + 日志"未知 actionType" |

## 4. 控件条目（`controls[]`）

### 4.1 字段表（实测 15 个顶层字段）

| 字段 | 说明 |
|---|---|
| `id` | 控件 ID（如 `control_map_439`）。**`actionConfig.controlId` 与 `continueWhen.controlId` 必须在此列表内** |
| `name` | 控件显示名 |
| `role` | 角色/来源说明（如 `来自控件库扫描：`） |
| `enabled` | 是否启用 |
| `windowTitle` | 目标窗口标题（`*` 表示不约束） |
| `targetMethod` | 定位方法（逗号成对，如 `automation_id,control_type,label_text`） |
| `targetValue` | 定位值（与 method **段数必须一致**） |
| `templateKey` | 模板键（用于自动接线 `fallbackTemplate`） |
| `uiPath` | UI 路径（`Window_Main > A > B > C`） |
| `notes` | 备注（常含"定位评分=100"等采集信息） |
| `labelText` | 标签文本（消歧关键） |
| `relatedLabelName` | 关联标签名 |
| `helpText` / `functionText` | 帮助文本 / 功能语义文本（评分 +12） |
| `rawInspectText` | **原始 Inspect 文本**（完整 UIA 属性快照，排障金矿） |
| `optionValues` | 可选值列表 |
| `auxChecks` | 补充校验（评分每项 +1），如 `["IsEnabled=True", "FrameworkId=WPF", ...]` |
| `inspectData` | 采集到的结构化属性（§4.2） |

### 4.2 `inspectData` 字段（评分的输入）

| 字段 | 说明 |
|---|---|
| `name` / `controlType` / `localizedControlType` / `className` / `frameworkId` | 基础属性 |
| `automationId` | **最可靠的定位属性**（评分 +14） |
| `boundingRectangle` | 矩形（如 `[l=656,t=110,r=875,b=159]`） |
| `isEnabled` / `isOffscreen` / `isKeyboardFocusable` / `hasKeyboardFocus` | 状态属性 |
| `processId` / `runtimeId` / `nativeWindowHandle` | 运行时标识 |
| `providerDescription` | UIA Provider 描述 |
| `legacyName` / `legacyRole` / `legacyState` / `legacy*` | MSAA 遗留字段 |
| `children` | 子结构签名（部分匹配 **+24** / 全不匹配 −18） |
| `ancestors` | 祖先链（部分匹配 **+6**） |
| `availablePatterns` | 可用 Control Pattern |
| `recommendedTargetMethod` / `recommendedTargetValue` | 采集器推荐 |
| `foundIndex` | 父容器内同类同级 **0 基序号**（命中 **+12**） |
| `howFound` / `firstChild` / `lastChild` / `next` / `previous` | 采集辅助 |

> ⚠️ `_clean_control_definition` 会把 `inspectData` 的值统一 `normalize`（int → str），**运行时必须用 `int()` 容错解析**（如 `foundIndex`）。

## 5. 注册表 `flow_package_registry.json`

### 5.1 顶层字段（实测）

```
version / project / description /
sourceDefinitionPath / storageDir / runtimeConfig /
flowPackages[] / steps[] / lastUpdated
```

| 字段 | 说明 |
|---|---|
| `sourceDefinitionPath` | 来源流程定义路径 |
| `storageDir` | 存储目录 |
| `runtimeConfig` | 运行时配置 |
| `flowPackages[]` | `{id, name, description, stepIds[]}` |
| `steps[]` | **全量步骤聚合副本** |

> 📌 注册表自带 `steps[]`，因此它本身就是一份**可直接执行的完整 payload**，不只是索引。

### 5.2 包条目示例

```json
{
  "id": "发送综合计算",
  "name": "发送综合计算",
  "description": "（已剔除 step_1..27 计算步骤，仅保留导出链路）",
  "stepIds": ["step_1", "step_2", …]
}
```

### 5.3 同步方式

| 场景 | 机制 |
|---|---|
| 编辑器保存 | `sync_flow_package_registry(...)` 自动同步（**不要手改**） |
| 总控台读取 | `load_effective_flow_payload()` = 目标流程 ⊕ 注册表（`_merge_target_with_registry`） |

## 6. 校验规则（`wt_flow_validation`）

保存前与加载时执行。完整清单见 B2 §5.1，此处列**最容易踩的**：

| 检查 | 报错要点 |
|---|---|
| `controlId` 不在本步骤 `controls[]` | "不存在于当前步骤细分控件清单中" |
| 占位值未填（`请补充` / `<...>`） | "仍是占位值" |
| `targetMethod` 与 `targetValue` **段数不一致** | "N 个方法，但只有 M 个值" |
| `relativeRegion.x/y` 越界 | 需 0–1 |
| `relativeRegion.width/height` 越界 | 需 >0 且 ≤1 |
| `frameworkId` / `anchor` / `condition` 不在白名单 | "仅支持: …" |
| stepId 重复 / 包 ID 重复 / 包引用不存在的步骤 | 流程级报错 |

**枚举白名单**

```python
ALLOWED_CONTINUE_WHEN_CONDITIONS    = ("exists","present","visible","enabled","gone",
                                       "nonempty","non_empty","value_equals",
                                       "toggle","checked","toggle_state")
ALLOWED_RELATIVE_REGION_ANCHORS     = ("center","left_center","right_center")
ALLOWED_ON_ERROR_MODES              = ("continue","retry","stop","fallback","ask")
ALLOWED_PARENT_WINDOW_FRAMEWORK_IDS = ("WPF","Win32","uia","WinForm")
```

## 7. 字段契约纪律（改结构前必读）

| # | 纪律 |
|---|---|
| 1 | **白名单重建陷阱**：`normalize_step` 用白名单重建步骤，新增字段必须**显式放行**，否则保存即丢失 |
| 2 | **Excel 往返五处同步**：列定义 / 规范化 / 写出 / 读入 / 清理，缺一处往返丢数据（C4 §4.4） |
| 3 | 新增字段后跑一次 `audit_flow_excel_roundtrip` 验证 |
| 4 | 改流程前先 `.bak_<场景>_<日期>` |
| 5 | 保存走编辑器（自动同步注册表），不要手改 `flow_package_registry.json` |
