模块由三个职责清晰的文件组成：
- `wt_flow_executor.py`：流程执行核心。通过全局 `_GET_STEP_DEFINITION` / `_LOG_STEP` / `_CLICK_FLOW_CONTROL` 等可注入钩子（由 `configure_flow_executor(...)` 统一注册）与上层解耦；`execute_step_by_id` 根据 `actionType` 分发到 script/action/flow_ref/placeholder 分支，其中 action 分支再按 `actionConfig.action` 分派 click/type_text/send_keys/drag_and_drop/mouse_wheel/wait_for_control/menu_select/sleep/log 等具体动作，并内置 retry/fallbackTemplate/AI 干预/continueWhen 四段式错误处理链。
- `wt_flow_locator.py`：底层控件定位与交互实现。以 `FLOW_WINDOW_CACHE` / `FLOW_CONTROL_CACHE` / `FLOW_PARENT_CACHE` 三级 TTL 缓存窗口和控件树；提供自愈选择器（`control_maps/self_heal_store.json` 持久化降级定位器）、下拉项运行时候选评分、相对区域/锚点点击、模板兜底定位等；同样通过 `configure_flow_locator` 注入 `_GET_STEP_DEFINITION` / `_LOG_STEP` 钩子，依赖 `pywinauto`（UIA backend）+ `pyautogui` + `pywinauto_recorder.player.send_keys`。
- `wt_flow_validation.py`：纯函数式静态校验器，从 `wt_action_schema` 读取 ACTION_SCHEMAS 与白名单，对 step/controls/windowTitle/targetMethod-targetValue 数量一致性、relativeRegion 坐标范围、flowRef 引用完整性等进行断言，不产生副作用。
依赖方向：executor ↔ locator 通过配置钩子双向耦合（executor 调用 locator 暴露的 click/select/drag/wheel 等函数，locator 反向通过 `_GET_STEP_DEFINITION` 取控件定义），validation 仅依赖 schema 且被 executor 在运行前调用。
