# 发送综合计算 · 四综合参数矩阵（路线B · 非Agent）实现与排障记录

> 日期：2026-08-24
> 范围：`flow_packages/flow_definition_发送综合计算.json` + `WT_AUTOMATION_Agent/parameter_scan.py` + `WT_AUT_recorded.py` + `tests/test_param_matrix.py`
> 目标：把"单综合、单塔、不带绘图、Wohler=1"的线性流程，改造为参数表驱动的"四综合矩阵"自动建立链路。

---

## 一、需求概述

常规计算一般需建立 4 个综合：

| 综合 | 风机配置 | Wohler | 建立方式 |
|---|---|---|---|
| 综合1 | 不带绘图 | 1 | 从头新建 |
| 综合2 | 不带绘图 | 4 | 从综合1复制，仅改 Wohler |
| 综合3 | 不带绘图 | 10 | 从综合1复制，仅改 Wohler |
| 综合4 | **带绘图** | 1 | 从综合1复制，**重新设置一遍**，并新增"绘图上的默认风机类型"环节（设置风机类型但不设 Wohler） |

- 复制交互：**先点击"综合1"列表项，再点击（悬停亦可）行尾图标渲染出"复制"弹窗，点"复制"后自动进入副本**，配置完点 GoBack 返回列表再复制下一个。
- 副本由软件自动排序命名为综合2/3/4，"综合1"名称不变。
- 热稳定度：按已算 CFD 结果整窗全勾选（`step_22a`），流程不区分等级。
- 单塔场景本次实现；**多塔差异组（多塔按钮/参考点/参考气象、IEC改"组合"、极风参考塔）留阶段2**。

## 二、技术方案（路线B · 最小补点）

**核心思路**：脱离 agent，仅靠现有自动化链路执行参数矩阵。

```
flow_definition_发送综合计算.json          参数表 param_table_发送综合计算.xlsx
│ 顶层 paramTable 字段                     │ 4 行：stepMode / synthesisName / wohler / drawTurbineType
│ 41 个模板步骤（带 stepTags + ${stepParams} 占位）
▼
WT_AUT_recorded._apply_param_table_expansion
▼
ParameterScanner.scan 读参数表
  ├─ 每行复制模板步骤，注入 stepParams
  └─ 按行 stepMode 过滤：create 全步 / copy 去 create-only / copyfull 复制+带绘图+绘图组
▼
展开后 90 步（create=31 + copy=10 + copy=10 + copyfull=36 + 3 分隔）
▼
wt_flow_executor 线性执行 → _RESOLVE_DYNAMIC_VALUE 替换 ${stepParams.xxx}
```

**关键前提**（均已代码实查确认）：
- `wt_flow_executor._RESOLVE_DYNAMIC_VALUE` 是预留依赖注入点，`WT_AUT_recorded` 已注入 `_resolve_dynamic_value`（执行 context 的 `step_params` 由展开后每步的 `stepParams` 构建）。
- `type_text` 先 `set_edit_text`（整体替换），失败再 `^a` 全选+键入 → **覆盖旧值**，copy 模式改 Wohler 不会变成"14"。
- 执行内核（控件定位/点击）**零改动**，爆炸半径极小。

## 三、代码改动落点

### 1. `WT_AUTOMATION_Agent/parameter_scan.py`
- `scan` 新增**行级步骤过滤**：参数表含 `stepMode` 列时，按行 `row_mode` 过滤模板步骤；模板步骤通过 `stepTags` 声明所属模式（空=通用，所有行执行）。**无 `stepMode` 列时退化为旧行为**（每行全步）；非法 `stepMode` 值告警并退化为全步。
- 新增 `_normalize_step_tags(tags)`：规整 `stepTags` 为小写模式集合（支持 None/[]/逗号字符串/列表）。

### 2. `WT_AUT_recorded.py`
- `_apply_param_table_expansion`（已有）：读取顶层 `paramTable`（相对流程文件目录解析）→ 调 `scan` 展开覆盖 `steps`；无 paramTable/异常安全降级。本次新增：
  - **包 stepIds 同步映射**：展开后把 `flowPackages` 中包的 `stepIds` 从原始模板 id 映射为展开后 id（否则校验报"引用了不存在的步骤"）。
  - **stepTags 缺失告警**：参数表有 `stepMode` 列但模板缺 `stepTags` 时明确告警（编辑器保存会剥离 `stepTags`，防止静默全跑）。
- `_resolve_steps_to_run`：`--steps`/`--from-step`/`--to-step` 传模板 id 时，按 **base id → 展开 id** 映射，并**保持展开顺序（行线性执行）**——不能按模板 base 分组，否则会把所有行的 step_1 先跑完再跑 step_2，完全乱序。

### 3. `tests/test_param_matrix.py`
新增 6 个用例：三模式行级过滤、无 `stepMode` 列向后兼容、非法模式退化、`_apply_param_table_expansion` 端到端过滤、`_normalize_step_tags`、包 stepIds 映射、`--steps`/from-to 模板 id 映射。

## 四、流程定义文件结构（41 步）

模板步骤按角色打 `stepTags`（模式：`create` / `copy` / `copyfull`，空=通用）：

| 角色 | 步骤 | stepTags |
|---|---|---|
| 通用导航/保存/发送 | step_1, step_27, step_28 | 空（所有行执行） |
| 新建专属 | step_2 创建一个综合、step_3 综合名、step_4 描述、step_5/6 风机配置(不带绘图) | create |
| 复制组 | step_copy_select 选中综合1、step_copy_menu 行尾悬停、step_copy_click 复制、step_copy_goback 返回列表 | copy, copyfull |
| 打开默认风机类型 / wohler / 确认 | step_7, step_11, step_12 | create, copy, copyfull |
| 默认风机类型重设（检索/机型/版本） | step_8, step_9, step_10 | create, copyfull |
| 气象/IEC/稳定度/极风/高级等 | step_13 ~ step_26 | create, copyfull |
| 带绘图配置组 | step_cfg_draw_open/select | copyfull |
| 绘图默认风机类型组 | step_draw_open/search/select/confirm | copyfull |

**copy 行（综合2/3）步序**：`step_1 → 选中综合1 → 行尾悬停 → 复制 → 自动进副本 → 打开默认风机类型 → 改wohler → 确认 → 保存 → 发送 → GoBack`
**copyfull 行（综合4）步序**：在 copy 基础上，插入 `选带绘图 → 默认风机类型全重设(wohler=1) → 绘图默认风机类型(检索/机型/确认)`。

占位符约定：`${stepParams.synthesisName}`（综合名）、`${stepParams.wohler}`（Wohler）、`${stepParams.drawTurbineType}`（绘图风机类型）。

## 六、踩坑与修复记录（重点沉淀）

1. **`stepTags` 错位**：流程文件曾被重新录制，步骤 id 相对假设整体偏移（wohler 实际是 `step_11` 而非 `step_12`），导致标签与占位符写错位 → 审计后按真实结构修正。
2. **无 `stepMode` 列时 `row_mode` 默认为 `""`（非 None）误触发过滤** → 禁用过滤时强制 `None`。
3. **占位符写错键**：executor 读 `action_config.get("text", action_config.get("value"))`，**优先 `text`**；占位符曾写在 `value` 键上被忽略（综合名硬编码 "Test1"）。
4. **wohler 占位符写错步骤**：曾写到 `step_12`（确认按钮）的 `value` 上，而真正的 wohler 输入在 `step_11.text`。
5. **悬停控件 Image [788,177,840,229] 无法直接定位**：无 name/automationId，uiPath 到 `MUPWRAAnalysisResultsView` 不唯一，扫描仅给 `control_type:Image`，`found_index` 未产出 → 用 `click_relative_anchor` 锚定 `WRAResults_Button_Cancel`（稳定 automationId）右缘 + `offsetX=26` 定位到图标中心。
6. **副本自动命名综合2/3/4**：`step_copy_select` 用 `name=综合1, ListItem` 定位，始终命中综合1，不受影响。
7. **展开后 flowPackages 包 stepIds 失效**：包 `发送综合计算` 是"整流程登记包"（stepIds=全部主步骤），展开后主 steps 换成 `_scan` id → 校验报"引用了不存在的步骤" → 展开时把包 stepIds 映射为展开后 id。
8. **`--steps` 传模板 id 找不到**：展开后 id 带 `_scanX_Y` 后缀 → `_resolve_steps_to_run` 按 base id 映射，且**保持展开顺序（行线性）**，不能按 base 分组。
9. **`stepTags` 被编辑器剥离（重要）**：在 Launcher 流程编辑器里保存流程文件会**剥离自定义字段 `stepTags`**，导致 `stepMode` 过滤失效、每行全跑（41×4=167 步）→ 表现为"综合1新建行混入复制步骤"的乱象。已重新注入 `stepTags` 并加**防御告警**。

### 方案：双维行级过滤（stepMode × towerMode）
- `parameter_scan.scan` 过滤升级为 **AND 双维**：参数表新增 `towerMode` 列（`single`/`multi`），步骤新增可选 `towerTags`。
  - 步骤保留条件：`(stepTags 空 OR stepmode ∈ stepTags) AND (towerTags 空 OR towermode ∈ towerTags)`。
  - **无 `towerMode` 列时默认 `tower_mode="single"`**（历史流程均单塔），保证单塔步骤执行、多塔组被排除，向后兼容。
  - 值非法时该维不过滤（与 stepMode 非法退化一致）。
  - 硬失败保护：有 `towerMode` 列且存在非空行，但模板零 `towerTags` → 抛 `StepModeFilterUnavailable`。
- 参数表新增列：`towerMode`（默认 single）、`mettowername`（测风对象/参考塔名，默认 M1，后续多塔改参考塔）、`refMast`（参考点测风塔编号）、`refClimatology`（参考气象名称）。

1. **`stepParams` 合并注入**：`scan` 注入改为 **合并**——`模板步骤自带默认 stepParams` + `参数行值`（行值覆盖同名键）。此前是整体覆盖，参数表缺列会把步骤默认值（`defaultturbine=WT6250D220`、`cpversion=Cp0.429`、`weathername=testMESO`、`mettowername=M1`）冲掉，导致 `${stepParams.xxx}` 占位符失效、输入字面量。
