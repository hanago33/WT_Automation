## 1. 发布三件套

| 脚本 | 行数 | 职责 |
|---|---:|---|
| `make_release.py` | 154 | **生成发布包**（全量包 / 增量包） |
| `deploy_release.py` | 427 | **内网机一键部署**（解压 + 应用）增强版；融合原 `deploy_release` 与发布包批量更新能力 |
| `apply_release.py` | 47 | **应用发布包**：把 zip 解压后的文件按相对路径覆盖到目标仓库，**并处理删除** |

### 1.1 `make_release.py`

| 函数 | 行号 | 作用 |
|---|---|---|
| `git(*args)` | L33 | 调 git（用 git 差异决定增量包内容） |
| `top_dir(path)` | L39 | 仓库根定位 |
| `filter_paths(paths)` | L43 | 路径过滤（排除不应发布的项） |

### 1.2 `deploy_release.py`

| 函数 | 行号 | 作用 |
|---|---|---|
| `load_config()` / `save_config(cfg)` | L45 / L53 | 部署配置（记住目标目录等） |
| `list_release_zips(release_dir)` | L61 | 列出发布包 |
| `find_zip(hint=None, release_dir=None)` | L78 | 按提示找包 |
| `_zip_file_list(zip_path)` | L100 | 列出包内文件 |
| `apply_zip(zip_path, target, backup_dir=None, log=print)` | L105 | 应用单个包（带备份） |
| `_apply_deleted_list(zip_path, target)` | L139 | **处理删除清单**（增量包可能要删文件） |
| `plan_apply(zips, target, mode="all", dry_run=False, backup=True, log=print)` | L161 | 生成应用计划，支持 **dry-run** 预演 |
| `DeployApp` | L195 | GUI 部署程序 |
| `main_cli(argv)` / `main()` | L365 / L412 | CLI / 入口 |
| `_safe_join(root, rel)` | L92 | 防路径穿越 |

> 💡 **`plan_apply` 支持 `dry_run`**——内网部署前务必先预演一次，看会覆盖/删除哪些文件。

### 1.3 产物与版本控制

| 项 | 说明 |
|---|---|
| 打包输出 | `dist/`、`release_out/`（均 `.gitignore` 忽略） |
| 保留策略 | `release_out` 习惯上**保留最近 14 个发布点**，旧包按需清理 |
| `.exe` 产物 | 三件套各自的 PyInstaller 产物 `apply_release.exe` / `deploy_release.exe` / `make_release.exe` 已于 **2026-09-09 移出版本控制**（`git rm --cached` + `.gitignore`）。需要时用源码或从 Release 获取 |
| Release Notes | `RELEASE_NOTES_v4.0.0.md`、`RELEASE_NOTES_v5.0.0.md` |

## 2. 诊断工具族

| 脚本 | 行数 | 症状 → 用途 |
|---|---:|---|
| `diagnose_mup_windows.py` | 77 | 枚举本机可见的 MUP 相关窗口（标题 / 类名 / 尺寸）+ 相关路径与会话信息。用于定位"健康检查只找到 160×28 小窗口" |

| `wt_queue_selfcheck.py` | 251 | 队列服务一键自检（详见 C5 §5） |
| `control_locator_probe.py` | 244 | **隔离进程**定位探针（避免 UIA 堆损坏拖垮主进程，见 B1 §8） |
| `control_live_detector.py` | 2 092 | 开发期实时控件检测器（悬停即匹配，见 C3 §8） |
| `wait_global_mapper_ready.py` | 179 | 等待 Global Mapper 就绪（地形预处理前置） |
| `fix_server_gm_exe.py` | 53 | 服务器端把 `${GM_EXE}` 从 `.lnk` 改为直接可执行 `.exe` |
| `test_detector.py` | 247 | TextBlock 控件定位可用性验证测试 |

> 📌 诊断族**未被 `.bat` 引用**，均为可独立运行的命令行工具。

### 5.3 ⚠️ 跑全套测试的前置条件

`tests/test_control_live_detector.py` 依赖根目录的 **`control_live_detector.py`**，而后者**被 `.gitignore` 忽略**。

因此新建 worktree 时必须从主目录拷贝（见 `AGENTS.md` 初始化检查单）：

| 文件 | 用途 |
|---|---|
| `control_live_detector.py` | `tests/test_control_live_detector.py` 依赖，**跑全套测试必需** |
| `WT_AUTOMATION_Agent/_gui_config.json` | Agent 运行配置（用 Agent 功能时必需） |
| `WT_AUTOMATION_Agent/model_profiles.json` | LLM 模型档案（用 Agent 功能时必需） |

> ⚠️ 因环境缺失导致的**收集错误不算"全绿"**。

### 5.4 CI/CD 现状

| 项 | 现状 |
|---|---|
| GitHub Actions | **仅一条**：`.github/workflows/deploy-website.yml`（站点发布） |
| 测试自动化 | **无 CI 测试流水线**，靠人工执行 `python -m pytest tests/ -q` |
| 贡献流程 | worktree 隔离（见 `AGENTS.md`）：AI 在 `ai/session-N` 分支改 → 测试 → commit → 人工审查合并 |

> 💡 **可改进项**：把 `pytest` 接进 GitHub Actions 是低成本高收益的改进（当前合并门槛完全依赖人工自律）。

## 7. 发布与运维检查清单

| # | 检查项 |
|---|---|
| 1 | 发布前：确认 `git status` 干净、测试全绿 |
| 2 | `make_release.py` 打全量包还是增量包？（增量包要确认删除清单 `_apply_deleted_list`） |
| 3 | 部署前：`plan_apply(..., dry_run=True)` 预演 |
| 4 | 部署时：确认 `backup=True`（可在出错时回滚） |
| 5 | 部署后：`验证环境_内网.bat` + `wt_queue_selfcheck.py --check <IP>` |
| 6 | 若队列任务不动：`diagnose_session.py` 查会话、`check_queue_link.bat` 查连通、`服务器一键会话修复.bat` 修复 |
| 7 | 保留策略：`release_out` 保留最近 14 个发布点 |
