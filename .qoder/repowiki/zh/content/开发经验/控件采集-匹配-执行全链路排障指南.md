> 适用场景：控件库维护界面编辑/校验错位、实时控件监测器匹配失效、采集能力对齐、标签→输入框执行兜底。

## 1. 实时监测器匹配失效（ancestors 格式不兼容）

### 1.1 根因

增强采集后，`inspectData.ancestors` 从**字典列表**变为**字符串列表**（uiPath 段）：

```python
# 旧格式（字典）
[{"name": "xxx", "className": "Window", "controlType": "Window"}, ...]

# 新格式（字符串，全库 982 个控件均为此格式）
["Window", "MUPGeographicalDataMainView", "GeoDataMainView_TabControl_Tabs", ...]
```

匹配代码 `_score_single_control` 对字符串调 `.get("controlType")` → 抛 `AttributeError: 'str' object has no attribute 'get'`。

### 1.2 静默吞异常

`_monitor_loop` 的 `except Exception: time.sleep(0.2)` 把整个匹配异常吞掉，界面无任何报错，表现为"所有控件都匹配不上"。

### 1.3 修复方案

新增 `_normalize_ancestor_tokens(ancestors)` 统一规整为小写 token 集合，兼容字符串/字典两种格式。匹配改为**顺序无关的 token 交集**打分（原逻辑还有方向 bug：库祖先自顶向下，实时捕获自底向上，顺序相反）。

```python
def _normalize_ancestor_tokens(ancestors):
    tokens = set()
    for anc in ancestors:
        if isinstance(anc, str):
            tokens.add(anc.strip().lower())
        elif isinstance(anc, dict):
            for field in ("name", "className", "controlType"):
                t = str(anc.get(field, "") or "").strip().lower()
                if t: tokens.add(t)
    return tokens
```

### 1.4 教训

- **后台线程的 `except Exception` 是静默杀手**：任何数据格式变更都可能导致全功能失效且无提示。
- 修改采集输出格式时，**必须检查所有下游消费者**（匹配、显示、导出）。

## 2. 实时监测器与库采集器能力对齐

### 2.1 问题本质

| 维度 | 库采集器 `_extract_wrapper_info` | 实时监测器（改前） |
|------|---|---|
| controlType | 归一化（处理 `UIA_...ControlTypeId`） | 原始未归一化 |
| recommendedTargetMethod/Value | ✅ 有 | ❌ 无 |
| ValuePattern value | ✅ 有 | ❌ 无 |
| frameworkId / helpText / toggleState | ✅ 有 | ❌ 无 |
| ancestors 格式 | 字符串列表 | 字典列表 |
| 字段总数 | ~35 | ~13 |

### 2.2 修复方案

`_get_control_single` 重构为：

```
① 递归下钻 → ② 标签兄弟回退 → ③ 复用库采集器富字段管线
```

- 新增 `_extract_control_info_rich`：调用 `build_control_map_library._extract_wrapper_info`，产出与控件库**完全同构**的记录。
- 保留 `_extract_control_info_thin`（原轻量逻辑）作为回退，导入失败或异常时兜底。
- `_update_display` 兼容字符串/字典两种 ancestors 渲染。

### 2.3 注意事项

- `build_control_map_library.py` 导入时设置 `sys.coinit_flags = 0`（MTA），对 UIA 后端无害。
- `main()` 有 `__main__` 保护，导入不启动 GUI。
- 实时监测器已有自己的 `_build_path_segments_from_wrapper`（复制版），富抽取改用库采集器版本以保持同源。

## 3. 控件库维护界面编辑/校验错位（排序索引 bug）

### 3.1 根因

`WT_Flow_Editor.py` 列表视图的 Treeview iid = **排序后列表中的位置**（`str(index-1)`），但编辑/校验直接用这个数字去**原始未排序** `flatControls[idx]` 取控件。排序打乱后错位。

### 3.2 修复（4处改动）

1. `_build_controls_from_payload`：给每个显示控件打 `_sourceIndex`（原始数组下标）。
2. `_get_control_for_locator_test`：列表视图改用 `_get_filtered_controls()[idx]`（同一份排序列表）。
3. `edit_selected_control`：回写用 `_sourceIndex`（树视图用 `_tree_node_index`）定位真实数组下标。
4. `ControlEditDialog.on_save`：剥离 `_` 前缀内部字段，防止写入 JSON。

### 3.3 教训

- **显示顺序 ≠ 数据顺序**：任何"列表展示 + 按索引操作原始数据"的模式都必须维护映射关系。
- 内部辅助字段用 `_` 前缀标记，序列化时统一剥离。

## 4. 执行侧标签→输入框兜底（③）

### 4.1 场景

采集侧 ①+② 已能把"采到标签"变成"采到框"，但**存量旧数据**或**WPF 自绘控件**（不暴露 Edit 节点）仍可能命中非输入控件。执行侧需要兜底。

### 4.2 实现（wt_flow_locator.py）

在 `type_text_into_wrapper` 开头：

```python
if not _is_editable_control_type(get_wrapper_control_type(control)):
    editable = _resolve_editable_target(control)
    if editable is not None:
        control = editable
```

- `_find_editable_descendant`：后代 BFS 找 Edit/ComboBox/Spinner/Document。
- `_find_editable_sibling`：父容器兄弟中找同行、右侧、最近的可输入控件。
- 已是可输入类型 → 零额外开销，行为不变。

### 4.3 局限

对 WPF 自绘控件（如"导入地形图"窗口），UIA 树里根本没有 Edit 节点，③ 无法生效。此类窗口只能走：
- 点带 automation_id 的 Text 后直接 `type_keys`
- 坐标/相对区域（`type_text_relative`）输入

## 5. 标签→实际控件关联逻辑（待增强）

### 5.1 当前能力

采集器区域关联策略：`标签 → 祖级容器 → 同行右侧控件`。

### 5.2 实际场景的不足

以"导入地形图6"为例：
- 标签"背景"矩形 `x=2020~2471` 几乎覆盖 ComboBox 矩形 `x=2012~2479`
- 二者是 ScrollViewer 下的**平级兄弟**，不是标签在左、控件在右
- 画框区域 `x=0~1191` 未覆盖 ComboBox（`x=2012~2479`），区域筛选正确丢弃

### 5.3 需要扩展的关联维度

```
标签
  ├─ 同层兄弟控件
  ├─ 祖级容器下的兄弟控件
  ├─ 同行控件（垂直中心线重叠）
  ├─ 相邻列控件
  ├─ 矩形大面积重叠控件（标签覆盖控件时优先保留控件）
  └─ 控件组/ScrollViewer 内的相邻列匹配
```

### 5.4 关键约束

- 画框命中一个标签时，应自动读取其祖级容器的兄弟控件
- 即使目标控件部分/全部位于画框外，也可作为 `regionRelated` 关联控件保留
- "组"控件（被打"建议忽略"标签）属于"访问级别"下拉框内的可选内容（WPF 虚拟化，未展开时不渲染全部选项）

## 6. 常见错误速查

| 错误/现象 | 原因 | 修复 |
|------|------|------|
| 实时监测器所有控件匹配不上 | ancestors 字符串格式 + `.get()` 崩溃 + 静默吞异常 | `_normalize_ancestor_tokens` 兼容两种格式 |
| 编辑控件显示的是另一个控件 | 排序后 iid ≠ 原始数组下标 | `_sourceIndex` 映射 |
| 编辑后 JSON 多了 `_sourceIndex` 字段 | `on_save` 整体拷贝含内部字段 | 剥离 `_` 前缀字段 |
| 树视图编辑存不进去 | `int(uiPath)` 抛异常被吞 | 用 `_tree_node_index` 回写 |
| type_text 打到标签上不生效 | 执行侧无标签→输入框兜底 | `_resolve_editable_target` |
| 新采集文件 ComboBox=0 | WPF 自绘不暴露 Edit 节点 / 画框未覆盖 | 非代码问题，需扩大画框或走坐标输入 |
| 匹配分数偏低 | 实时捕获 controlType 未归一化 | 复用库采集器 `_extract_wrapper_info` |
