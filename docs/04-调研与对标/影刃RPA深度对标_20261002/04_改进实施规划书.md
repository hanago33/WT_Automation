## P0 批次（6 项）

### P0-1 输入通道参数化（inputChannel）

- **目标**：每条输入/点击类步骤可配置注入方式，而不是由代码路径决定。
- **影刃参照**：`win32.element.input` 的 `input_type: simulate|clipboard|automatic` 三选一（卷二 §3.3）。
- **WT 现状**：`wt_flow_executor.run_action_step` 内 type_text/click 等动作的注入方式写死（pyautogui 或 pywinauto，共 40+ 调用点）；`wt_action_schema.ACTION_SCHEMAS` 无通道字段。
- **改动点**：`wt_action_schema.py`（schema 加字段+默认值+枚举）→ `wt_flow_executor.py`（dispatch 前按通道归一）→ `WT_Flow_Editor.py`（表单自动跟随 schema，预计无需大改）。

### P0-2 剪贴板输入通道 + IME 防线

- **目标**：中文输入法不再吃键；密码框/长文本输入有可靠通道。
- **影刃参照**：`save_to_clipboard`（注释原文"avoid input method problems"）、`clipboard_input()`、`force_ime_ENG`、`click_before_input`、`focus_timeout=1000`、`send_key_delay=50(min 5)`、`contains_hotkey` 转义规则。
- **WT 现状**：`wt_flow_executor` type_text 直敲；无剪贴板法；无 IME 处理；`win32_input_hook.py` 只做监听。
- **改动点**：`wt_flow_executor.py`（新增 `_type_via_clipboard`、`_force_ime_eng` 辅助）或独立 `wt_input_channels.py`（避免继续加重大文件）；schema 加 `focusTimeoutMs`/`clickBeforeInput`(默认 true)。
- **参考代码**（示意，纯 ctypes 无新依赖）：

```python
import ctypes
import time

def _type_via_clipboard(hwnd_edit, text: str, focus_timeout_ms: int = 1000) -> None:
    """影刃 clipboard_input 对标：聚焦 → 备份剪贴板 → 粘贴 → 恢复。"""
    import win32clipboard
    prev = None
    try:                                   # 备份原剪贴板文本，粘贴后恢复
        win32clipboard.OpenClipboard()
        if win32clipboard.IsClipboardFormatAvailable(win32clipboard.CF_UNICODETEXT):
            prev = win32clipboard.GetClipboardData(win32clipboard.CF_UNICODETEXT)
    finally:
        win32clipboard.CloseClipboard()

    _focus_and_wait(hwnd_edit, timeout_ms=focus_timeout_ms)   # click_before_input + focus_timeout
    win32clipboard.OpenClipboard(); win32clipboard.EmptyClipboard()
    win32clipboard.SetClipboardData(win32clipboard.CF_UNICODETEXT, text)
    win32clipboard.CloseClipboard()
    try:
        _post_hotkey(ctrl=True, vk='V')    # keybd_event: Ctrl down → V → Ctrl up
        time.sleep(0.05)
    finally:
        if prev is not None:               # 恢复用户剪贴板
            win32clipboard.OpenClipboard(); win32clipboard.EmptyClipboard()
            win32clipboard.SetClipboardData(win32clipboard.CF_UNICODETEXT, prev)
            win32clipboard.CloseClipboard()

def _force_ime_eng(hwnd_edit) -> bool:
    """影刃 force_ime_ENG 对标：将目标焦点窗口输入法切英文态（不强制加载美式键盘的轻量版）。
    返回 False 时调用方可选择降级到 clipboard 通道。"""
    imm32 = ctypes.windll.imm32
    himc = imm32.ImmGetContext(hwnd_edit)
    if not himc:
        return True                        # 无 IMC 视作纯英文环境
    try:
        # 0100 = IME_CMODE_NATIVE 关掉（_NATIVE 关=字母态）；先置 ConversionMode
        return bool(imm32.ImmSetConversionStatus(himc, 0x0000, 0x0000))  # 简化示意
    finally:
        imm32.ImmReleaseContext(hwnd_edit, himc)
```

- **验收标准**：中文输入法（搜狗/微软拼音）挂起时，clipboard 通道向 MUP 任意文本框输入含中英混排字符串逐字正确；`focusTimeoutMs` 生效（故意调大可观察到聚焦后停顿）；剪贴板原内容输入后恢复；单测 mock 剪贴板验证备份/恢复路径。
- **工作量**：2~3 天。**风险**：剪贴板恢复在目标程序异步占用剪贴板时可能失败——失败时记日志不抛错（影刃同策略）。

### P0-3 重试策略升级 + 超时三态语义

- **目标**：重试可退避、超时语义全库统一。
- **影刃参照**：`Retry(timeout=-1, times=-1, interval=0.2, error_message, ignore_exception)` 迭代器；timeout 三态 0/-1/N（卷二 §2）。
- **WT 现状**：`_resolve_retry_policy`（retryCount<=0 强制 1 次、retryInterval 固定 1.0s）；timeoutSeconds 默认 3s 散落数十处；无无限等表达。
- **改动点**：`wt_flow_executor.py` 的 `_resolve_retry_policy` / `_run_action_step_with_retry`；`wt_action_defaults.py`（三态常量定义）；文档同步。
- **参考代码**（示意）：

```python
# wt_action_defaults.py
TIMEOUT_INHERIT = "inherit"     # 取该动作类别的类默认（维持现状）
TIMEOUT_NEVER   = -1            # 影刃语义：无限等待
TIMEOUT_NONE    = 0             # 不等待

def normalize_timeout(value, default: float) -> float:
    """三态归一：0=不等待；-1=无限；None/缺省/inherit=类默认。"""
    if value is None or value == "inherit":
        return default
    v = float(value)
    return max(v, 0.0) if v >= 0 else TIMEOUT_NEVER

def wait_deadline(timeout: float, started: float) -> float | None:
    """把三态换算成轮询 deadline；None 表示无限。"""
    if timeout == TIMEOUT_NEVER:
        return None
    return started + timeout

# wt_flow_executor.py —— 重试
def _iter_retry(policy, *, jitter=0.3):
    """固定间隔 + 可选指数退避+抖动（影刃 Retry 迭代器语义的 WT 化）。"""
    attempt, delay = 0, policy.retry_interval
    while True:
        attempt += 1
        yield attempt
        if attempt >= policy.retry_count:
            return
        backoff = (policy.retry_interval * (2 ** (attempt - 1))
                   if policy.backoff else policy.retry_interval)
        delay = min(backoff, policy.retry_max_interval or 60.0)
        time.sleep(delay * (1 + random.random() * jitter))   # 抖动防同步重试风暴
```

- **验收标准**：存量步骤默认行为不变（backoff 默认关）；新增 `retryBackoff: true` 的步骤实测间隔按 1s/2s/4s 退避±抖动；timeout=-1 的 wait_for_control 在目标永不出现时可被任务队列 terminated 状态打断（防止永久僵尸任务——必须与队列取消联动）。
- **工作量**：2 天。**风险**：timeout=-1 与无人值守队列叠加可能造成僵死任务——实施时必须同时提供队列侧的最大运行时长上限。

### P0-5 防休眠 + 指令级卡死登记

- **目标**：长跑任务不被系统休眠打断；卡死可归因。
- **影刃参照**：`os_sleep.start_prevent_os_sleep()`（SetThreadExecutionState 常量硬编码 0x80000000|0x1）、`StuckChecker`（60s 看门狗+主线程栈转储，卷一 §5）。
- **WT 现状**：无防休眠；卡死只有窗口级探针（`_window_is_responsive`）。
- **改动点**：`WT_AUT_recorded.py`（运行入口包防休眠上下文）；`wt_flow_executor.py`（步骤开始/结束登记）；`wt_logging.py`（栈转储落 JSONL）。
- **参考代码**（示意）：

```python
# wt_run_guards.py（新文件，避免碰大文件）
import ctypes, threading, time, json, traceback

ES_CONTINUOUS = 0x80000000
ES_SYSTEM_REQUIRED = 0x00000001

class PreventSleep:
    """影刃 os_sleep 对标：运行期间阻止系统休眠（不阻止熄屏）。"""
    def __enter__(self):
        ctypes.windll.kernel32.SetThreadExecutionState(
            ES_CONTINUOUS | ES_SYSTEM_REQUIRED)
        return self
    def __exit__(self, *exc):
        ctypes.windll.kernel32.SetThreadExecutionState(ES_CONTINUOUS)
        return False

class StuckRegistry:
    """影刃 StuckChecker 简化对标：登记当前步骤 + 60s 看门狗写栈转储。"""
    def __init__(self, sink, interval=60.0):
        self._cur, self._t0, self._sink = None, 0.0, sink
        self._lock = threading.Lock()
        self._stop = threading.Event()
        self._thread = threading.Thread(target=self._routine, daemon=True)
        self._thread.start()
    def step_start(self, step_id, timeout):
        with self._lock:
            self._cur, self._t0 = step_id, time.monotonic()
    def step_done(self, step_id):
        with self._lock:
            if self._cur == step_id:
                self._cur = None
    def _routine(self):
        while not self._stop.wait(self.interval):
            with self._lock:
                if not self._cur:
                    continue
                stuck_id, elapsed = self._cur, time.monotonic() - self._t0
            # 不杀进程（单进程架构），只留证据：
            self._sink(json.dumps({
                "event": "stuck_suspect", "step": stuck_id,
                "elapsed_s": round(elapsed, 1),
                "main_stack": traceback.format_stack(limit=40),
            }, ensure_ascii=False))
```

- **验收标准**：电源计划为"10 分钟睡眠"的机器上运行 1 小时任务不休眠（事件查看器无 Kernel-Power 56）；人为让一步 sleep 超过 60s，JSONL 出现 `stuck_suspect` 且带完整主线程栈。
- **工作量**：1~2 天。**风险**：极低。

def _snapshot_step_inputs(step_def, resolved) -> dict:
    """影刃 inputs[{name,value,type,isFullValue}] 对标；敏感键掩码。"""

## P2 批次（4 项）

### P2-1 定位器子进程隔离（Provider 模式）

- **影刃参照**：UIAutomation.Provider.exe 独立进程 + 命名管道（卷一 §2.1）。
- **设计**：`wt_locator_service.py` 子进程持有全部 UIA 查询；主进程经 `multiprocessing.Pipe` 发查询请求，**请求级超时**（如 8s）未回 → 杀子进程重启并降级到现有探针路径。这是对 742 秒挂起的根治。
- **参考代码**（示意骨架）：

```python
# 主进程
class LocatorClient:
    def query(self, spec, timeout=8.0):
        self._pipe.send(spec)
        if not self._conn_poll(timeout):
            self._kill_and_restart()            # 硬杀 Provider 子进程
            raise LocatorTimeout(spec)
        return self._pipe.recv()
# 子进程：recv → 执行 _find_flow_control_impl 核心循环 → send 结果
# 迁移期开关：locatorService=off(默认,现状) | on
```

- **风险**：高——UIA 对象（wrapper）无法跨进程，需要把"返回元素"改为"返回坐标/句柄快照"；因此放在 P2，待 P1-2 Target 抽象稳定后再做（Target 恰好是隔离的前提）。**工作量**：2~3 周。
