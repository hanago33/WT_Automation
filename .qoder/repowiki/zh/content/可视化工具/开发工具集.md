## 项目结构
WT自动化框架将开发工具集中在 tools 目录下，并提供若干构建与启动脚本，便于快速搭建环境与运行任务。关键目录与文件包括：

- flow_packages：流程包定义与注册表
- control_maps：控件映射与标准控件目录

## 核心组件
本节概述各工具的职责与典型用法，帮助快速上手。

- API测试工具（tools/dev_utils/test_api.py）
  - 用途：验证后端接口连通性、鉴权、请求构造与响应解析
  - 典型用法：通过命令行参数指定目标URL、HTTP方法、请求头与负载；支持输出结构化结果与错误码
  - 建议：结合环境变量注入敏感信息（如Token），避免硬编码

- 模型列表查看器（tools/dev_utils/list_models.py）
  - 用途：列出可用模型或元数据，便于确认版本、路径与可用性
  - 典型用法：按分类过滤、导出清单、校验模型完整性
  - 建议：在CI中定期巡检模型清单一致性

- 鼠标位置获取工具（tools/dev_utils/get_mouse_position.py）
  - 用途：捕获当前鼠标坐标与窗口句柄，辅助UI定位与相对区域计算
  - 典型用法：在GUI界面中点击目标控件后输出坐标，用于录制或定位策略
  - 建议：配合多显示器与DPI缩放场景进行校准

- **DPI感知模块（wt_dpi.py）**
  - 用途：处理Windows DPI缩放感知，确保UI自动化在不同分辨率下正常工作
  - 典型用法：自动检测系统DPI设置，提供坐标转换和尺寸适配功能
  - 建议：在多显示器环境中启用DPI感知，确保跨屏幕操作准确性

- **Windows输入钩子系统（win32_input_hook.py）**
  - 用途：拦截和处理Windows系统输入事件，支持键盘和鼠标事件监听
  - 典型用法：全局输入监控、按键组合识别、输入行为记录
  - 建议：谨慎使用全局钩子，注意性能影响和权限要求

- **C# UIA树转储工具（uia_tree_dumper）**
  - 用途：导出UI Automation树结构，辅助UI元素分析和调试
  - 典型用法：生成UI元素层次结构报告，支持XML格式输出
  - 建议：结合Inspect工具使用，深入分析复杂UI控件结构

- **日志分析工具（tools/analyze_run_logs.py）**
  - 用途：分析自动化执行日志，提取关键信息和错误模式
  - 典型用法：统计执行成功率、识别常见错误、生成性能报告
  - 建议：集成到CI流水线，自动监控执行质量

- 流程包生成器（tools/generate_flow_package.py）
  - 用途：基于模板与配置生成流程包定义，统一结构与字段校验
  - 典型用法：选择模板、填充变量、输出到flow_packages目录并更新注册表
  - 建议：为不同业务域维护独立模板，保持命名规范

- 控件库合并工具（tools/merge_standard_control_library.py）
  - 用途：合并多个控件映射至标准目录，去重、冲突检测与报告生成
  - 典型用法：输入多个library_*.json，输出标准目录与差异报告
  - 建议：在合并前备份原始库，保留变更记录

## 详细组件分析

### API测试工具（tools/dev_utils/test_api.py）
- 职责
  - 发送HTTP请求并解析响应
  - 支持常见认证方式与重试逻辑
  - 输出结构化日志与失败原因
- 关键流程
  - 参数解析 → 构建请求 → 发送请求 → 解析响应 → 记录结果
- 使用建议
  - 将敏感信息放入环境变量
  - 在CI流水线中作为冒烟测试步骤
  - 对超时与网络异常做幂等重试

```mermaid
flowchart TD
Start(["开始"]) --> ParseArgs["解析命令行参数"]
ParseArgs --> BuildReq["构建HTTP请求"]
BuildReq --> SendReq["发送请求"]
SendReq --> RespOK{"响应成功?"}
RespOK --> |是| ParseResp["解析响应体"]
RespOK --> |否| HandleErr["处理错误与重试"]
ParseResp --> LogResult["记录结果"]
HandleErr --> RetryCheck{"达到重试上限?"}
RetryCheck --> |否| SendReq
RetryCheck --> |是| FailOut["输出失败报告"]
LogResult --> End(["结束"])
FailOut --> End
```

## 性能考虑
- 批量操作优化
  - 合并与生成流程时采用流式读写，减少内存峰值
  - 对大文件进行分块处理与并行校验
- 缓存策略
  - 对频繁读取的配置与目录索引建立内存缓存
  - 合理设置缓存失效策略，避免脏读
- 并发控制
  - 限制并发度以避免资源争用
  - 对I/O密集型任务使用异步或线程池
- **DPI性能优化**
  - 缓存DPI检测结果，避免重复查询
  - 批量处理坐标转换操作
- **输入钩子性能**
  - 使用事件过滤减少不必要的回调
  - 避免在钩子回调中执行阻塞操作
- **UIA遍历优化**
  - 限制树遍历深度和范围
  - 使用缓存避免重复查询相同元素

## 故障排查指南
- 常见问题
  - 配置文件缺失或路径错误：检查资源文件是否存在且可读
  - 模板渲染失败：核对模板语法与变量名
  - 控件映射冲突：查看差异报告，手动解决键值冲突
  - DPI缩放异常：检查系统DPI设置和应用兼容性
  - 输入钩子权限不足：以管理员权限运行或调整安全策略
  - UIA连接失败：确认目标应用支持UI Automation
  - 日志分析失败：检查日志格式和编码设置
- 日志与诊断
  - 开启详细日志，记录关键步骤与异常堆栈
  - 使用工具输出的报告进行问题定位
- 回滚与恢复
  - 在合并与生成前备份原始数据
  - 提供一键回滚脚本，快速恢复到稳定版本
