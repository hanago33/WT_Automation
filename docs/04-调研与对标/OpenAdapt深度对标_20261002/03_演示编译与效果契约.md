# 卷三 · 演示编译与效果契约（openadapt-flow 精读）

> 依据：`openadapt_flow/ir.py`（180KB，57 类）、`compiler/compile.py`（123KB）、`compiler/effect_mining.py`（29KB）、`runtime/effects/effect.py`、`verification.py`、`docs/design/PROCESS_CONTRACT_V1.md`。

## 1. 编译产物：IR 类型词汇表（ir.py，57 类）

`ir.py` 的 class 清单本身就是一份"确定性桌面自动化程序"的完备需求单：

| 域 | 类型 | 说明 |
|---|---|---|
| 动作 | `ActionKind` | 动作种类枚举 |
| 定位证据 | `Landmark`（OCR 文本地标）、`StructuralLocator`（DOM/UIA 结构定位）、`TokenTemplate/ConcatTemplate/IdentityTemplate`、`Anchor`（模板裁剪+区域+点击点+OCR 文本+上下文带的复合锚点） | **一步多证据**：每个编译步同时携带模板裁剪、OCR 标签、几何地标、结构定位器（RESOLUTION_LADDER.md §1） |
| 程序结构 | `Step / State / Transition / ProgramGraph / LoopSpec / Relation / Guard / Predicate / Interstitial` | 工作流编译成**状态机图**而非线性脚本——条件跳转、循环、护栏是一等公民 |
| 参数 | `ParamKind / ParamSpec`、`ValueExpr` | 演示值 → 参数占位（对应 WT 的运行参数体系） |
| 风险 | `Postcondition/PostconditionKind`、`Effect`（卷三 §3）、风险分级（irreversible/consequential 贯穿） | 每步可声明后果等级；**不可逆步骤不允许低置信匹配下执行** |
| 身份 | `IdentityCheck / IdentitySignalEvidence / PixelIdentityEvidence / ApiIdentityBinding / ApiBinding` | "点对了东西"的证据体系：像素身份带 / API 绑定双轨 |
| 交付 | `ActionDeliveryReceipt / ActionDeliveryUncertainty` | 动作是否真的送达（键盘焦点被偷→uncertainty） |
| 运行证据 | `Resolution / HealEvent / StepResult / HaltObservation / UnarmedStep / EffectVerificationEvidence / SafetyRefusalEvidence / EffectJournalEntry / ExecutionOutcomeEnvelope / RunReport` | 每步与整跑的证据类型化——**证据不是日志文本，是带类型的对象** |
| 打包 | `BundleManifest / BundleProvenance / BackendHints` | bundle 内容摘要密封、来源溯源、后端提示 |

【WT 启示】WT 的 `wt_flow_graph` 已有图结构；差距在**证据类型化**（StepResult/IdentityCheck/Resolution 这一层）与"每步多证据锚点"（模板+OCR+地标+结构四合一）。卷五规划将二者列为 P1 统一目标抽象的字段蓝本。

## 2. 编译管线：演示 → bundle

`compiler/compile.py`（123KB）主流程（结合 RESOLUTION_LADDER.md 与 effect_mining.py 交叉确认）：

1. 读录制事件流 → 事件聚合（legacy 管线的现代版）；
2. 为每步派生**视觉后置条件**（`compile._postconditions`：步骤前后帧差）与**结构后置条件**（URL/标题/新标签页）；
3. 派生锚点四件套（模板裁剪、OCR 文本、几何地标、结构定位器）；
4. **效果挖掘**（§3）尝试派生系统台账效果契约；
5. 资格预演（qualification：多试次跑通 + 故障注入）→ 产出密封 bundle（manifest 内容哈希）。

## 3. 效果挖掘的"诚实四分法"（compiler/effect_mining.py）

模块 docstring 开宗明义：编译器此前只会挖**视觉**后置条件，而"从演示自动派生系统台账 Effect 绑定"是两轮外部评审共同指出的缺口。本模块以**诚实**为最高原则关闭缺口：

- **零模型零网络**："The miner makes ZERO model / network calls — pure heuristics over what the demonstration already recorded"——编译期 $0 保证。
- 数据来源：录制时后端若暴露系统台账（`SystemOfRecordBackend`），recorder 在每个事件上写 `sor_before/sor_after` 快照（镜像既有 `url_before` 约定）；结构化 DOM 字段同理（`dom_fields_before/after`）。像素-only 面不写，走降级路径。

| 处置 | 条件 | 产物 |
|---|---|---|
| `derived` | 演示**真的观察到**台账前后差（如 `/api/db` JSON 快照）且恰好 1 条新记录 | 真实 Effect：`record_written(match=选择器, expected_count=1)` + 载荷字段 `field_equals` 读回 |
| `readback` | 无台账观察，但演示在保存后**看到过**该值 | 屏上读回 oracle（纯 GUI 录制的默认，替代无条件 HALT） |
| `placeholder` | 确是后果性写，但绑定不可派生 | 显式占位 Effect（哨兵选择器 `__unbound_system_of_record__: operator-must-bind`——**任何真实记录都不可能携带该值，误配置的运行也永远无法假确认**），运行遇到即 HALT |
| `none` | 无可派生效果且非后果性 | 诚实记"no verifiable effect derivable"，**绝不发 fabricated green** |

三条挖掘纪律（:87-104, :185-202）：

1. **代理键不入选择器**：`id` 类系统分配字段写入时才存在，编译期不知道，混进 match 只会匹配到演示那一行；
2. **载荷与身份分离**：值等于演示参数的字段是"写了什么"（field_equals），其余非空字段全部进身份选择器——"宁过细勿过松，过细只会拒绝、不会误认"（fail-safe 方向单一化）；
3. **恰好 1 条新记录才可绑定**：0 条（没写）或 >1 条（一步混入多次写）都拒绝——"无法诚实地绑定一个 at-most-once 契约"。

## 4. Effect 契约与证据强度分级

`runtime/effects/effect.py`：`Effect(kind, match, expected_count, risk, probe, idempotency_key, readback, needs_operator_confirmation)`；`EffectVerifier` Protocol：`capture_pre_state(context) -> EffectState` + `verify(expected, before, context) -> EffectVerdict`。

**三种契约类型**（docs/design/EFFECT_VERIFIER.md §Protocol）：

- `record_written`：匹配选择器的记录**恰好** `expected_count` 条（at-most-once 语义）；
- `field_equals`：单字段读回核对；
- `exact_new_set`：范围内**新增集合恰好等于声明集合**——防多写护栏。

**VerificationTier 证据强度分级**（verification.py:46-97）——本卷最重要的可移植抽象：

```python
class VerificationTier(IntEnum):
    INDEPENDENT_SYSTEM = 1        # 独立系统读（FHIR/REST/SQL/文件）——最强
    INDEPENDENT_SESSION = 2       # 独立会话读
    PERSISTED_STATE_REACQUISITION = 3   # 持久化状态重取
    IMMEDIATE_SCREEN = 4          # 立即屏读——最弱，与执行面同源
    # "Verifiers advertise strength explicitly; callers never infer it from
    #  class names, substrate labels, or prose."  —— 强度是声明值，不许从类名猜
```

- 生产 `VERIFIED` 的门槛 `VERIFIED_EFFECT_TIER = INDEPENDENT_SESSION`（:97）——**纯像素运行（无台账读）永远不可能 VERIFIED**（Citrix 场景被明确点名为不可 VERIFIED）；
- `verify_effect_without_mutation`（:24-43）：调用验证器前深拷贝 Effect、调用后比对序列化——**外部验证器篡改契约直接抛错**（防御性编程的极端纪律）。

【WT 启示】WT 的队列重试、run report 的 fallback 统计都隐含一个假设："截图/控件结果 = 业务结果"。VerificationTier 提供了把这件事**显式分级**的词汇：WT 的 `image_appear` 是 tier-4 屏读；若目标系统（Meteodyn WT / 数据库 / 文件产出）存在可读的台账（项目文件落盘哈希、结果 CSV 存在性、DB 行），就应声明 tier-1/2 效果契约。卷五给出 WT 版效果契约的最小落地形态。
