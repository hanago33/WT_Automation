本模块由四个职责正交的 Python 文件组成，共同构成 DSL 运行期的“可执行步骤 + 动作元数据 + 控件索引”三层：
- wt_business_steps.py：业务步骤实现与注册中心。通过 `configure_wt_business_steps(...)` 注入全局 `_LOG_STEP`、`_GET_*`、`_CLICK_*` 等回调（依赖注入），将 pywinauto_recorder 的 UIPath/click/send_keys 与上层环境解耦；`get_step_registry()` / `get_step_registry_map()` 以 `(step_id, step_func)` 列表形式暴露所有业务步骤，供引擎按 id 分派。
- wt_action_schema.py：声明式动作元数据。`ACTION_SCHEMAS` 字典集中定义 click/type_text/menu_select 等基础动作的 label/description/target_required/input_key/suggested_columns 等字段，并提供 `build_action_schema_hint` 生成面向编辑器的提示文本；同时维护新旧错误策略枚举 (`stepPolicy.onFail` ↔ `onError`) 的双向映射，保证向后兼容。
- wt_action_defaults.py：动作级超时与等待默认值 (`timeoutSeconds`/`waitBefore`/`waitAfter`)，由 `build_action_default_config` 合并覆盖后下发给执行器。
- wt_control_index.py：从 flow_definition.json 的步骤内嵌 controls、control_maps/总控件信息.json 和 standard_control_catalog.json 三个来源收集控件，去重并排序后输出人类可读的索引文本，供 DSL Agent System Prompt 使用；`build_dsl_context_for_agent` 直接构造 `DslContext` 供编辑器调用。
依赖方向：wt_business_steps 仅依赖 pywinauto_recorder 与 os/time/re，不反向引用 schema/defaults/index；schema 与 defaults 是纯数据/工具，被上层引擎消费；index 仅在构建 Agent 上下文时按需 import WT_AUTOMATION_Agent.agent.DslContext，避免循环导入。
