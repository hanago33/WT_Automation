## 2. 各资产详情与自动化关联

### 2.1 粗糙度索引文件（CorrespondanceFiles）— 已落地

- **路径**：`<安装目录>\Assets\CorrespondanceFiles\*.txt` + `<数据目录>\local_*\DATA\TOPOGRAPHY_CORRESPONDENCE\*.txt`
- **内容**：11+ 个文件，每个是"粗糙度代码→地表粗糙度长度(m)"映射（如 `ESA2020.txt: 10→0.5, 20→0.1`），对应 MUP 各粗糙度源（ESA/CLC/NLCD/Copernicus/GLC100m）。
- **与自动化关联**：流程 step20"选择粗糙度索引文件 ESA2020.txt"的下拉框选项即来源于此目录。采集器常采不到 `optionValues`，此处是**权威补全源**。
- **落地**：`mup_assets.py` 双源合并扫描（含 TIFF 版 `TiffCLC/TiffESA2009/TiffESA2010/TiffNLCD.txt`），注入下拉框 optionValues + 键盘导航后显示值验证 + `resolve_index_file()` 后置校验。

### 2.2 PROD 配置参数（PROD_default_parameters.ini）— 已落地

- **路径**：`<安装目录>\PROD_default_parameters.ini`（417 键）；`Customer_default_parameters.ini` 为可覆盖层（升级不覆盖）。
- **关键内容**：
  - 粗糙度源↔索引文件官方映射：`MTDSiteGeoServerConfig_5_RoughnessSourceName=rough:WC10_2020` ↔ `..._5_CorrespondanceFileName=ESA2020.txt`（8 组）
  - `GeoData_RoughLayers` 可用图层（8 个）
  - CFD 参数：DAS（36键）、NSParameters（89键）、OPT（146键）
  - `DAS_ExePath=BIN\DASSolver_1.2.3.exe`（CFD 求解器）
- **与自动化关联**：`ESA2020.txt` 应配对 `rough:WC10_2020` 源——可用作"选择粗糙度索引文件"步骤的**配置一致性校验**。
- **落地**：`mup_prod_config.py` 提供 `roughness_pairs()` / `correspondance_to_roughness_source()` / `rough_layers()` / `get_parameter()` 等。

### 2.3 用户配置（user.config）— 已落地

- **路径**：`%LOCALAPPDATA%\Meteodyn\MUPSmartClient.exe_Url_*\1.10.1.0\user.config`（glob 匹配跨机命名）
- **关键内容**：`ProjectionSelectionHistory`（投影历史 WKT，实测含 `CGCS2000 / 3-degree Gauss-Kruger zone 43` EPSG:1024）、气象数据导入解析规则（列头/分隔符/编码）、语言=zh。
- **与自动化关联**：投影选择步骤（step_10）的候选值来源。
- **落地**：`mup_user_config.py` 提供 `projection_history()` / `resolve_projection()`（EPSG/名称/WKT 三级匹配）；执行器 `wt_flow_executor.py` 已接入**投影选择后置校验**（成功步骤后确认所选投影在历史/预置中）。

### 2.4 用户数据目录（ProgramData）— 已落地

- **路径**：`C:\ProgramData\Meteodyn\MUP\local_<用户名>_<机器GUID>\`（跨机命名需 glob）
- **结构**：
  - `DATAFILES\OROGRAPHY\*.tif` — 导入的地形数据（实测 `TEST1_Project_43.tif` 2.9MB，43=CGCS2000 43带）
  - `DATAFILES\TIMESERIES\*.tim` — 测风塔时间序列（15个×2.3MB）
  - `DATAFILES\ROUGHNESS\` / `RESULT_FILES\` / `SYNTHESIS_FILES\`（计算/合成产物）
- **与自动化关联**：**流程产物落盘点**——导入/计算/合成步骤执行后文件系统即变化，可作为"步骤真生效"的文件级铁证（不依赖 UI 读值，避免假成功）。
- **落地**：`mup_data_files.py` 提供 `snapshot()` / `diff()` / `list_new_files()`；执行器在流程开始拍快照、收尾时把差异写入 `run_report["mupDataFiles"]`，总控台运行报告摘要展示"数据落盘：地形新增N个"。

### 2.5 内置 REST API（9998 端口）— 调研定性，不落地

- **证据**：`MUPSmartClient.exe.config` 含 `<RemoteAddress value="127.0.0.1"/><RemotePort value="9998"/>` + logger `MTD.RESTAPI.Server.MTDRESTAPIServerBootstrapper`；官方管理工具 `MUPManagementTool64.exe`（console）就是其客户端。
- **现状**：9998 未监听（默认不启动）；有认证层（`MTDAccessAuthorization.dll` + `CreateAdminUser` 命令，需建管理员/token，有数据库副作用）。
- **管理命令面**（`MTDManagementCommand.dll`）：`CreateAdminUser` / `ExecuteSqlCommand` / `Migrate` / `DeleteSite` / `ImportFile` / `ChangeConnection` — 均为**数据库系统运维**命令，**不含"新建项目/设投影/选粗糙度源"等业务流程操作**。
- **定性**：系统运维通道，非业务流程通道。对"创建风机类型/气象数据/地形数据"，UI 自动化仍是可靠方案；REST 不覆盖业务操作，故不落地。
- **备注**：`MUPManagementTool64.exe --help` 实测仅输出连接参数（`-n/-p/-s/-c`），无业务子命令。相关探测脚本归档于 `tools/research/mup_rest_probe*.py`。

### 2.6 MUP 运行日志（tmp_Logs）— 调研定性，不落地

- **路径**：`C:\ProgramData\Meteodyn\MUP\tmp_Logs\MUPSmartClient.log.<日期>`（log4net 按天滚动）
- **内容**：仅**启动/模块加载**事件（Search Modules / Initialize Services / Initialize Modules）+ **License 警告**。
- **局限**：**业务操作不落盘**——用户观察到的 `SaveChanges`/`ReloadRange`/`Publish LicenceUpdate` 等是 **OutputDebugString 调试输出**（走系统调试通道，不写文件；8/10 自动化运行期间文件日志零新增为证）。
- **结论**：不可用作"步骤真生效"日志源；仅可作为"MUP 是否成功启动"的辅助判断。

### 2.7 技术栈（Licenses 目录）— 记录备查

- `GribApi.Apache2.lic` → MUP 支持 **GRIB 格式气象数据**（标准气象数据交换格式，比 .tim 更标准）
- `Npgsql` → PostgreSQL 支持；`BitMiracle.LibTiff` → TIFF 处理；`NetTopologySuite` → GIS 拓扑
- **意义**：若测风塔/气象数据源提供 `.grib` 格式，MUP 原生支持，可写进流程数据格式建议。

### 2.8 其他（记录备查）

- `Assets\AutomaticReport\WORDTEMPLATE\CTSAutomaticReport.dotx / WDAAutomaticReport.dotx` — 自动报告模板（MUP 自动生成 Word 报告）
- `Assets\GoogleEarth\MODEL3D`（3 个模型）+ `TEXTURES`（11 个纹理）— Google Earth 导出可视化资源
- `BIN\DASSolver_1.2.3.exe` — CFD 求解器（唯一可执行文件）
- `zh\*.dll`（143 个本地化卫星程序集）— 界面中文文本，可作控件匹配参考（成本高，未采用）
- `gdal\data\epsg.wkt` — GDAL 投影库（数千投影，比 user.config 历史全，若需完整投影列表可作后备）

## 4. 探索中的关键结论（防重复踩坑）

1. **不要再用 `MUPManagementTool64.exe` 当业务流程通道**：它只暴露数据库运维命令，`--help` 无业务子命令。
2. **`tmp_Logs` 不含业务操作**：拿它做步骤校验是死路；业务日志走 OutputDebugString，需 DebugView/子进程捕获（当前 `os.startfile` 拿不到）。
3. **REST 9998 未启用且有认证**：要启用需建管理员 + token + 触发条件，且命令面是 DB 运维——**投入产出不成比例**。
4. **数据目录命名跨机变化**：`local_<用户名>_<GUID>`，所有读取需 glob 匹配（已实现）。
5. **粗糙度选项有双来源**：安装目录 + ProgramData 副本，且含 TIFF 版——采集器采不到 optionValues 时优先用本方案补全。
