# 定位与 MUP 资产驱动可靠性修复方案

日期：2026-08-17
范围：`wt_flow_locator.py`（7316 行）、`WT_AUT_recorded.py`、`wt_flow_executor.py`、`wt_run_reporting.py`、`wt_window_helpers.py`、`mup_assets.py`、`mup_prod_config.py`、`mup_user_config.py`、`mup_data_files.py`

本方案为调研结论的落地文档。所有问题均经代码全量审计 + 关键点抽查验证。实施顺序 P0 → P1 → P2，每项完成后跑 pytest 全量回归；P0 独立 commit（含针对性单测）。

## P0 — 防错位与假成功（直接威胁正确性）

### P0-1 MUP 窗口回退路径死代码（B1）
- **位置**：`wt_flow_locator.py:2833`（`_try_get_window_by_handle`）、`:3206`（枚举侧）
- **根因**：枚举侧把 hwnd 转成 `hex()` 字符串（如 `"0x1a0c"`），回退侧 `int(handle)` 不认 `0x` 前缀 → ValueError 被吞 → 返回 None。`find_flow_window` 的"MUP 可见窗口候选"回退分支（:4065-4075）恒为空，只剩前台窗口单候选。
- **改法**：`_try_get_window_by_handle` 内改 `int(handle, 0)`；枚举侧与回退侧共用同一解析函数，杜绝二次漂移。
- **验证**：单测覆盖 hex 字符串入参；真实环境临时把窗口标题改为必然不匹配，确认日志出现"回退候选窗口 N 个"且能定位。

### P0-2 下拉键盘导航"防错位"补全（B2）
- **位置**：`wt_flow_locator.py:2117-2146`
- **根因**：① 发 DOWN×N+ENTER 前不确认下拉已展开、焦点在列表内——未展开时按键落到当前焦点控件；② 显示值校验被 `if option_values_injected:` 门控，控件库自带 optionValues 导航后完全不校验；③ DOWN 次数未考虑当前选中项，重跑流程可能选到第 2N 项。
- **改法**：
  1. 导航前：`dropdown_expanded` 为 False 时先 set_focus+点击展开（复用现有展开逻辑），仍不可读则试 ExpandCollapsePattern；确认失败不发按键，直接转键入搜索。
  2. 显示值校验对**所有来源**生效（去掉门控），不匹配转键入搜索；注入来源保留日志区分。
  3. DOWN×N 前先发 HOME 把选中项归零。
- **验证**：单测 mock 未展开 / 已选中第 N 项两种场景；真实 MUP 同一流程连跑两次确认选中一致。

### P0-3 Toggle 闸门禁用枚举路径（B13）
- **位置**：`wt_flow_locator.py:2009-2015`
- **根因**：Telerik RadComboBox 的 TogglePattern 挂在 PART_DropDownButton，定位到 ComboBox 根时 ToggleState 读取失败 → 闸门恒 False → "枚举+点击"新增路径静默退化，全走键盘导航（叠加 P0-2 风险）。
- **改法**：闸门改三态——ToggleState 可读用之；不可读试 ExpandCollapseState；都不可用则"set_focus+点击 ComboBox 本体后枚举候选"，枚举不到才落键盘导航。
- **验证**：单测覆盖 toggle 读不到场景；真实 Telerik 粗糙度下拉确认枚举路径走通。

### P0-4 执行链假成功三连（BUG-2/3/6）
- **空步骤列表假成功**（`WT_AUT_recorded.py:1623-1631` `_resolve_steps_to_run`）：对每个被丢弃的步骤 id 记 warning（含总数）；`steps_to_run` 为空时中止并以 failed 收尾。
- **AI 干预"试过即成功"**（`wt_flow_executor.py:1280-1310`、`WT_AUT_recorded.py:1146-1162`）：配置了 continueWhen 时介入成功后同样执行 `_wait_for_continue_when`，不满足按失败；未配置时报告写 `aiInterventionUnverified: true` 并降级 partial_success。
- **runId 秒级碰撞**（`wt_run_reporting.py:29`）：runId 追加毫秒 `%f`；报告写入改 temp + `os.replace` 原子替换。
- **验证**：单测（空列表、AI 无校验路径、runId 唯一性、原子写）。

### P0-5 fallbackChain 成功无后置校验（BUG-4）
- **位置**：`wt_flow_executor.py:460-467` `_try_fallback_chain` 成功返回处
- **改法**：与模板兜底/AI 路径对齐，链成功后执行 `_wait_for_continue_when`（有配置时）；无配置时日志注明"未验证"。

## P1 — 可靠性

### P1-1 窗口最小化后永不恢复（BUG-1）
- `wt_window_helpers.py:147,178-195`：就绪判定要求"未最小化"，而恢复动作在就绪**之后**——恢复分支永远到不了。
- 改法：wait 循环内检测 minimized 先 `ShowWindow(SW_RESTORE)` 再判就绪；抽 `_restore_if_minimized` 公共函数。

### P1-2 Tab 导航阈值与异常兜底（B3/B4）
- `wt_flow_locator.py:1250-1252`：循环结束后 `best_score >= 70` 才返回，否则 None（与注释语义一致）。
- `:5976-5999`：`int(steps)` 加 try/except 默认 0；preferTab 块整体包 try/except 记日志后落入常规定位链。
- 缓存侧：错误/低分命中不写 FLOW_CONTROL_CACHE（避免 12 秒污染）。

### P1-3 MUP 落盘铁证修正（BUG-7）
- `WT_AUT_recorded.py:1834-1838`：before 快照移到 launch_gm 完成之后（或首个业务步骤前），排除启动期初始化文件误报。
- `:1743`：判定加 `or result["deletedCount"]`（纯删除场景也写报告）。
- `:1750`：裸 `except Exception: pass` 改 warning 日志 + `run_report["mupDataDiffError"]`。
- `mup_data_files.py:107-112`：changed 判定容差 0.5s→2s，或结束前延时重扫一次。
- `locate_data_dir`（:40-48）目录漂移：diff 时校验 before/after 同目录，不同仅报漂移不报文件变化。

### P1-4 投影后置校验修正（BUG-8）
- `wt_flow_executor.py:1125-1173`：校验目标改读下拉当前选中值，而非 controlName（现在"投影"二字即触发、子串匹配易假通过）。
- `resolve_projection` 前调 `mup_user_config.clear_cache()`（否则本次运行新加的投影被判不在历史）。
- 解析异常记 warning 写报告，不静默 `return {}`。

### P1-5 窗口存活与点击异常（B5/B6）
- `wt_flow_locator.py:3021-3031` `is_wrapper_alive`：句柄存在时追加 `ctypes.windll.user32.IsWindow` 校验（死窗口缓存不再永久有效）。
- `:6724-6736` `click_flow_control`：三处 click_input 包 try/except，失败走 `click_wrapper_center` 坐标兜底再返回 False。

### P1-6 下拉候选点击失败恢复（B9）
- `wt_flow_locator.py:1963,2037-2046`：显示值校验失败后剔除该候选、重置 `expanded_attempted` 重新展开；候选耗尽转入键盘兜底（当前会无限重复点同一个错误项）。
