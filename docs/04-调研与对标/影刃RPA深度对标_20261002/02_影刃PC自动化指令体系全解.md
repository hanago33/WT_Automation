## 4. win32 窗口族与系统级指令

### 4.1 窗口指令（`xbot_visual.win32.window`）

统一参数前缀 `window_type: window_instance | window_selector | win_handle | win_title_or_class`（**四种寻窗方式逐指令可选**），支持 `use_wildcard` 通配标题：

| 指令 | 语义 |
|---|---|
| get / get_list | 按选择器/句柄/标题+类名取窗口对象（get_list 支持批量） |
| get_details | operation: title/text/process_name |
| activate / set_state(minimize/maximize/restore) / **set_visibility(hide/show)** / move / resize / close | 状态控制族 |
| contains_element | content_type: contains_element/not_contains_element + 元素或文本（**窗口内容断言**） |
| exists / wait_window | 存在判断/等待 |

Win32Window 对象方法（代码模式）另有：`is_active / wait_active / wait_close / wait_focus / wait_focusout / find / find_all / wait_appear / wait_disappear / get_detail(title|text|process_name)`。

### 4.2 键鼠原始操作（`xbot_visual.win32`）

- `move_mouse`：relative_to: screen/currentactivatedwindow/**currentmouseposition**；move_speed: instant/fast/middle/slow
- `click_mouse`：button left/right/middle；click_type click/dbclick/**down/up**（按下/弹起可拆开）；hardware_driver_click（驱动级）；is_move_mouse_before_click；keys 修饰键
- `wheel_mouse`：up/down × wheel_times + keys；**is_wheel_point + 坐标**（在指定位置滚动，不必先移鼠标）
- `send_keys`：keys + hardware_driver_input + send_key_delay + contains_hotkey + fore_ime_eng
- `get_mouse_position`
- **`manual_motion_on/off`**：`motion_move`(随机路线移动) / `motion_click`(随机落点点击) / `motion_delay`(指令间随机停顿 min_time~max_time 秒) —— **一段流程区间内整体拟人化**

|---|---|
| lock_screen / unlock_screen(user, password) | 锁屏/带凭据解锁 |

## 5. 图像自动化指令族（4 条 + 引擎参数）

| 指令 | 参数要点 |
|---|---|
| image.wait | window_kind: screen/window/currentactivatewindow；wait_mode: appear/disappear；template_images(**images 编辑器，多选**)；is_wait_all_images(bool)；iswait+timeout；→ wait_result |
| image.click | 同上寻域 + anchor_type(center/random/custom)+sudoku+offset + clicks/button/keys + move_mouse + timeout=5 + delay_after |
| image.hover | 同 click 减去按键参数 |
| image.exist | exist_mode: exist/notexist + is_find_all_images |

设计观察：
1. **图像与元素指令形态完全同构**（寻域→目标→锚点→动作→timeout→delay_after），用户学一套心智模型；
2. 图像库独立成库（imagesV2.xml repository），指令只引用名字，**模板可替换而流程不用改**；
3. 多图组 + `wait_all` 开关天然支持"多个可能弹窗，等任何一个出现"的分叉场景；
4. 引擎侧相似度阈值参数化（Provider 中 `similarityThreshold`），而非全局硬编码。

## 7. 流程控制原语（workflow 15 条 + programing 异常系）

```
workflow.if / elseif / else / endif          ← 表达式 test(operand1, operator, operand2)
workflow.multiple_conditions_if (+elseif)    ← 多条件组合判断
workflow.for (start/stop/step)
workflow.while (test)
workflow.forin (list + loop_start_index/loop_end_index + 可选倒序)
workflow.forin_expr（表达式取列表）

workflow.continue / break / endloop / infinite_loop

programing.snippet（code 编辑器，裸 Python）
programing.variable / sleep / log / random_int / comment / region/endregion

```

操作符语义（`workflow.test` 桩代码枚举）：`in`、数字比较（可解析 int/float）、日期比较（pywintypes 时间自动转换）、空值处理（empty_value）、大小写归一。**控制流靠"指令块 + indent/scope 声明"实现**，编译器把块结构翻译成 Python 的 for/if/try——WT 的线性步骤表若引入块指令，可用同样的 JSON 嵌套方案。

## 9. 弹窗守护与元素监控（隐蔽但高价值的能力）

`xbot\_core\monitor_manager.py`（桩）：

```python
add_monitor_record(handle_method, close_button, element_selector, process, package)
remove_all_record()
register_triggers_in_browser(browser)
```

配合资源串中的两句话术：
- `发现%close_button%按钮时，关闭弹框` —— **注册"看见即关"的弹窗黑名单**；
- `发现%element%时，执行流程%process%` —— 元素出现即触发指定流程。

这解决 RPA 最经典的翻车场景：跑长流程时突然弹出升级提示/错误框，整条流程卡死。WT 的 MUP 自动化同样会被各类提示框打断，该机制（后台监控线程 + 出现即处置）值得列入规划。
