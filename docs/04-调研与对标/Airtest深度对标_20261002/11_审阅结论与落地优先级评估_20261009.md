## 1. 结论摘要

1. **图像域判断全部成立**。卷四 21 维矩阵中图像域 7 项缺口（多尺度粒度、`region` 未参与匹配、灰度单段置信度、无早退、无模板级参数、裸 Point 结果、无多实例消歧）逐项回码核实**属实**；三份独立对标（影刃 P0-4、Airtest 卷五、OpenAdapt T1）**同时指向图像域**——这是全项目最高杠杆的改造，且三份互为补充（需求=影刃、实现=Airtest、算法增补=OpenAdapt）。
2. **阶段 A / B / C 建议采纳**，合成"图像域批次"（Airtest 合计约 3 人日）；阶段 D 维持触发条件制。
3. **校正 5 处**（见 §3），最重要两处：调用点"15 处"实为 **5 处**（改造面比文档更小）；模板"50 张"实为 52 张（含非模板与重复图）。
4. **新发现一条低成本高价值项**：卷九"报告渲染增强"（模板缩略图 / 生成永不崩 / 全相对路径归档 / 工具化入口）建议列入第二批小项。
5. **附带发现**（与 Airtest 无关、独立缺陷候选）：`WT_AUT_recorded.py:2244` 调用的 `_click_template` 在生产代码中无定义（仅存在于 `samples/legacy_tests/`），见 §6。

## 4. 落地建议

### 4.1 定位：图像域批次 = 三份对标的收敛点

```
影刃 P0-4（需求："图像一等公民"+等待语义+多图组）
  + Airtest 阶段 A/B/C（实现蓝本：参数入库→内核→等待审计，卷六带代码）
  + OpenAdapt T1（算法增补：多实例消歧门 ~60 行）
  = 一个完整"图像域批次"（约 3.5 人日，2~3 个 commit）
```

**该批次优先于影刃卷八的 P0-4' 原始建议**（原始建议只含"索引统一 + 参数透传"，应升级为本批次）。

### 4.2 与影刃 08 卷/OpenAdapt 06 卷的排期合并

| 批次 | 内容 | 参照 |
|---|---|---|
| 第一批（不变） | P0-6' Agent schema 同源；P0-5' 防休眠+卡死登记；P1-6 参数快照 | 影刃 08 卷 §4 |
| 第二批（扩充） | ① 输入通道参数化 + 剪贴板（影刃 P0-1/P0-2' + Airtest 扫描码 D3 + 卷八协商思想）；② 重试退避（影刃 P0-3' + **Airtest 重试装饰器**）；③ **图像域批次（本卷 A/B/C + T1）**；④ 报告可用性增强（本卷卷九四项） | 本卷 §4.1 + 影刃 08 卷 §5 + OpenAdapt 06 卷 §5 |
| 第三批/触发条件 | 阶段 D（mss/BRISK/find_all）、录屏、错误码、T2/T5 治理项 | 各卷 |

### 4.3 落地前置：schema 合并（避免双字段体系）

三份对标给出三组图像参数字段，**落地时必须合并为一份 schema**（一次定稿）：

| 来源 | 字段 |
|---|---|
| Airtest 阶段 A | `threshold` / `rgb` / `scale_step` / `scale_max` / `capture_resolution` |
| 影刃 P0-4' | `match{confidence, scales, grayscale, region_hint}` |
| 既有索引字段 | `region`（复用为 ROI）、`source_screenshot`、`updatedAt` |

建议形态：以 Airtest 字段为主体（有代码蓝本），`region_hint` 语义直接用既有 `region`，`grayscale` 与 `rgb` 二选一（建议用 `rgb`，与 Airtest 一致、默认 False）。

## 6. 附带发现（与 Airtest 对标无关，独立缺陷候选）

**`_click_template` 疑似 NameError**（审阅调用点时发现，镜像副本同样存在）：

- 调用点：`WT_AUT_recorded.py:2244`（DWG 投影选择"从文件加载"的图片识别兜底分支）、`:2253`（文件名输入框兜底，位于 try 内会被捕获）；镜像 `tools/generic_flow/generic_automation.py:2169/2178`。
- 实测：`_click_template` 的定义**仅存在于** `samples/legacy_tests/test_projection_loading.py:266`（samples 不参与默认执行）；生产代码无定义、无导入、无别名赋值（全仓精确搜索仅此 1 处定义）。
- 影响：`:2244` 分支一旦触发（流程链路匹配失败时的图片识别兜底）即抛 `NameError`；该分支本身处于"失败处置"路径，属二次错误（不影响正常路径，但让失败恢复失真、日志误导）。
- 建议：独立立项确认（修复方向：改用 `wt_projection_helpers.click_template` 或删除该兜底分支改为显式报错）。**本审阅不改代码**，交维护者决策。
