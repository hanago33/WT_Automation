1. **步骤切换会静默丢失未应用的表单修改**

   在 [WT_Flow_Editor.py:5085](/D:/My_RF_Project/WT_Automation/WT_Flow_Editor.py:5085) 的 `_on_tree_select()` 和 [WT_Flow_Editor.py:5115](/D:/My_RF_Project/WT_Automation/WT_Flow_Editor.py:5115) 的 `_select_step()` 中，选择新步骤时会直接调用 `_load_step_into_form()`。

   但普通输入框、文本框、下拉框没有统一的修改跟踪，`dirty` 主要只在“应用步骤”“新增步骤”等命令中设置。典型场景：

   1. 修改步骤名称或 Action 参数；
   2. 不点击“应用修改”；
   3. 点击另一个步骤；
   4. 原来的修改直接被覆盖。

   保存时 [WT_Flow_Editor.py:5964](/D:/My_RF_Project/WT_Automation/WT_Flow_Editor.py:5964) 只会尝试保存当前选中的表单，因此之前步骤的修改无法恢复。

   建议：

   - 增加独立的 `form_dirty` 状态；
   - 给 `StringVar`、`BooleanVar` 和文本框统一绑定变更事件；
   - 切换步骤、删除步骤、拖动排序、打开文件、关闭窗口时，统一弹出“应用 / 放弃 / 取消”；
   - 或者在切换步骤前自动提交当前表单，但仍建议保留显式“放弃修改”。

2. **控件 ID 修改后，所有引用没有完整同步**

   [WT_Flow_Editor.py:5382](/D:/My_RF_Project/WT_Automation/WT_Flow_Editor.py:5382) 的 `cmd_edit_control()` 只在当前目标控件正好等于旧 ID 时更新目标控件：

   ```python
   if self._get_target_control_id() == old_id:
       self._set_target_control_value(new_id)
   ```

   但没有同步：

   - `actionConfig.continueWhen.controlId`
   - 其他可能引用该控件的步骤字段
   - 当前表单中的 `action_config_text`
   - 其他运行时配置或辅助引用

   结果是：控件看起来已经改名，但保存时校验可能提示旧 ID 不存在，或者运行时仍然使用旧 ID。

   建议建立统一的 `rename_control_id(step, old_id, new_id)`，一次性更新本步骤所有引用，并在修改控件 ID 时显示引用数量。

> 这个为什么能成功，如果相对位置没变但窗口大小变了是不是就不行？

对，这个方案能成功的前提是：当前“导入时间序列文件”窗口的实际布局和录制时一致，或者至少相对坐标仍然对应同一个视觉位置。

它成功的原因是这次失败不是窗口真的缩放了，而是同一个窗口 UIA 有时返回了两套边界：

- 成功基准：`115,25,2329x1465`
- 失败时运行时边界：`128,76,2304x1364`

两者差异主要是标题栏/边框/内容区口径不同。你的 `relativeRegion` 本来就是按成功基准录出来的，所以我让这些步骤继续按录制基准换算，就能抵消 UIA 边界口径漂移。

但你说的风险成立：如果用户真的把窗口缩放了、换分辨率、DPI 改了、软件布局自适应了，那么固定 `referenceWindowRect` 不会自动适配。它解决的是“同一窗口同一尺寸下，API 返回内容区/外框不一致”的问题，不是通用缩放适配。

更稳的升级方案是：保存录制基准矩形，但运行时按当前窗口外框与录制外框做比例缩放。也就是：

```text
runtime_x = current_left + (recorded_relative_x * current_width)
runtime_y = current_top  + (recorded_relative_y * current_height)
```

关键是 current_width/current_height 必须是真正同口径的窗口外框。当前问题正是这个 current rect 不稳定，所以不能直接用它。最佳长期方案是：

1. 录制时保存 `referenceWindowRect`。
2. 执行时先尝试找到同口径外框。
3. 如果能稳定拿到外框，就按当前外框缩放。
4. 如果只能拿到内容区，就退回录制基准，避免这次这种偏移。

也就是说，我刚才做的是保守止血修复；它会让你这条固定流程恢复，但不算最终的“可缩放窗口适配”。
