# F2 · 故障树与排障手册

> 本篇回答：**出问题了，按症状往哪查**。
> 读者：所有人。**这是整套文档里最实用的一篇。**
>
> 底层原理在卷 B，报告字段在 F1；本篇是**症状 → 根因 → 修复**的索引。

---

## 0. 排障方法论（照做即可）

| # | 步骤 |
|---|---|
| 1 | **拿证据**：先看 `logs/last_run_report.json`（F1 §4 三步读报告法） |
| 2 | **写假设**：列出 2–3 个**可证伪**的假设，不要凭猜叠加补丁 |
| 3 | **最小插桩**：在关键分支落取证日志（候选、得分、命中窗口 rect、控件 Pattern） |
| 4 | **pre-fix / post-fix 对比**：改前改后各跑一次，对比同一步的候选与得分，确认因果 |
| 5 | **最小修复**：只改根因点 |
| 6 | **回归**：跑相关单测；必要时把断言改成"更强的新行为"，**不要放宽断言** |
| 7 | **沉淀**：按"背景/症状 → 假设 → 调试计划 → 运行时证据 → 结论 → 修复 → 验证"记进 `docs/05-调试案例/debug/` |

> ⚠️ 两条铁律：
> ① **报错步往往不是首因**，回溯到第一个"界面没按预期变化"的步骤；
> ② **动作成功 ≠ 业务生效**，必须校验状态变化。

## 2. 假成功（日志成功但界面没变）

| 模式 | 症状指纹 | 根因 | 修复范式 |
|---|---|---|---|
| **A · 命中展示层** | 命中控件 `controlType=Text/TextBlock`、`IsKeyboardFocusable=False`、无 Invoke/Selection/Value/Toggle 任一 Pattern | 打分命中了**只读显示层文字** | 补真实可点击目标，或改用 `click_relative_region`；评分里降权纯展示型控件 |
| **B · 输入未提交** | 输入"成功"但下一步依赖该值的操作失败 | 值写入控件但**未失焦/未回车** | 配 `postInputKeys: {TAB}` 或 `{ENTER}` |
| **C · 错窗口** | 相对区域点击落到主窗（rect ≈ 全屏）而非弹窗 | 空标题 WPF 主窗评分过宽 | 前台窗口优先；空标题窗口只在"确为前台"时兜底；收紧标题匹配 |
| **G · 首因滞后** | 末尾某步报"找不到控件" | 上游某步假成功导致前置条件不满足 | **回溯到第一个界面未按预期变化的步骤** |

**快速判断**：在步骤上加 `continueWhen` 断言，立刻能区分"没点到"和"点了没生效"。

## 3. 定位失败与误命中

| 模式 | 症状指纹 | 根因 | 修复范式 |
|---|---|---|---|
| **F · 同名同类** | 一排同 type/name 的控件里点错序号；`automation_id` 含 `_5` 升级后变 `_6` | 缺稳定"同级序号"消歧 | 用 `inspectData.foundIndex`（父容器内同类同级 0 基）+ 打分 +12；**永不覆盖可靠 id/name** |
| **L · SVG name 劫持** | fast 阶段空转 2–3 s 后掉整树；控件 `name` 是几百/几千字符的 SVG path | fast 查询 `if name … elif automation_id` 让稳定 ID 分支被跳过 | **automation_id 优先**；`_is_svg_path_name()` 识别 SVG 时跳过 name 查询 |
| **L' · 面板标题污染** | 各节点共用图标按钮（`InterestAreas_Button_*`），UIA name 是 M6/M19 等 SVG，功能语义在 helpText/面板标题 | 采集端取了字段标签而非节点名；对话框去重键把 8 个节点并成 1 条 | 按 `InterestAreasView_Tile_Header` 面板节点名消歧；**三处同时改**（C3 §7） |
| **N · 高分早退劫持** | 点 A 命中同排兄弟 B；score ≈110–150（回退分）而非 170+ | 共享 automationId + 同型，`(aid,ct)` 回退仍 ≥100，fast 早退 | `_candidate_strict_full_match`：含消歧字段时早退必须**完整命中全部消歧字段** |
| **P · IsControlElement=False** | `PART_ContentHost count=0`；rawInspectText 里 `IsControlElement: False` | Control View（children/descendants/FindAll）不可见 | 如实标 `isControlElement=False` + 真实 controlType(Pane) + label 消歧，触发 `control_definition_expects_raw_view` |
| **R · 逻辑树 ≠ 运行时父链** | 离线 mock 全过、真机全灭 | 运行时每个 textbox 外层可能包 NumericUpDown 等模板容器 | 先 live 枚举真实 parent 链验证；优先选与包装无关的锚（紧邻兄弟 label + 容器内序号） |
| **O · 批量只遍历第一棵子树** | 批量选择只命中第一个；多候选（≥2）必现 | RawViewWalker 只把 `GetFirstChildElement` 首子入栈，未沿 `GetNextSiblingElement` 把其余直接子入栈 | 先把容器**全部直接子**入栈再逐层深入；去重用 handle/runtimeId |
| **ui_path 全失效** | 父链中间节点变化后整串不匹配，所有兜底全失败 | `ui_path` 是整串包含匹配，`ancestors` 只加分不重建路径 | 已知缺口，见 F3；临时方案：加 `label_text` 消歧 |

## 4. 原生崩溃（无 traceback，进程直接死）

| 模式 | 症状指纹 | 根因 |
|---|---|---|
| **H** | 日志在"开始执行步骤"后直接"自动化流程执行失败"，无"步骤结束"也无"错误："；faulthandler 报 `access violation` 或 `0xc0000374`，栈顶 `Garbage-collecting → comtypes … Release → __del__` | UIA 元素数组在 **GC 回收**时释放失效 COM 指针。**try/except/finally 完全抓不到** |
| **H-2** | 每步 `success`、报告 `success`、"运行结果摘要已写入"都打出，**但总控台仍报失败**；退出码非 0（如 `-1073741819` = `0xC0000005`）；faulthandler 无 dump | 收尾阶段崩溃：①**跨线程 Tk 重入**（后台线程调 `root.update()` → 递归进入 Tcl 事件循环）；②**跨线程 COM**（后台 `CoCreateInstance`、主线程 ctypes 直调 → 跨公寓）；③`gc.collect()` 与 `Py_Finalize` 释放失效指针 |
| **H-3** | 报告已落盘后立刻 `access violation`，栈指向 daemon 线程的 `run_automation` 结束/异常路径 | `finally` 里 `gc.enable()` 重新打开 GC → 异常 unwind 后下一次 GC 收集持有失效指针的对象 |

**统一修复范式**

| # | 措施 |
|---|---|
| 1 | `run_automation` 入口 `gc.disable()`；**`finally` 里不要 `gc.enable()`**，保持禁用直到 `os._exit()` |
| 2 | Tk 与 COM **一律主线程**：`MonitorWindow` 的方法去掉 `self.root.update()`；后台线程只经 `_ui_safe_call` / `root.after(0, cb)`；`_TaskbarProgress` 必须在**主线程**创建 |
| 3 | 收尾用 `os._exit(exit_code)` 跳过 `Py_Finalize`；成功 0 / 异常 1 |
| 4 | 保留 `faulthandler.enable(file=sys.stderr, all_threads=True)` 用于 dump 栈 |
| 5 | 校验定位放**隔离进程**（`control_locator_probe.py`） |

## 5. 性能

| 模式 | 症状指纹 | 根因 | 修复 |
|---|---|---|---|
| **J** | `[定位耗时] 整树=19000~36000ms`，fast 明明毫秒级命中 | `wrapper_matches_label_text` 对候选做 parent/top_window **全子树扫描**；兄弟 TextBlock 匹配排在后面；label 缓存每步硬清空 | ①兄弟 TextBlock 匹配**提前**到全树扫描前；②label 矩形缓存改 **TTL 软失效 30 s**；③Raw View 候选先做**兄弟标签预过滤** |
| **K** | `[FlowLocator] 窗口过滤严格无命中，回退前置窗口单候选` 反复出现；窗枚举 3 s+；`last_error='NoneType' object is not iterable` | ①`EnumWindows(enum_proc, 0)` **误传类型工厂**而非回调实例 → 被吞 → 永远返回空；②`_iter_raw_view_findall_candidates` 在异常分支 `return`（None）→ `for … in None` 抛 TypeError → **整条定位链提前炸穿** | ①`EnumWindows` 传回调**实例**；②返回候选列表的函数异常路径一律 `return []` |

> 📌 **通用纪律**：任何"返回候选列表"的函数，异常/提前返回路径必须 `return []`，不能 `return None`。

## 6. 缓存污染

| 模式 | 症状指纹 | 根因 | 修复 |
|---|---|---|---|
| **E** | 改了评分逻辑仍反复误命中同一个错对象；换窗口后仍拿旧结果 | `FLOW_CONTROL_CACHE` 命中未校验**当前窗口归属** | 缓存键/命中处加窗口归属校验，归属不符即失效重查 |

**缓存与 TTL 一览**（B3 §7）：窗口 60 s、控件 12 s、父容器 20 s、UIPI 判定 3 s、label 矩形 30 s（thread-local 软失效）。

## 7. 假失败

| 模式 | 症状指纹 | 根因 | 修复 |
|---|---|---|---|
| **I** | 键入/下拉日志显示成功，随后 `等待步骤续跑条件 … condition=value_equals` 超时失败；每次续跑等待都重新全量定位（单步 60–90 s） | 执行器对输入类动作**自动生成 `value_equals` 值断言**，但 `PART_ContentHost` / `PART_DropDownButton` / Text 标签 / 无 label 消歧的裸 `textbox` **读不到值** | `_is_unreadable_value_control` 识别后**跳过自动值断言**（动作成功即通过） |

## 8. 批量与名单

| 模式 | 症状指纹 | 根因 | 修复 |
|---|---|---|---|
| **O** | 只选中第一个元素（≥2 候选必现） | 同 §3（RawViewWalker 只入首子） | 全部直接子入栈 |
| **Q** | 日志 `wanted=["${runtime.xxx}"]`；未选项目文件夹时必现 | `_resolve_dynamic_value` 对空串/None **保留字面量**（防 `send_keys` 吃花括号） | 名单类动作入口检测 `${` 前缀 → 记警告并按"全选/默认语义"处理。**不要改 resolver 的空值保护** |
| **M** | 多选下拉误勾等级（曾误勾 0 和 3），或 `未找到匹配控件` | 等级文本在 CheckBox **子节点**而非自身/兄弟；Raw View 预过滤只做兄弟 | 预过滤加**子节点**匹配（深度≤2）；`wrapper_matches_locator` name 分支回退含子节点文本；配 `label_text` + `precondition` 幂等 |

## 9. 环境类

| 症状 | 根因 | 处理 |
|---|---|---|
| worker 看不见 MUP 窗口 | **会话不同**：不同 Session 的进程 `EnumWindows` 看不到对方 | `diagnose_session.py` 查 SessionId；`服务器一键会话修复.bat` |
| 输入无效 / 查询被拒 | **UIPI**：低完整性级别进程不能向高完整性级别进程发输入 | 同样提权；`.bat` 已做管理员提升 |
| 锁屏/RDP 断连后失败 | UI 树与渲染失效 | 保持可交互会话存活（运维侧保证） |
| 任务一直 `pending` | 服务未跑 / 连通性问题 | `wt_queue_selfcheck.py --check <IP>` |
| 任务卡 `running` | worker 崩溃 | `recover_orphan_running_tasks`（默认 120 s） |
| 跑的流程不是我投的 | worker 读本机默认 | 校验任务是否携带 `flowPath`（C5 §3.2） |

## 10. 启动与部署

| 症状 | 处理 |
|---|---|
| 双击后一闪而过 | 用 `调试启动_显示错误.bat`；查 `logs/launcher_headless.log` |
| 内网提示找不到 Python | 不要装 Python；跑 `验证环境_内网.bat` 三步排查（便携包 → 依赖 → 全量包） |
| 刚部署/切换后启动无反应 | **先重启电脑**（陈旧文件句柄 / 杀软首轮扫描） |
| `make_release.exe` 报找不到仓库 | exe 必须在仓库目录内（靠 `git rev-parse` 定位） |
| 内网缺 VC++ 运行库 | 把开发机 `vcruntime140.dll` / `msvcp140.dll` 拷到便携 Python 目录 |
| 界面发虚 / 一部分窗口很小 | DPI 虚拟化，调"界面缩放"档位（B1 §5） |
| 中文乱码（发布包） | 发布包是 UTF-8，必须用 `deploy_release.exe` 解压，**不要用资源管理器** |
