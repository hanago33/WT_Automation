### 7 个 problem 明细（`validate_chain_manifest` 实测）
全为「可降级」类（不涉及文件缺失/非法）：
```
- terrain: 不含 flowPackages.id=地形导入（实际 test）
- project: 不含 flowPackages.id=创建一个新建模（实际 test）
- project: 未消费 ${runtime.projectName}
- turbine: 未消费 ${runtime.turbineImportFilePath}
- turbine: 未消费 ${runtime.thrustCurveFilePath}
- element: 未消费 ${runtime.mastCoordFilePath}
- element: 未消费 ${runtime.turbineCoordFilePath}
```
根因：manifest 是 #4 波新写的（声明新 id + 新 runtime 键），但 flow 初时被还原到 HEAD（原版用 `id="test"` + 硬编码路径）。

## ⚡ 最终根因澄清（2026-11-03 追加）
flow 恢复新版（runtime 注入）后，`validate_chain_manifest` problem 数 **7 → 0**。证明这 7 个 problem **纯粹是 flow 被误还原**所致——HEAD 原版 flow 是硬编码路径旧版，与 manifest 契约脱节。恢复 `_WAVE-NEW` 新版后完全一致。配套：`test_input_contract_p0.py` 从 5 失败 → 18 passed 全绿；全量测试 exit code 0。
