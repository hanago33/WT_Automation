# 00 · 术语与缩略语

> 全文档集统一用词。同一概念在不同模块里可能有不同叫法（历史遗留），本表给出**规范名**与**别名**，
> 写代码、写步骤、写文档一律用规范名。

---

## 1. 领域（风力发电 / Meteodyn WT）

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| MUP | Meteodyn Universe / WT 软件 | 法国 Meteodyn 公司的风资源评估与风电场设计软件，本项目自动化的**被测目标程序**。主进程 `MUPSmartClient.exe` |
| 测风塔 | Mast | 现场测风设施，含多个高度层的风速/风向时间序列 |
| 机位点 | Turbine position / WTG | 拟布置风机的坐标点 |
| 地形数据 | Orography / ORO | 以 `.tif` 形式导入的高程栅格 |
| 粗糙度 | Roughness | 地表粗糙长度，MUP 通过"粗糙度索引文件"（如 `ESA2020.txt`）映射 |
| 微尺度 CFD | Microscale / CFD 计算 | 基于 CFD 的流场计算，产出风资源图谱 |
| 综合计算 | Synthesis / 发电量计算 | 把风资源图谱 + 风机功率曲线 → 年发电量（AEP）的全过程 |
| AEP | Annual Energy Production | 年发电量，风电场核心评价指标 |
| 尾流 | Wake | 风机下游的风速亏损与湍流增强 |
| 威布尔分布 | Weibull | 风速频率分布的常用拟合形式 |
| 空气密度修正 | — | 把 10 min 时序风速折算为等效风速的 IEC 常用方法（`make_power_template.py` 使用） |
| 投影 | Projection / CRS | 地理坐标系，MUP 中需为项目指定；历史值可从 `user.config` 提取 |
| 计算域 | Spatial domain | CFD 计算的空间范围，`wt_spatial_domain_calc.py` 负责计算与参数注入 |
| Simple 模式 | — | MUP 的一种项目创建模式，参数可由项目工作文件夹自动解析（`wt_project_workdir_parser.py`） |

## 2. 系统分层与运行

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| 总控台 | `WT_Launcher.py` | 主 GUI 入口，集成流程选择、参数配置、执行、队列、监控、流程图 |
| 流程编辑器 | `WT_Flow_Editor.py` | 可视化编排/编辑流程定义的 GUI |
| 执行器 | Executor / `wt_flow_executor.py` | 解析流程定义、调度步骤、执行动作、收集结果与报告的运行时核心 |
| 定位器 | Locator / `wt_flow_locator.py` | 把"控件语义"转成"屏幕坐标/控件句柄"的模块（10 327 行，本项目最大模块） |
| 控件索引 | Control index / `wt_control_index.py` | 控件元数据的 LLM 可读索引（现为向后兼容包装器，指向 `WT_AUTOMATION_Agent.control_index`） |
| 外部桥接 | Backend / `tools/external_capture/` | 访问目标应用 UIA 树、截图、发输入的适配层 |
| 工作进程 | Worker | 由 `wt_task_server.py` 拉起、实际执行流程的 `WT_AUT_recorded.py` 子进程 |

## 3. 流程与动作

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| 流程定义 | Flow definition / `flow_definition_<板块>.json` | 一个业务板块（如"发送综合计算"）的完整步骤序列与参数的 JSON 描述 |
| 流程包 | Flow package | 流程定义 + 依赖资产的可分发单元，由 `flow_package_registry.json` 登记 |
| 注册表 | Registry | `flow_packages/flow_package_registry.json`，集中登记所有可用流程包 |
| 步骤 | Step | 流程中的一条执行单元，有唯一 `stepId` |
| 动作 | Action | 步骤的原子执行类型，共 **19 种**（见卷 E1） |
| 业务步骤 | Business step | 多个原子动作组合出的领域复合动作（`wt_business_steps.py`） |
| 子流程引用 | `flow_ref` | 步骤内引用另一个流程/步骤，实现复用与编排 |
| 前置条件 | `precondition` | 步骤执行前求值的跳过/继续判定表达式 |
| 继续条件 | `continueWhen` | 动作执行后需等待满足的 UI 状态条件（exists / visible / enabled / gone / value_equals / toggle …） |
| 步骤策略 | `stepPolicy` | 步骤级失败策略（含 `maxRetries`） |
| 降级链 | `fallbackChain` | 主定位/动作失败后依次尝试的备用动作序列 |
| 运行参数 | Run params / 占位符 | 运行时才绑定的值（文件路径、塔名等），支持多层级覆盖 |
| 参数矩阵 | Param table / `param_table_*.json|xlsx` | 批量运行的参数组合表 |

## 4. 控件与定位

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| 控件 | Control / Element / Wrapper | 目标程序 UI 树上的一个节点 |
| 控件库 | Control map / `control_maps/` | 控件结构化描述的资产集合（173 文件，4 子目录） |
| 采集 | Capture / 半自动采集 | 通过遍历 UIA 树或交互式点击，把控件信息录入控件库 |
| 控件语义 | — | 用于定位的一组属性组合（automationId / name / controlType / 祖先链 …） |
| UI 路径 | `ui_path` | 从窗口根到目标控件的完整路径字符串（当前为**整串包含匹配**，见 B3 已知缺口） |
| 祖先 | `ancestors` | 控件的父链，评分时允许**部分匹配** |
| 同级序号 | `foundIndex` | 同名同型兄弟控件中的序号，用于消歧 |
| 候选 | Candidates / `_candidates/` | 采集过程中待确认的控件条目 |
| 标准控件库 | `standard_control_catalog.json` | 由 `tools/merge_standard_control_library.py` 合并出的统一控件目录 |
| 自愈 | Self-heal | 定位失败后记录成功覆盖的定位器，下次复用的学习机制 |
| 亲戚区域 | Relative region | 以父窗口为基准按比例/偏移定位，不依赖控件树 |
| 锚点 | Relative anchor | 以某个已知控件/区域为基准做偏移定位 |

## 6. 任务与服务

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| 任务队列 | Task queue / `wt_task_queue.py` | 基于 SQLite 的持久化任务队列（仅标准库） |
| 队列服务 | `wt_task_server.py` | 对外暴露鉴权后的 HTTP 队列端点，并拉起 worker 子进程 |

| 令牌 | Token | 队列服务鉴权凭据（**禁止入库**） |

## 8. 平台与工程

| 规范名 | 别名 / 英文 | 含义 |
|---|---|---|
| UIA | UI Automation | Windows 现代无障碍/自动化 API，pywinauto 的 `uia` 后端 |
| MSAA | Microsoft Active Accessibility | UIA 之前的旧无障碍接口 |
| RawView / ControlView / ContentView | — | UIA 树的三种视图；本项目采集用 **RawView**（最全） |
| TreeWalker / RawViewWalker | — | UIA 树的遍历器；本项目以 **BFS + RawViewWalker** 替代 `wrapper.children()` |
| Axe.Windows | Accessibility Insights 底层引擎 | 第三方采集适配器之一，注意其 Scan API 只返回**触规元素子集**，非全树 |
| UIPI | User Interface Privilege Isolation | Windows 界面特权隔离，影响跨权限进程的输入注入与窗口枚举 |
| DPI 虚拟化 | — | 高 DPI 下坐标缩放问题，由 `wt_dpi.py` 统一处理 |
| 输入注入 | — | 模拟鼠标键盘；优先级 pynput → `win32_input_hook.py`（ctypes 零依赖钩子） |
| 内网机 | — | 无外网的目标机器，使用便携 Python（如 `D:\wt_python`） |
| worktree | — | Git 工作树；本项目规定 AI 只在 `ai/session-N` 分支工作（见 `AGENTS.md`） |
