01 / 项目简介

不是单一脚本，而是完整的自动化平台

WT Automation 针对 WT 界面流程长、参数录入多、混合 WPF/Win32 窗口等痛点， 建设了一套可配置、可兜底、可回溯、可重复验证的执行体系， 并提供 AI 对话式流程构建和业务流程蓝图库。

结构化主执行

以控件信息和流程定义为核心，优先通过结构化方式执行，保证稳定性与可重复性。

AI 自然语言 → RPA

WT_AUTOMATION_Agent 模块支持自然语言描述转换为 RPA 步骤，实现对话式自动化构建。

业务流程蓝图

基于软件用户手册建立操作蓝图库，将专业文档转化为结构化、可执行的自动化流程定义。

可视化工具链

从启动器、流程编辑器到模板采集器，提供完整的可视化操作界面，降低维护门槛。

02 / 问题与挑战

为什么需要 WT Automation？

⚠️

流程长、参数多

WT 仿真软件的完整流程涉及数十个步骤，人工重复操作效率低且易出错。

⚠️

混合窗口类型

同时存在 WPF 和 Win32 两类窗口，传统自动化工具难以统一处理。

⚠️

纯 AI 方案成本高

全流程 AI 识别成本高、速度慢，重复步骤会被反复识别，性价比低。

03 / 解决方案

三层执行策略

第一层

结构化主路径

控件定位 + 流程定义，优先执行

90%+ 场景
↓
第二层

相对区域 + 模板

复杂 WPF 场景的补偿方案

~8% 场景
↓
第三层

AI 介入

仅处理当前卡住步骤，不重跑

~2% 场景
04 / 核心功能

从采集到执行的完整能力

WT Automation 提供覆盖自动化全流程的能力集，支持从控件信息采集到运行报告输出。

智能控件定位

基于 UIAutomation 和 pywinauto 的控件识别能力，支持 WPF/Win32 混合窗口检测，内置评分与缓存机制，确保定位的准确性和效率。

  • 多层级窗口筛选与评分
  • 相对区域定位补偿
  • 控件信息缓存与复用
  • 控件库资产管理

可视化流程编辑

Tkinter 驱动的流程编辑器，支持通过模板化步骤、控件搜索和相对区域配置快速编辑，无需手工修改代码。

  • Schema 驱动的字段显隐
  • 拖拽式步骤管理
  • Excel 流程导入导出
  • 实时一致性校验

结构化执行引擎

以 action schema 为核心的执行引擎，支持动作级 fallback、弹窗自动处理、运行参数动态替换等高级特性。

  • 动作级 fallback 机制
  • 窗口切换与激活管理
  • 文件对话框自动处理
  • OCR + 图像模板识别

运行报告与回溯

结构化运行结果输出，记录每步执行耗时、成功率、fallback 使用情况，便于回归测试和问题定位。

  • JSON 结构化报告
  • 执行耗时与成功率统计
  • 失败步骤快速定位
  • 调试截图与日志记录

06 / 关键模块

深入了解核心组件

每个模块都有明确的职责定位，协同工作完成端到端的自动化任务。

AI 智能

WT_AUTOMATION_Agent

自然语言 RPA 流程构建 Agent，支持对话式自动化生成。可独立运行，连接大模型 API 将自然语言描述转换为可执行 RPA 步骤。

# 快速开始 from WT_AUTOMATION_Agent import DslAgent agent = DslAgent(config) steps = agent.nl_to_sequence("点击确认按钮", context)
业务蓝图

operation_blueprints/

业务流程蓝图库，基于软件用户手册建立。已建立气象数据、微尺度模型、风机类型、风机功率曲线等场景蓝图，将文档转化为可执行流程。

# 蓝图文件结构 { "schemaVersion": "blueprint-1.0", "name": "风机类型创建", "sourceManual": "MUP_UserManual", "steps": [...] }
执行引擎

wt_flow_executor.py

负责动作的具体执行和 flow_ref 的调度管理，支持 fallback 机制和多策略执行，是整个自动化系统的心脏。

# 动作执行示例 def execute_action(action): result = try_main_path(action) if not result.success: result = try_fallback(action) return result
控件定位

wt_flow_locator.py

提供控件定位、评分、窗口筛选和缓存能力，针对 WPF 与 Win32 混合场景设计了相对区域定位算法。

# 控件评分与定位 def locate_control(spec): candidates = find_window_candidates(spec) scored = score_and_rank(candidates) return select_best(scored)
流程编辑

WT_Flow_Editor.py

可视化流程编辑器，支持步骤模板化、控件搜索、相对区域配置，降低流程维护的技术门槛。

# 编辑器核心能力 step = editor.create_step(template) step.bind_control(control_id) step.set_action(action_type) editor.validate() # 实时校验
报告系统

wt_run_reporting.py

生成结构化运行结果，统计执行数、失败数、fallback 次数与耗时，支持 JSON 格式输出与可视化分析。

# 报告输出示例 report = { "totalSteps": 46, "failedSteps": 0, "fallbackUsed": 0, "duration": "119.597s" }
资产构建

build_control_map_library.py

控件库采集与保存工具，支持半自动采集窗口控件信息，沉淀为可复用的控件库资产。

# 控件库构建流程 window_info = capture_window(target) control_map = extract_controls(window_info) save_library(control_map, path)
模板系统

build_image_template_library.py

模板图像制作与截图工具，基于 OpenCV 和 Tesseract OCR，提供图像识别的兜底能力。

# 模板识别流程 template = load_template(image_path) location = match_template(screenshot, template) text = ocr_extract(screenshot, location)

08 / 快速开始

三步上手 WT Automation

从环境配置到实际运行，快速体验完整的自动化流程。

01

环境准备

确保 Python 3.11+ 环境可用，并安装项目依赖。

PowerShell
$ cd WT_Automation $ pip install -r requirements.txt $ pytest # 运行回归测试
02

启动平台

使用启动器进入主控制台，或直接运行可视化编辑器。AI 助手支持 Web GUI 和命令行两种模式。

PowerShell
# 传统自动化平台 $ python WT_Launcher.py # 启动器 $ python WT_Flow_Editor.py # 流程编辑器 # AI 对话式助手 $ python -m WT_AUTOMATION_Agent.gui # Web GUI $ python -m WT_AUTOMATION_Agent.cli # 命令行
03

执行流程

在编辑器中配置或导入流程，然后通过启动器执行并查看报告。

执行流程
1. 启动器选择目标流程 2. 配置运行参数 3. 点击执行 4. 查看 logs/last_run_report.json
