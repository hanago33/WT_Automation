## 1. text_tools：转换/处理线程化（★★★）

- **位置**：`text_tools.py` — `CsvConvertCard.run` 与 `_build_single_xlsx / _build_merged_multi_sheet / _build_merged_single_sheet / _build_txt`（约 L546-680）；`TextToolsCard.run` 与 `_process_one`（约 L956-1010）。
- **现状**：逐文件转换/去重/拆分/过滤全部在 **UI 线程同步**执行（仅 `update_idletasks` 推进度条）→ 大文件批量时窗口点不动；无「取消」按钮。
- **修法**：
  1. 后台线程执行逐文件循环；进度经 `self.after(0, ...)` 回主线程（进度条 + 日志）；
  2. 新增取消（`threading.Event`，逐文件边界检查；取消后弹「已取消（完成 N/M）」）；
  3. `self.log` 改为「主线程派发」（参照 round5/6 的 `_append` 模式：worker 只投递，主线程写 Text）。
- **难点（必须先设计）**：`_confirm_overwrite`（同名覆盖确认）**嵌在逐文件循环里**——后台线程不能弹窗。
  建议改为**运行前预扫描**：先枚举所有目标路径 → 收集冲突清单 → **一次性**询问「全部覆盖 / 全部跳过 / 逐个确认(取消并行)」→ 之后循环内无交互。
- **测试建议**：`_build_*` 在 worker 上的行为（用替身记录 after 投递）；预扫描冲突清单函数单测；取消路径单测（Event 置位后循环提前退出）。
- **注意**：`run()` 的收尾弹窗（round6 已按失败数三档）需原样保留。

## 2. txt_merge_tool：合并线程化（★）

- **位置**：`txt_merge_tool.py` — `TxtMergeApp.merge`（约 L346-371）；核心 `merge_txt_files`（L60-103，纯函数）。
- **现状**：合并全程 UI 线程同步、无进度、无取消；大文件/大量文件时窗口假死。
- **修法**：`merge_txt_files` 增加可选 `progress_callback(done, total)`（逐文件回调），`merge` 改为 worker 线程 + after 进度 + 取消 Event；完成后弹结果框（主线程）。
- **测试建议**：`progress_callback` 次数/顺序单测（不依赖 Tk）；取消路径单测。
- **提示**：与第 5 条（双实现合并）有协同——先做本条时注意保留与 text_tools 实现的参数差异记录。

## 3. build_image_template_library：OCR 命名线程化（★★）

- **位置**：`build_image_template_library.py` — `suggest_name_for_index`（约 L1426）、`ocr_name_current`（L1439）、`ocr_name_selected`（L1459，批量循环）；OCR 执行链 `extract_text_with_ocr`（L370）/ `run_tesseract_cli`（约 L330-368）。
- **现状**：批量 OCR 命名在 **UI 线程串行**调 `extract_text_with_ocr`（pytesseract 或 tesseract 子进程），**无 timeout** → 批量命名界面假死、不可取消。
- **修法**：
  1. 批量循环移入 worker；每框结果经 after 回主线程更新 `template_names[i]` + `refresh_listbox`（可用「进度 N/M」状态）；
  2. `run_tesseract_cli` 增加 `timeout` 参数（`subprocess.run(..., timeout=)`；超时记「OCR 超时」跳过该框）；
  3. 取消 Event（逐框边界）；`push_undo_state` 仍在主线程一次性执行（运行前）。
- **测试建议**：worker 循环替身（patch `extract_text_with_ocr` 返回固定串，断言逐框 after 投递与取消中断）；timeout 分支单测。

## 4. build_image_template_library：拖动每帧全量重建改增量（★★）

- **位置**：`build_image_template_library.py` — `on_canvas_drag`（约 L1182）：`drawing` 与 `selecting` 分支均每帧 `self.refresh_canvas()`；move/resize 分支（约 L1204+）同。
- **现状**：拖动时每帧全量重建画布（重画截图 + 所有候选框 + 选中态）→ 框多/图大时拖动卡顿。
- **修法（先读 `refresh_canvas` 复核）**：
  1. 拖动期只更新「预览图元」：为临时框/选择框/被拖框保留 canvas item id，用 `canvas.coords(item, ...)` 更新；
  2. 松手（`on_canvas_release`）后 `refresh_canvas()` 一次（现状已有）；
  3. 若 `refresh_canvas` 每次重建 item，需引入 `_preview_items` 缓存或 `self._dragging_preview = True` 分支（画布只画静态层 + 预览层）。
- **测试建议**：行为替身（FakeCanvas 记录 `coords`/`create_*` 调用次数）：拖动 N 帧不得触发全量重建（`refresh_canvas` 计数为 0）、松手后恰好 1 次。
- **风险**：画布坐标系/缩放处理需保持一致（用 `image_point_from_event` 的逆变换）。
