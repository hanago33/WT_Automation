## 1. 调度中枢 core/cv.py（291 行）

### 1.1 等待循环 loop_find（cv.py:40-82）

```python
def loop_find(query, timeout=ST.FIND_TIMEOUT, threshold=None, interval=0.5, intervalfunc=None):
    start_time = time.time()
    while True:
        screen = G.DEVICE.snapshot(...)          # 每轮截屏一次
        if screen is None:
            G.LOGGING.warning("Screen is None, may be locked")   # 锁屏告警不断言
        else:
            if threshold:
                query.threshold = threshold      # 调用方可临时覆盖阈值
            match_pos = query.match_in(screen)
            if match_pos:
                try_log_screen(screen)           # 成功也存图（证据）
                return match_pos
        if intervalfunc is not None:
            intervalfunc()                       # 每次失败后的用户钩子
        if (time.time() - start_time) > timeout:
            try_log_screen(screen)               # 失败也存图（现场）
            raise TargetNotFoundError(...)
        else:
            time.sleep(interval)                 # 默认 0.5s
```

五个语义要点：

1. **成功与失败都落证据**：`try_log_screen`（cv.py:86-112）把当前截图按毫秒时间戳存为 JPEG（质量 `ST.SNAPSHOT_QUALITY=10`，可 `ST.IMAGE_MAXSIZE` 限幅），失败现场永远有图为证。
2. **intervalfunc 钩子**：每轮失败后回调用户函数——这是"等待期间做别的事"的标准抽象（刷新界面、点掉弹窗、喂心跳）。
3. **类型化异常**：只抛 `TargetNotFoundError`，调用方可精确捕获，不必解析错误文本。
4. **锁屏容忍**：截到 None 只警告不崩溃，继续下一轮。
5. **threshold 可临时覆盖**：同名模板在不同步骤可以有不同严格度。

【WT 启示】WT 的 `locate_template_center_by_path`（wt_projection_helpers.py:261-303）把"等待"内嵌在定位函数里：deadline 轮询 + 写死 `time.sleep(0.4)`、无失败钩子、超时抛泛型 `RuntimeError(f"模板未匹配到...")`。对照改造点：抽 `wait_template(timeout, interval, intervalfunc)` + 类型化 `TemplateNotFoundError` + 失败自动截图进 run report。

### 1.3 降级链 CVSTRATEGY（cv.py:24-36, 167-199）

```python
CVSTRATEGY = ["mstpl", "tpl", "sift", "brisk"]        # settings.py:15
# cv2.__version__ 介于 (3.4.2, 4.4.0) 时自动剔除 sift（专利期），退为 ["mstpl","tpl","brisk"]

def _cv_match(self, screen):
    ori_image = self._imread()                        # 彩色原图（np.fromfile+imdecode，中文路径安全）
    image = self._resize_image(ori_image, screen, ST.RESIZE_METHOD)  # 按录制分辨率预缩放
    for method in ST.CVSTRATEGY:
        func = MATCHING_METHODS.get(method)           # 名称→类 注册表（cv.py:24-36）
        if func is None: raise InvalidMatchingMethodError(...)   # 配错名字：硬错误立即抛
        if method in ["mstpl", "gmstpl"]:
            ret = self._try_match(func, ori_image, screen, threshold=..., rgb=..., record_pos=..., resolution=..., scale_max=..., scale_step=...)
        else:
            ret = self._try_match(func, image, screen, threshold=..., rgb=...)
        if ret: break                                 # 首个成功即胜
    return ret

@staticmethod
def _try_match(func, *args, **kwargs):                # cv.py:187-199
    try:
        ret = func(*args, **kwargs).find_best_result()
    except aircv.NoModuleError:                       # 缺 opencv-contrib → 警告并降级
        return None
    except aircv.BaseError:                           # 算法内部错误 → 静默降级
        return None
```

注册表 `MATCHING_METHODS` 共 10 种：`tpl / mstpl / gmstpl / kaze / brisk / akaze / orb / sift / surf / brief`。三类分层：

| 层 | 算法 | 依赖 | 擅长 | 代价 |
|---|---|---|---|---|
| 模板匹配 | tpl | opencv 基础 | 固定 DPI、精确外观 | 尺度敏感 |
| 多尺度模板 | **mstpl（默认首选）** | opencv 基础 | DPI/缩放漂移 | 预测良好时最快 |
| 特征点 | kaze/brisk/akaze/orb（contrib: sift/surf/brief） | 基础/contrib | 旋转、部分遮挡、大形变 | BFMatcher 慢，放链尾 |

**错误处理三分法**（值得抄的纪律）：配置错误（方法名打错）→ 立即抛 `InvalidMatchingMethodError` 硬失败；环境缺失（contrib 没装）→ warning 降级；算法运行失败（找不到点、矩阵奇异）→ debug 降级。**链的容错不能掩盖配置错误。**

【WT 启示】WT 没有降级链概念：`pyautogui.locateCenterOnScreen`（pyscreeze，单尺度）失败 → 自研 `_match_template_multiscale`（固定 7 档）。Airtest 的 `mstpl→tpl→特征点` 链与 WT 的 fallbackChain（控件→图像→AI）是同构思想，图像域内部再嵌一层小链即可，两者可共用同一调度器骨架。

### 1.4 预缩放与分辨率适配（cv.py:229-250 + utils/resolution.py:11-20）

`_resize_image`：若模板记录了录制时 `resolution` 且与当前屏幕不一致，用 `ST.RESIZE_METHOD`（默认 `cocos_min_strategy`）把**模板图**缩放成当前屏幕等效尺寸再匹配：

```python
def cocos_min_strategy(w, h, sch_resolution, src_resolution, design_resolution=(960, 640)):
    scale_sch = min(sch_w/960, sch_h/640)      # 模板来源分辨率对设计分辨率的缩放比
    scale_src = min(src_w/960, src_h/640)      # 当前屏幕对设计分辨率的缩放比
    scale = scale_src / scale_sch
    return int(w*scale), int(h*scale)
```

要点：min 取宽高较保守者；设计分辨率是可调参数（游戏行业遗产）。注意这只做**一次粗缩放**，精确尺度仍由 mstpl 在预测范围内微调——"粗预缩放 + 细多尺度"两级组合。

## 2. mstpl：多尺度模板匹配全解（multiscale_template_matching.py，228 行）

默认首选算法 `MultiScaleTemplateMatchingPre`（Pre = 基于预设条件预测）。五个技巧按执行顺序：

### 2.1 技巧一：搜索区裁剪（:162-173, 213-227）

```python
def _get_area_scope(self, src, templ, record_pos, resolution):
    x, y = self.get_predict_point(record_pos, (W, H))          # 预测中心点
    predict_x_radius = max(int(tw * W / w), self.DEVIATION)    # 半径 ≥ 模板当前应有宽度，且 ≥150px
    predict_y_radius = max(int(th * H / h), self.DEVIATION)
    area = (max(x-radius,0), max(y-radius,0), min(x+radius,W), min(y+radius,H))
    return area, (缩放后的 resolution)                          # 同步修正记录分辨率
```

流程：`record_pos` 预测中心 → 以 `max(模板当前应有尺寸, DEVIATION=150px)` 为半径裁屏 → **只在裁剪区域内做全部尺度搜索** → 结果坐标加回 `area[0]/area[1]` 偏移（:180-181）。
效果：1920×1080 全屏 ≈ 2.07M 像素，预测区按 500×300 计 ≈ 0.15M 像素，**每档 matchTemplate 面积缩小约 93%**（matchTemplate 复杂度与搜索图面积线性相关）。

### 2.2 技巧二：比例范围预测（:193-203）

```python
def _get_ratio_scope(self, src, templ, resolution):
    rmin = min(H/h, W/w)      # 当前屏 / 录制分辨率 的宽高比下限
    rmax = max(H/h, W/w)      # 上限
    ratio = max(th/H, tw/W)   # 模板相对录屏的大小
    return max(r_min, scale_step), min(r_max, 0.99)   # 缩放比搜索范围 [r_min, r_max]
```

缩放比不再自由扫描，而是被"录制分辨率→当前分辨率"的几何关系约束在小区间内，步进 `scale_step=0.005`。DPI 漂移 25% 时搜索区间也只有 ±25% 附近的几十个小步，而 WT 的 7 档是 0.7~1.35 全域盲扫且粒度粗（0.15 步进会跳过 1.075 这类中间值）。

### 2.3 技巧三：性能护栏（:97-111, 120-131）

- 源图长边压到 `src_max=800`（`sr` 比例），匹配在压缩图上做，结果坐标除回 `sr`（:114-118）；
- 模板最短边 <10px 跳过该比例（防 matchTemplate 退化）；
- 搜索前给灰度图塞锚定像素 `src[0,0]=0; src[0,1]=255`（:131-132，与置信度计算同款技巧，见 3.1）。

【WT 启示】WT 现状（wt_projection_helpers.py:336-353）：每轮轮询 7 档全部 matchTemplate 取全局 `best_score`，再 `>= confidence` 判定。两个缺陷：① 慢——正确尺度命中后仍继续扫完剩余 6 档；② **错误接受风险**——某错误尺度在噪声下的 max_val 可能高于正确尺度的分数，"全局最优"反而选错位置。Airtest 的"达阈值即复验早退"同时解决两者。

## 3. cal_confidence.py（50 行全文精读）

```python
def cal_ccoeff_confidence(im_source, im_search):
    im_source = cv2.copyMakeBorder(im_source, 10,10,10,10, cv2.BORDER_REPLICATE)  # ① 外扩 10px
    im_source[0,0] = 0; im_source[0,1] = 255                                      # ② 锚定归一化动态范围
    im_source, im_search = img_mat_rgb_2_gray(...), img_mat_rgb_2_gray(...)
    res = cv2.matchTemplate(im_source, im_search, cv2.TM_CCOEFF_NORMED)
    return cv2.minMaxLoc(res)[1]                   # max_val

def cal_rgb_confidence(img_src_rgb, img_sch_rgb):
    img_src_rgb = np.clip(img_src_rgb, 10, 245)    # ③ 抑制极值
    img_sch_rgb = np.clip(img_sch_rgb, 10, 245)
    img_src_rgb = cv2.cvtColor(img_src_rgb, cv2.COLOR_BGR2HSV)   # ④ HSV 强化颜色差异
    img_sch_rgb = cv2.cvtColor(img_sch_rgb, cv2.COLOR_BGR2HSV)
    img_src_rgb = cv2.copyMakeBorder(img_src_rgb, 10,10,10,10, cv2.BORDER_REPLICATE)  # ①
    img_src_rgb[0,0] = 0; img_src_rgb[0,1] = 255                                  # ②
    src_bgr, sch_bgr = cv2.split(img_src_rgb), cv2.split(img_sch_rgb)
    bgr_confidence = [每通道 matchTemplate 的 max_val ...]
    return min(bgr_confidence)                     # ⑤ 三通道取最小，一票否决
```

**逐条动机**：

- ① `BORDER_REPLICATE` 外扩 10px：给 matchTemplate 留出完整滑窗空间，边缘目标的相似度不因边界截断而失真。
- ② **锚定像素**（最精妙的一处）：`TM_CCOEFF_NORMED` 是相关系数，会先减均值再归一化——两张几乎全同的图若只有微小差异，归一化会把这点差异放大到接近 ±1。人为塞入 0 和 255 两个极端值后，归一化的动态范围被"锚定"在全区间，微差不再被放大。**这是 WT 灰度单段置信度误报偏高的一个已知根因，且修复只需 2 行。**
- ③ clip 到 [10,245]：抗单像素极值（反锯齿、压缩噪声）对 HSV 色相计算的扰动。
- ④ 转 HSV：把亮度与色度解耦，颜色差异（比如红色按钮 vs 灰色按钮同布局）在 H 通道上被直接放大。
- ⑤ 取 min：三通道分别相似才整体相似——B 通道 0.99、G 0.98、R 0.62 → 0.62，判定不通过。**一票否决制**。

适用性注记：WT 的目标软件（Meteodyn WT）存在大量同布局不同数据的表格/图元窗口，正是"灰度分高、颜色不同"误报的高发场景（参见 docs/05-调试案例/debug/debug-add-data-false-hit.md 类案例）——两段式置信度对 WT 是准确率级别的修复，不是锦上添花。

### 5.2 基类流程（keypoint_base.py:47-86）

```
detectAndCompute(模板) + detectAndCompute(截图)
→ BFMatcher.knnMatch(k=2)
→ Lowe 比例初筛：m.distance < FILTER_RATIO(0.59) × n.distance     (:150)
→ 按源图坐标去重（允许多对一，不允许一对多）                        (:153-160)
→ 分支：
   0/1 对 → None（无法构区域）
   2 对   → 两点法：算 x/y 两轴缩放比，反推中心与矩形              (:233-266)
   3 对   → 取两点+第三点与第二点的中点，同两点法
   ≥4 对  → findHomography(RANSAC, 5.0) → 剔离群 → 再求一次单应 →
            perspectiveTransform 把模板四角映射到截图坐标           (:185-231)
→ _target_error_check：目标区 <5px，或宽高与模板差 >5 倍/<0.2 倍 → 识别无效 (:282-291)
→ 裁目标区缩放回模板尺寸 → cal_rgb/ccoeff_confidence
→ 置信度修正 (1+c)/2                                              (:113-115)
```

三个细节：

- **置信度修正 (1+c)/2**：特征点路径算的是"形变后区域 vs 模板"的相关系数，取值范围经验上偏 [-1,1]，线性映射到 [0,1] 后才能与模板匹配路径的阈值体系共用。
- **合理性校验前置**：形变矩形 <5px 或 5 倍形变直接判无效——特征点匹配最典型的失败模式（误配出小大极端矩形）被显式拦截。
- **双重单应**：第一次 RANSAC 剔离群点，第二次用内点重估矩阵，提升四角精度。

【WT 启示】特征点链对 WT 是**第四优先级**：WT 目标是固定桌面软件、模板可重截、形变以 DPI 缩放为主（mstpl 已覆盖）；BRISK 兜底只在"控件被部分遮挡/主题色大改"时才有增益。但 `findHomography+合理性校验`的工程纪律值得整体移植（若引入，作为 CVSTRATEGY 链尾）。

## 6. 辅助机制

### 6.1 TargetPos 九宫格（utils/transform.py，42 行）

### 6.2 aircv.py 公共 API（126 行）

- `crop_image`（:78-98）：rect 四值全部钳制到图像边界后才切片——防御性裁剪，WT 的 region 处理可对照加固。
- `mark_point`/`mask_image`（:101-121）：调试可视化（画十字/涂白区域）——WT 调试截图可加同款叠加标注，排障效率更高。

### 6.3 耗时内省（utils.py:15-26）

`@print_run_time` 把每次算法耗时写进结果 dict 的 `"time"` 键——匹配结果自带性能数据，run report 可直接统计"每种算法平均耗时/超预算次数"。
