# WT_Automation 项目讲解讲稿

## 第1页 项目背景与目标
- 这是一个围绕 WT 的桌面自动化项目，目标是把原本操作链路长、人工干预多的软件流程逐步自动化。
- 项目的核心不是单纯追求 AI 全自动，而是追求稳定、可复用、可维护的执行体系。
- 所以当前方案已经从“全流程 AI”转向“录制脚本 + 模板兜底 + AI 介入”的融合路线。
- 这一页重点强调两个亮点：第一，项目目标清晰，不是只做一个 demo；第二，已经具备持续迭代的工程化基础。

## 第2页 技术路线演进
- 第一阶段尝试过让 AI 直接执行全流程，但问题是速度慢、成本高，遇到重复步骤还容易反复识别。
- 现在的思路是先让脚本执行稳定动作，失败后由模板识别兜底，最后再把少量复杂判断交给 AI。
- 这样既保留了 AI 的灵活性，也大幅降低了 token 消耗，并提升了整体执行效率。
- 一个关键优化点是：必须明确告诉 AI 当前已经执行到哪一步，让它续跑，而不是从头重做。
- 这一页的亮点是“AI 续跑”思想，它直接解决了投影配置这类场景中的重复执行问题。

## 第3页 总体架构与执行链路
- 顶层由 Robot Framework 做总调度，下面由 Python 主流程承接具体业务动作。
- Python 层内部同时整合了 pywinauto、录制脚本、模板识别和 UI-TARS 桌面智能体。
- 当前主流程已经覆盖启动 WT、配置投影、打开 DWG、导入后投影确认、图层处理、覆盖区、格网和导出等关键节点。
- 配合日志、调试截图、模型配置和模板库，项目已经形成可持续调试的闭环。
- 这一页要突出的是：项目不是单点脚本，而是已经形成“调度、执行、兜底、配置、日志、编辑”的闭环架构。

## 第4页 界面与使用讲解
- 日常使用的入口是 GM_Launcher 总控台，可以直接运行流程、修改模型配置、打开工具和打包日志。
- 当脚本定位不稳定时，可以进入模板制作器补采模板，例如投影按钮和图层展开图标。
- 当需要维护流程步骤或控件信息时，则进入 GM_Flow_Editor，在图形界面中编辑步骤、控件和 Inspect 相关信息。
- 现在流程编辑器还支持半自动采集和交互点击采集，为后续维护控件库打下基础。
- 这一页的亮点是：项目已经具备可视化入口，不再完全依赖开发者手改代码。

## 第5页 当前现状与下一步
- 当前项目的路线已经稳定，关键链路也已经有实际验证结果。
- 下一阶段重点是三件事：第一，继续提升细小控件和复杂菜单的命中率；第二，把流程编辑器真正接到执行层；第三，继续补全后半段业务链路。
- 最终目标是把这个项目沉淀成一个可复用的桌面自动化解决方案，而不是只服务于单一案例。
- 这一页要把“已经做到什么”和“接下来做什么”讲清楚，让听众知道项目既有成果，也有明确路线图。
