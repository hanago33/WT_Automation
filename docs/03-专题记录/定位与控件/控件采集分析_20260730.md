- **Text + Button 占 ~60%**，符合业务表单/地图界面特征。
- **Image 高达 253 个**，且大量 `name` 是 **SVG 路径字符串**（如 `M19,13L13,13…`），实为工具栏图标按钮，被识别为 Image 且无 name/automationId → 定位脆弱。
- ScrollBar 164、纯 Text 标签极多，多为非交互噪音，是文件体积主因。

### 2.2 同名控件（同 name + 同 controlType）

- **142 个**"同名+同类型"控件在 ≥3 个大文件里重复出现。
- 典型重复：
  - `载入`(Text) ×49、`0`(Text) ×28
  - `MTD…Layer`(ListItem) ×24、`(`/`)`(Text) ×24
  - `Toggle TileState`(Button) ×24、一批 SVG 图标按钮(Button) ×24
  - `没有可供显示的元素`(Text) ×21、`ShowProductInfo`(Button) ×15、`admin (admin)`(Button) ×9
  - `街道`/`标签`/`X (m)`/`Y (m)` 等坐标标签
- 含义：这些是地图/风机/计算页面的固定业务组件，每次全量重抓 → **应抽成通用控件库/模板**。

### 2.3 匿名与空名（定位难点）

- 合计 **空 name 841（38.0%）**，**匿名（无 automationId 且无 name）296 个**。
- 匿名集中在：`Custom`（地图主视图 `MUPMapMainView` 等）、`Image`（图标）、`Text`（标签）。
- 这类控件只能靠 `class_name + 层级 + found_index` 定位 → 同级顺序一变即失效。

- 所有控件的 `IsOffscreen / IsEnabled / IsKeyboardFocusable` 在采集快照里**均为正常**（离屏 0 / 禁用 0 / 不可键焦 0）——即采集时都在屏且可用。

## 三、后续采集改进的 8 条结论

1. **修异常档**：`20260724` 只抓到 1 个水印窗（`WaterMarkUI`，isEnabled=False），真实业务窗口没进去。建议采集端加"最小控件数校验 / 重试"，避免只抓到水印窗的废档。

2. **把可自动化体检落进产物**：已实现的 `assess_control_automatability` 结果只进了 `notes`，`flatControls` / `controlDefinitions` 里**没有 `automatabilityRisk` 字段**，下游编辑器和回放看不到。建议像 `qualityTier` 一样写进 flat control，并在回放 fallback 时使用它。

3. **治理匿名 / 空名（296 / 38%）**：对 `name` 为 SVG 路径的 Image 标记为"图标按钮"，改用相邻 label 或 `class_name + 层级` 定位；`Custom` 地图视图回放用 `uiPath` 而非 name。

4. **降低 found_index 依赖（约 20%）**：对 ListItem / 同类按钮改用 content/value 或相对锚点；24 个 SVG 图标按钮引入"语义标签"或坐标容差。

5. **同名控件归一成模板**：142 个跨文件同名控件抽成可复用 control-map 片段，减少每次全量重抓与冗余。

6. **更早剪枝非交互噪音**：38% 空名 Text（`没有可供显示的元素`×21、`元素数量：`×12）与 ScrollBar 是体积主因（单文件 10~22MB）。建议采集端提高质量阈值（只保留"推荐保留 + 容器控件"）或分窗口存储。

7. **兼容 schema 演进**：07-30 文件比 07-24 多了 `legacy*`、`pathHash`、`childCount`、`isTransparentContainer` 等字段，需确认下游消费者（编辑器 / 转换 / 回放）已兼容，避免读取报错。

8. **保留并扩展下拉 / 弹窗捕获**：`dropdownExpandDiagnostics` 是有效能力，建议进一步覆盖 popup / ContextMenu 的展开选项捕获。
