## 1. Excel/Word 域：三驱动抽象（本卷最重要发现）

### 1.1 驱动抽象结构（目录与签名实测）

```
xbot\excel\
├── __init__.py          # create/open/get_active_workbook/kill_excel_process
├── workbook\  baseworkbook.py(5.9KB) | openpyxlworkbook.py | wpsaddonworkbook.py(4.2KB) | win\(com)\ | mac\
├── worksheet\ baseworksheet.py(14KB) | openpyxlworksheet.py | wpsaddonworksheet.py | win\(com)\ | mac\
└── workrange\ baseworkrange.py | openpyxlworkrange.py | wpsaddonworkrange.py | win\(com)\ | mac\
```

同一套业务 API（workbook/worksheet/workrange 三层对象模型）挂三个驱动：

| 驱动 | 实现 | 特性 |
|---|---|---|
| `openpyxl` | 纯 Python 库 | **无头**（不启动 Excel 进程）、快、保格式有限 |
| `office` | COM（win\com\worksheet.py 里 `ComWorkSheet`） | 可见交互、格式保真、支持宏 |
| `wps` | WPS 加载项（`xbot._core.wps_addon.wpsclient`，**自研 WPS Addon**） | 国产环境兼容 |
| `auto_check` | 回退链 | office → wps → 都没有抛 ValueError |

关键语义：`visible` 参数"**用于控制自动化操作是否用户可见，并不限制自动化的能力**"——同一份流程既能无人值守无头跑，也能"开着 Excel 给用户看"地跑。指令层 `launch` 的 `driver_way: openpyxl|office|wps|auto_check` 由用户按场景选。

配套的工程细节：
- `kill_excel_process(close_process: office|wps, kill_task)` —— **一键清理残留的 Excel/WPS 进程**（COM 自动化的经典事故现场）；
- `set_displayAlert(wdAlertsNone)` —— Word 域抑制弹窗（弹窗交由宏默认处理，流程不中断）；
- WPS 支持走**自研加载项**（wps_addon 客户端类型 WpsClientType），不是勉强 COM——国产办公环境一等公民。

### 1.2 业务级数据语义（xbot_visual\excel.py 实测）

写侧：
- `write_data_to_workbook` 的 **`write_as_text_cols: 'C,F'`** + 内部函数 `_number_add_green_triangle`——**指定列按文本写入并处理 Excel 的"数字存文本"绿色警告三角**。风电/工程数据里"塔筒编号 01、坐标 3307.206"被 Excel 吃成数字是真实痛点，影刃把它做成指令参数；
- `save_way: save|saveas` + `is_close_after_save`、`close_way: notsave|save|saveas`——保存语义完备。

读侧：
- `using_text: True/False` + `text_cols: 'C,F'`（按文本读取指定列，防精度丢失）；
- `clear_space: True/False`（读时清理前导空白，内部 `_clear_space`）；
- `has_header_row`（表头行语义）。

循环侧：
- **循环 API 1.0→2.0 演进**：`loop_data_from_workbook`（2020-03 前版本）→ `loop_data_from_workbook_with_return_item_location`——新版循环**额外返回当前位置**（循环行→当前行号，循环列→当前列名，循环区域→当前行号）。旧指令保留兼容，新能力加新指令——向后兼容的 API 演进范例。

其他：`execute_macro`、`select_range(absolute_range|relative_to_activecell)`（后者标注"将来用于扩展"——**在文档里诚实地写未实现**，桩代码即文档的好处）。

## 2. databook：流程内的内存数据表

`xbot\app\databook.py`（引擎托管，经 robot RPC 操作）+ 16 条可视化指令：

```
get_row(row_num)->List[str]        # 1 起始
set_row(row_num, values, begin_column_name='A')
append_row / insert_row(row_num, values)
remove_row([0,1,2,3])              # 行号列表批量删
get_cell(row_num, col_name) / set_cell
get_column(col_name, begin_row_num=1) / set_column / append_column / insert_column
remove_column([0,1,2])             # 列号列表批量删
```

一个**轻量 DataFrame**：行列号 1 起始 + 字母列名（Excel 心智），行列级批量操作，供流程中转数据（写 Excel 之前先在 databook 里清洗/循环）。配合 `programing.databook.foreach / loop_data_from_workbook(11 参)` 和对话框域的 `show_workbook_dialog`（**把数据表直接展示给用户编辑**）。

**WT 对标**：多塔批量参数、投影结果表目前散落在 flow JSON 的列表/字典里；一个同款"运行时数据表"抽象（+编辑器可視化查看）能把"数据准备→逐塔执行→结果回收"三段串成一条数据流。

## 3. 人机协同三件套（与 WT 的"人工确认对话框"直接对标）

### 3.1 声明式自定义对话框（`app\dialog.py` show_custom_dialog，15KB 全录）

```json
{
  "dialogTitle": null, "height": 0, "width": 0,
  "use_wait_timeout": false, "timeout": 20,      // ★ 超时机制：0 不等待 / >0 等待 / -1 一直
  "autoCloseButton": "确认",                      // ★ 超时自动点击哪个按钮
  "canRememberContent": true, "storage_key": "...", // ★ 记住内容：配合 storage 持久化上次输入
  "settings": {
    "buttons": [ {"type":"Button","label":"","theme":"white|red","hotkey":"Escape|Return"} ],
    "editors": [ {"type":"TextBox|Number|Password|TextArea|CheckBox|Select|MultiSelect|...",
                  "label":"", "VariableName":"", "value":null, "nullText":"", ...} ]
  }
}
```

三个杀手细节：
1. **`use_wait_timeout + autoCloseButton`**：无人值守时弹出的确认框超时自动点默认按钮，**流程永不因对话框卡死**（WT 目前"项目计算参数人工确认对话框"是手搭 Tk 双 Tab，若人不在场会一直等）；
2. **`canRememberContent + storage_key`**：输入内容持久化、下次预填（勾选"记住内容"）——把"记住上次输入"从每个对话框自己写变成引擎能力；
3. **按钮热键**（Escape/Return）与红色危险按钮主题——确认类交互的细节完整。

### 3.2 workqueue：条目级事务队列（`xbot_visual\workqueue.py`）

```
WorkQueueItem: uuid / name / priority / expireTime / bizInfo / status / createTime / updateTime / description
enqueue → dequeue → update_item(status, description) → 失败时 reenqueue(新的生效时间/过期时间/描述)
```

与 WT 的 `wt_task_queue`（任务级，8 状态机）差异：workqueue 是**业务条目级**——一批 50 个塔位是 50 个 item，单个失败 `reenqueue`（还带生效时间，实现"冷却后重试"），其余照常。priority 决定消费顺序，bizInfo 挂业务上下文。

### 3.3 进度回报（`app\progress.py`）

`set_message(message)` / `set_progress(value, message='')`——流程主动向控制台 UI 报告百分比进度（而非只有日志流）。

## 4. 触发器体系全貌（卷六 §1.3 的补全）

```
TriggerServer(WebsocketServer)     # 引擎内嵌 WS 服务，_find_available_port() 动态选端口
TriggerManager                     # 全局单例
  register_trigger(trigger_id, web_page, handle_method,
                   close_button, element_selector, process, package)
  enqueue_trigger_event(trigger_id) / try_execute_web_trigger(bid)
  get_server_port() / is_running() / clear()
trigger_executor                   # 事件→流程 的执行器
```

七个注册参数把两类触发合一：**网页元素触发**（web_page+element_selector：网页上出现某元素→执行流程）与**弹窗守护**（handle_method+close_button：发现指定弹窗→点关闭按钮或执行流程）。设计器侧弹窗守护话术："发现%close_button%按钮时，关闭弹框"。

## 5. 错误文案与多语言体系（strings.py，54KB）

`xbot\strings.py` 是 gettext 结构的错误文案目录：

```python
lang = os.getenv("XBOT_CULTURE")            # 环境变量切语言
es = gettext.translation('strings', localedir=..., languages=[lang]); es.install()

##OCR_NLP
#影刀识别引擎仅支持公有云，请更换识别引擎        ← 中文注释即源语文案
OCR_NLP_Error_Captcha = _("WebService_Error_Captcha")   # 常量名=英文键

##通用
Common_Error_Timeout = _("Common_Error_Timeout")            # 操作超时
Common_Error_Connect_Robot = _("Common_Error_Connect_Robot")# 无法连接到Robot
Common_Error_Robot_Execute = _("Common_Error_Robot_Execute")# Robot执行命令失败, {0}, {1}
Common_Error_Connect_UIA / Common_Error_UIA_Send
Common_Error_UIA_Read_Response / Common_Error_UIA_Execute   # ← RPC 失败按 连接/发送/读取/执行 四段细分

##validation
Validation_Error_Is_None / Is_Empty / Type / Is_Number /
Validation_Error_Greather_Than / Less_Than / Range / FileName / In   # ← 参数校验九词表

##utility
Error_Begin_Row_OutOf_Range = ...  # 起始行超出总行数: 有效起始行={0}, 总行数={1}
```

三个可抄的设计：
1. **错误码常量名即英文键**，中文文案放在注释里——`grep` 常量名就能定位全部用点；
2. **RPC 失败四段式分类**（连接→发送→读取→执行，Robot 与 UIA 各一套）——排查引擎故障时日志可直接归因到段；
3. **参数校验词汇表**（不能为 None/空/类型错/必须大于/必须在区间/合法文件名/枚举…）——所有指令的参数校验报错措辞统一。

## 6. 发布与更新机制

`installer\shadowbot-v6.2.23-x64-public-fps.txt`（1.4MB）实测格式：

```
..\hostfxr.dll|d3d734f613d6480a84f111478a13015e
..\dotnet.win-x64\shared\Microsoft.AspNetCore.App\6.0.36\....dll|a11c4...
```

**逐文件 `相对路径|MD5` 清单**——安装器/更新器按 hash 比对做增量同步（配 `ShadowBot.Installer.dll` 48.7MB）。应用包另有 `package.sigstore` 签名（卷一 §3）。`users\…\development_apps` 表的 `isSynchronized / releaseTimestamp` 管应用版本同步状态。

**WT 对标**：`make_release.py / deploy_release.py` 目前整包分发；内网带宽/磁盘都紧，同款"路径|MD5 清单 + 增量落盘"可直接加到 deploy_release（配合现有 `.flow_versions.json` 版本台账即成完整发布体系）。

## 7. 其余办公与数据访问域（盘点级）

| 域 | 关键 API | 备注 |
|---|---|---|
| PDF | extract_text / extract_images / extract_pages / merge_pdfs / save_pages_to_images，全部带 `from_page, to_page, password, name_prefix` | 页区间+密码+命名前缀是固定三件套 |
| 数据库 | `ado.Database(engine_kind='ODBC').open(conn_str) / exec(sql, timeout=20, result_toString=True) / exec_many(sql, data) / close` | **result_toString**：查询结果统一转字符串——RPA 场景数据一致性的务实选择 |
| FTP/SFTP | `connect(server_ip, user_name, server_kind='FTP'|'SFTP', login_kind='usePassword'|'usePrivateKey', is_active, timeout=10)` | 双协议一入口；FTP 主动/被动模式参数 |
| Word | create/open/get_active_app(kind=office|wps|auto_check) + document/selection 子模块 | 与 Excel 同款三驱动；set_displayAlert 抑制弹窗 |
| 邮件/SSH | MailKit/MimeKit/Renci.SshNet/FluentFTP 底座（企业指令） | 未深挖（WT 内网场景弱相关） |
| Web | CEF/Chrome/Chromium/Firefox/IE 各一个 Automation 类挂在 WebAutomation 门面后 | 同款"多驱动一接口"模式再现 |

**跨域一致的设计语言**（本轮最大观感）：Excel、Word、Web、数据库、FTP 全部是"**一个门面函数 + kind/driver_way 参数 + auto_check 回退链 + Base 抽象类**"。用户学一次参数风格全产品通用。
