# 卷四 · 治理运行时与结果分类学

> 依据：`runtime/replayer.py`（结构）、`runtime/resolver.py`、`runtime/heal.py`、`runtime/effects/`、`repair/`、`runtime/report.py`、`docs/RESOLUTION_LADDER.md`、`docs/REPAIR_LIFECYCLE.md`、`docs/design/EFFECT_VERIFIER.md`。

## 1. 分辨阶梯（Resolution Ladder）——WT 统一目标抽象的成熟参照

每个编译步携带五类证据，回放时**按阶梯降级尝试**（docs/RESOLUTION_LADDER.md §1）：

```
结构元素匹配（后端拥有 DOM/UIA 树时）
  → 局部模板匹配（记录位置附近，search_pad 加窗）
    → 全局模板匹配（全帧 + 唯一性门）
      → OCR
        → 几何地标（多地标交叉验证：_landmarks_contradict / _estimates_conflict，resolver.py）
          → （可选，显式启用）grounding 模型
```

实测（同文档 §2）：桌面漂移基准上**结构阶梯解析 21/21 个目标，纯视觉回放仅 6/21**。健康路径在第一级命中、毫秒级、零模型成本。"Vision-first, not vision-limited"——像素-only 面（RDP/Citrix）才有视觉地板。

**治理约束**：①身份门只覆盖**已武装（armed）**步骤，bundle 实测只武装了部分点击（live OpenEMR 12 步武装 4-7）——**未武装点击没有任何身份检查**，这一点写进每份报告（§6）；②标记 irreversible 的步骤**不允许在低置信匹配下动作**。

## 2. 多实例消歧门（vision/match.py:68-242）——WT 可直接移植的算法

问题定义（:71-89，原文精义）：像素面上"每行一个编辑铅笔、每列一个空表单"的重复控件，`TM_CCOEFF_NORMED` 给每个实例都打 ~1.0，raw arg-max **点谁看运气**；而当真目标被压缩/光标遮挡/亚像素抖动降质时，**更干净的相似物反而得分更高、被静默点击**——"wrong-row/wrong-icon 是最危险的失败，因为未武装步骤下游没有任何机制能抓住它"。

四重门（全部 keyed on `prefer_near`，即编译期记录的锚点原点——后置条件匹配不带此参数、行为不变）：

| 门 | 逻辑 | 效果 |
|---|---|---|
| **局部性**（:199-203） | 枚举 NMS 峰（模板窗抑制、上限 16），取**离预期位置最近**的过阈值峰 | 退化/被遮挡的真目标胜过别处更干净的相似物 |
| **唯一性**（:204-206） | ≥2 峰过阈值且无一在预期半径内（`max(48px, min(模板宽,高))`） | 返回 None → 阶梯下落/停机，**不猜** |
| **邻位拒绝**（:207-220） | 局部窗（记录位加 pad）内无峰近预期、单峰在别处 → 是相邻重复控件（目标自己的格没渲染好） | 拒绝，交全局唯一性门裁决 |
| **降级同类怀疑**（:221-234） | 全局仅一峰过阈值但远离预期，且**第二响应 ≥0.7**（`AMBIGUITY_SUSPICION_SCORE`，低于干净相似物 0.75-0.95、高于背景 0.1-0.5） | 认定存在重复控件、孤峰不唯一 → 拒绝；真"唯一且移动了"的目标无第二响应、保留 |

配套：默认尺度梯 `(0.85, 1.0, 1.18)`、阈值 0.82；`find_structural_template` 用 Canny(50,150) 边缘图做**主题反转不变**的布局后置条件（平坦边缘裁剪 <16 边缘像素直接拒绝——归一化相关在无结构图上退化）；`pixels_changed(before, after, region)`（阈值 20/最少 4 像素）判"键击是否落在了可见处"——专抓**焦点被偷后键入落空**（typed-input 验证）。

【WT 启示】WT 图像内核（卷六 B 骨架）当前只有"全局最优/早退"逻辑，无任何消歧门；WT 的 `InterestAreas 控件按节点消歧修复记录`（docs/03-专题记录）证明这个失败类真实发生过。**局部性+唯一性两门约 60 行、可直接并入 `wt_image_matching.multiscale_locate`**（`region_hint` 天然充当 `prefer_near`）；这正是"多实例匹配"从 P2 升级为"阶段 B 增补项"的依据。

## 3. 自愈（heal.py）与修复治理（REPAIR_LIFECYCLE.md）

### 3.1 运行内自愈

非 template 阶梯命中成功时发 `HealEvent`（heal.py:150-239）：**新模板裁剪**（命中处取景，clamp 到帧内）+ 新 click_point + **重 OCR 标签**（同行碎片左右拼接成完整标签，:65-101）+ **上下文身份带重建**（从同一帧重derive 邻近文本行——"愈合的锚点住进了新位置，旧的邻居描述不再成立"；日期判别基准改为愈合当天，:104-147）。产物落 `run_dir/heals/<step>/`（裁剪+全帧+heal.json），可折叠成完整 healed bundle。隐私纪律：已有无 PHI 模板证据时**不往锚点里加活体明文**（:211-214）。

### 3.2 修复生命周期：自愈产物不是"改完即生效"

8 态状态机（docs/REPAIR_LIFECYCLE.md §The state machine）：

```
candidate → reviewed（人工看 diff）→ replay_passed（健康漂移电池：shift/scale/retheme/reflow 全过）
  → fault_passed（对抗电池：歧义/错实体/过期目标/意外弹窗/验证器失效——每例必须被拒绝）
    → approved（人工批准，绑定前后 bundle 精确哈希）→ staged（双 bundle 哈希复核落库）
      → canary（原子指针切换，默认前 5 次运行）→ active
任意态 → rejected / rolled_back；未画出的迁移一律非法（RepairLifecycleError）
```

四条硬规则：

1. **合同不变量**（`repair/invariants.py`）：diff 前后 bundle 的安全合同，**硬拒绝任何弱化**——丢失锚点证据层级、删身份策略、降仲裁配额、丢步骤效果、`irreversible→reversible`、删步骤、资格环境变更……唯一出路是走显式的重新资格认证修订链（`qualification.revision` 严格递增 + `previous_revision_sha256` 链接）；注册时查一次、批准时对盘上 bundle 再查一次；
2. **模型永不自晋升**：每个状态迁移断言操作者不是模型（`assert_not_model_actor`），review/approve 必须人类；模型建议只能产生 `model_suggestion` 来源的 candidate，走同一条人类门（有测试覆盖）；
3. **canary 双触发器自动回滚**：`silent-incorrect`（COMPLETED_UNVERIFIED / RECONCILIATION_REQUIRED 事务结果，或步骤观察到冲突业务效果）或 `verification regression`（任何非 VERIFIED 结果）→ **立即**回退指针；未知结果按回归算（fail-safe 蒸馏，:146-152 附近）；
4. **注册失败 fail-closed by absence**：没有 candidate 记录的提案 bundle 根本进不了生命周期。

【WT 启示】WT 的"自动更新模板"开关（`image_template_index.images_are_similar` 门控直接覆盖旧模板）与 OpenAdapt 方向**相反**：WT 是"看起来没变就自动换"，OpenAdapt 是"自动换出来的东西只是候选，要过对抗电池+人工批准+金丝雀"。WT 不需要全套 8 态，但**两件事值得立刻采纳**：①自动更新产物落"候选目录+diff 记录"而非直接覆盖（保留回滚能力）；②对抗用例（歧义/错实体/过期目标）纳入回归。详见卷五。

## 4. 效果验证与补偿

- **三值裁决**：`CONFIRMED / REFUTED（台账明确矛盾：缺失/重复/错值/附带损失）/ INDETERMINATE（台账不可达：传输错、非 2xx、token 过期、正文不可解析）`；后两者 `should_halt`——"过期 token 永不误判为记录不存在"（EFFECT_VERIFIER.md §The Protocol）；
- **故障矩阵实证**（同文档 THE PROOF 节，CI 驱动真实持久层）：屏幕验证对 5/7 类事务故障静默放行（重复提交/乐观 UI 后拒/部分保存/并发覆盖/双击多记录全显示"已保存"横幅），效果验证全部 REFUTED；反向案例"写后超时"屏幕验证误判失败会引发重复写，效果验证 CONFIRMED 阻止之；
- **补偿语义**（runtime/effects/compensation.py，文档 §Compensation）：重复→`RestCompensator` 删多余记录（保最早）→**重验证** CONFIRMED 才放行（`RECONCILED`）；缺失/部分/附带损失/INDETERMINATE → 一律 **ESCALATE**（对人的持久停机）；"补偿绝不发明的覆盖状态"；
- **显式降级通道**：无验证器的后果步骤默认 HALT；认证运行可 `--approve-unverified-writes`（运行绑定的授权，报告记 `effect_approved_unverified`，永不记 confirmed）。

## 5. ProcessContract v1（编排层的取舍智慧）

`docs/design/PROCESS_CONTRACT_V1.md` 值得读的不是功能，是**拒绝项**："一个通用工作流平台会在证明需要之前就加上画布、调度器和服务边界——我们选择把工作放进一个父级，以避免两笔更贵的成本：重复的暂停/恢复规则，和分散在 Flow 与新编排器之间的审计记录。" 执行状态是**事件哈希链**（每子任务完成追加一个带 receipt digest 的事件；恢复前验证全链+过程摘要——"确定性恢复，无需 Temporal"）。只有全部子任务 verified 且零模型使用才产出签名 `VERIFIED` 父 receipt；`RECONCILIATION_REQUIRED` 永不降级为 `HALTED_BEFORE_EFFECT`——"那会断言运行时并不具备的知识"。

## 6. REPORT.md 解剖（runtime/report.py）——WT run report 的对标物

| 报告区块 | 内容 | WT 对照 |
|---|---|---|
| 头部 | 图标化 outcome（✅VERIFIED / ⚠️COMPLETED_UNVERIFIED / ❌）+ **model_calls / est_model_cost_usd** / **external_network_calls** / **screenshot egress 透明度**（接了 grounding 组件→"截图可能离开本机"警告） | WT 报告无成本与出网字段 |
| 身份保护覆盖率 | "**N of M click steps identity-armed**；未武装点击无身份验证"（含未武装步骤清单+理由）——**覆盖盲区写在每份报告里** | WT 无对应概念（fallback 使用率最接近） |
| 效果验证覆盖 | "N/M 执行步携带台账效果契约——confirmed/halted/approved-unvided" | WT 无 |
| 每步表 | 步骤/意图/**Rung/Confidence**/验证门三连（id ✓✗⚠ + input ✓✗(retried) + effect ✓✗⚠approved）/耗时/ healed/OK | WT 有耗时与 fallback；缺 rung/门 |
| 每步证据 | **每步** before/after 帧并排 + 治理行（Rung · Gates · Heal · Outcome）+ heal 详情（旧锚点→新锚点+愈合帧） | WT 仅失败截图 |
| 诚实性纪律 | "只链接保留的产物、永不合成像素"（:424-438）；帧未保留显示 `_frame not retained_`；图片链接防路径穿越/软链（:92-118）；自由文本全量 PHI 脱敏 + 明文告警（:46-69） | WT 调试截图路径有基础，纪律待对齐 |
| 台账 | rung 直方图（█ 柱状）/ model_calls / est cost | — |

`StepResult` 的门字段（:149-178）：`identity.status ∈ {verified, mismatch, abstain, unreadable}`——**abstain（弃权）与 unreadable（不可读）都显式标记**，"步骤仅凭位置证据推进，绝不静默"。
