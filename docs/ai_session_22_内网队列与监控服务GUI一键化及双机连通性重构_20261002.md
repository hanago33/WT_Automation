## 1. 背景与用户痛点复盘

在将自动化项目部署至两台电脑进行“本地客户端 vs 远程服务器”双机联调测试时，用户反馈了以下阻碍体验的突出问题：

1. **连接失败静默且无反馈**：
   用户在客户端电脑输入服务器地址后，由于缺少协议头或仅改了任务服务地址（未改监控服务地址），导致界面一片空白，状态栏仅有简短报错，用户误以为界面卡死或无响应；
2. **缺乏历史地址记忆与本机信息展示**：
   每次重新打开程序都需要手动输入完整 IP 和端口，且不知道当前作为服务器的电脑本身的局域网 IP 是多少，需要切出命令行敲 `ipconfig` 查询；
3. **本地与服务器界面角色缺乏辨识度**：
   两台电脑打开的监控界面几乎一模一样，操作人员极易混淆哪台是“正在对外提供服务的服务器”，哪台是“发送远程指令的客户端”；
4. **强依赖 CMD 命令行搭建环境**：
   每次启动双机服务，都需要手动打开 CMD 输入 `python wt_queue_selfcheck.py --server --force`，或者找到批处理文件 `check_queue_link.bat`，不仅繁琐，而且容易产生端口被外部进程占用的“孤儿进程”问题；
5. **服务停止存在盲区**：
   总控台既有的停止服务逻辑仅能感知当前 Python 实例启动的子进程。若服务是通过外部 bat 或命令行拉起的，界面点击“停止服务”会提示“未由本控制台启动”，导致无法释放端口。

本次重构的目标是：**彻底告别 CMD 命令行，将服务启停、端口清理、连通性探测、历史地址下拉记忆、本机 IP 显式复制、三态角色高辨识度横幅全量收编入 GUI，实现开箱即用的双机协同**。

## 3. 核心功能实现细节

### 3.1 历史地址下拉记忆与智能推导（告别手动输入与空白无反馈）

- **`ttk.Combobox` 替换普通 `Entry`**：
  将任务服务地址输入框改为带历史记录的下拉框，支持键盘即时输入与下拉选择。
- **历史记录去抖持久化**：
  在 `WT_Launcher.py` 的 `launcher_state.json` 中新增 `historyServerUrls` 字段，去重保存最近 12 条使用过的地址；结合 400ms 去抖算法，避免逐键写入导致的磁盘 I/O 抖动。
- **协议智能补齐**：
  用户若直接输入 `192.168.0.102:8768`，系统在刷新与应用时自动规范化补齐为 `http://192.168.0.102:8768`，防止 `urllib` 解析报错。
- **监控地址智能联动（`_derive_monitor_url`）**：
  用户选择或更改任务队列地址时，系统自动解析 Host 并将端口从 8768 转换为 8767，自动填入并同步监控地址，**用户不再需要手动配置两个端口**。
- **展开式显式警示条（`_show_diag_banner`）**：
  当网络超时、端口不通或 401 鉴权失败时，顶部动态展开醒目的深红背景警示条，详细显示错误原因，并提供 `[🔍 点击一键排查原因]` 入口；服务恢复后自动无痕收起。

### 3.2 本机局域网 IP 自动侦测与高辨识度角色视觉系统

彻底解决“本地与服务器界面无法辨别”的问题，横幅重构为三种工业级高对比度视觉模式：

| 模式 | 背景主色调 | 适用场景 | 界面元素与快捷操作 |
| :--- | :--- | :--- | :--- |
| **🖥️【本机服务器模式】** | **翡翠墨绿** (`#064e3b`) | 当前电脑作为服务器，且 8768/8767 端口正在对外监听 | 显式显示本机内网物理 IP（自动识别 `192.168.x.x`）与服务令牌；右上角提供 **`[📋 复制本机服务地址]`** 按钮，点击一键复制，直接发给客户端电脑。 |
| **🌐【远程协作客户端模式】** | **科技深蓝** (`#1e3a8a`) | 本机作为客户端，连接远端服务器 IP（如 `192.168.0.102`） | 标题与横幅明确标注连接目标 IP，右上角提供 **`[🩺 网络诊断与排查]`** 按钮，一键诊断双机连通性。 |
| **💻【本地单机模式】** | **深板岩灰** (`#1e293b`) | 连接本机 127.0.0.1，但服务尚未对外启动 | 提示处于单机模式，右上角提供 **`[🚀 一键启动内网服务]`** 按钮，点击即可就地对外提供服务。 |

### 3.3 内网服务全生命周期与自检集成（彻底告别 CMD）

将原命令行工具完全封装为跨平台的 Python 编程接口，并在总控台与监控窗口双向透出：

1. **`🚀 一键启动内网服务(队列+监控)`**：
   - 内部调用 `wt_queue_selfcheck.start_lan_services(token, force=True, timeout=15)`；
   - 自动执行 `--force` 级清理，杀停可能占用 8768 / 8767 的残留进程；
   - 启动 `wt_task_server.py` 与 `wt_server_monitor.py` 并轮询健康接口；
   - 启动就绪后弹窗提示，并**自动将本机对外服务地址复制到剪贴板**。
2. **`⏹️ 一键停止内网服务`**：
   - 调用 `wt_queue_selfcheck.stop_lan_services()`；
   - 基于 `netstat -ano` 和 `taskkill /F /PID` 按端口清理，**即使服务是由外部 CMD 窗口、旧批处理或崩溃残留引起的孤儿进程，也能一键释放端口**。
3. **`🩺 内网服务与连通性自检`（`open_network_diag_dialog`）**：
   - 在 GUI 内弹出独立暗色终端诊断窗，提供异步无假死的 4 步检测：
     - **步骤 1**：本机物理网络环境探测（提取局域网主 IP 与全部 IPv4）；
     - **步骤 2**：目标主机 TCP 8768 端口可达性与网络往返延时（Ping ms）；
     - **步骤 3**：任务队列服务健康状态与 Bearer Token 鉴权验证（排查 HTTP 401）；
     - **步骤 4**：监控管理服务（8767）健康状态检查。
   - 给出通俗易懂的排查处置指引，并支持 `[使用此地址并立即连接]` 和 `[复制诊断日志]`。

## 4. 排查与踩坑记录（Bug Fix & Lessons Learned）

在本次重构开发与测试过程中，经历了两次极具价值的排查与修复：

### 踩坑 1：模块级函数放置位置导致类定义过早截断
- **现象**：运行全量测试时，在测试收集阶段报 `AttributeError: type object 'TaskQueueWindow' has no attribute '_detect_log_shift'`。
- **根因分析**：
  在提取 `open_network_diag_dialog` 顶层函数时，误将其放置在 `TaskQueueWindow` 类方法的中间（第 519 行，且顶格写 `def open_network_diag_dialog...`）。Python 解析器在遇到顶格函数定义时，认为 `TaskQueueWindow` 类定义已经结束，导致类后续声明的所有方法（包括 `_detect_log_shift`）未挂载到类上。
- **修复措施**：
  将 `open_network_diag_dialog` 移动到 `class TaskQueueWindow:` 声明之前（作为公共模块级函数），类内部保留方法 `def open_network_diag_dialog(self, default_target=None):` 代理调用。

### 踩坑 2：`_resolve_role` 返回值解包不兼容已有测试契约
- **现象**：运行 `tests/test_remote_flow_parity.py:RoleBannerTests.test_role_matrix_and_banner` 时报 `ValueError: too many values to unpack (expected 2, got 3)`。
- **根因分析**：
  原有测试对 `_resolve_role()` 的断言严格要求解包为 2 元组 `role, _ = window._resolve_role()`，且断言 `role` 为 `"server"` / `"client"` / `"unknown"`；而重构初版将其改成了 3 元组 `(role, host, desc)` 且将 role 改成了 `server_active`。
- **修复措施**：
  恢复 `_resolve_role` 返回 `(role, desc)` 2 元组的签名契约；将服务的监听状态检测逻辑内置在 `_refresh_role_banner` 与 `desc` 文本生成中；窗口标题同时保留 `【服务器本机】`/`【远程客户端】` 标识与现代化的富文本标签（如 `任务与服务器监控 【服务器本机】[🖥️ 本机服务器模式 - IP: 192.168.0.101]`），完美兼顾 100% 测试兼容与界面高辨识度需求。

## 6. 双机实测操作指引（运维操作手册）

### 场景 A：作为执行机（服务器电脑）
1. 打开总控台：运行 `WT_Launcher.py`；
2. 在「⚙️ 工具箱」的「检查与日志」分区，点击 **`🚀 一键启动内网服务(队列+监控)`**；
3. 弹出服务启动就绪提示，弹窗中明确显示对外 IP（如 `http://192.168.0.102:8768`），且**已自动复制到剪贴板**；
4. 点击 **`📊 任务与服务器监控`**，顶部横幅显示醒目的**翡翠墨绿**：`🖥️【本机服务器模式】对外服务中`。

### 场景 B：作为调度机（客户端电脑）
1. 打开总控台，点击 **`📊 任务与服务器监控`**；
2. 在「任务服务」地址栏中粘贴或选择服务器地址（如 `http://192.168.0.102:8768`），按回车；
3. 监控服务地址自动联动更新为 `8767`，顶部横幅切换为**科技深蓝**：`🌐【远程协作客户端模式】已连接远程服务器`；
4. 若连接异常，顶部自动浮现警告栏，点击 **`[🩺 网络诊断与排查]`** 即可一键定位是 IP 错误、防火墙阻断还是令牌不一致。
