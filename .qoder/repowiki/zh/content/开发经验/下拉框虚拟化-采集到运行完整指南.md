# PART_DropDownButton 下拉框：从采集到运行完整指南

> 适用场景：MTD (Meteodyn Universe) WPF PART_DropDownButton 下拉框的控件采集、入库、流程生成与运行时交互。

## 涉及文件

| 层 | 文件 | 职责 |
|---|------|------|
| 采集 | `build_control_map_library.py` | 点扫掠采集虚拟化选项、found_index 消歧、折叠值文本 |
| 入库 | `tools/merge_standard_control_library.py` | normalize → merge → build_catalog 保留 inspectData |
| 生成 | `tools/generate_flow_package.py` | build_control_from_catalog 合并真实 inspectData |
| 定位 | `wt_flow_locator.py` | select_dropdown_item_runtime 三层架构 + 键盘导航兜底 |
| 执行 | `wt_flow_executor.py` | 传递 target_option=text |
| 封装 | `WT_AUT_recorded.py` | 透传 target_option（易漏！） |
| 测试 | `tests/test_control_map_label_association.py` | RealizeOptionsByPointSweepTests |

## 1. 采集阶段

### 1.1 WPF 虚拟化特性
- MTD PART_DropDownButton 使用 WPF UI 虚拟化
- 下拉弹出后，选项 ListItem/TextBlock 节点**不立即**出现在 UIA 控件树中
- 仅在鼠标悬停或 UIA 命中测试（ElementFromPoint）时按需实体化

### 1.2 点扫掠策略（_realize_options_by_point_sweep）
- 沿下拉按钮正下方垂直扫描（step=22px, max_span=640px）
- 用 `Desktop.from_point(x, y)` 执行 UIA 命中测试，不移动物理鼠标
- 通过 `_nearest_option_ancestor` 上溯找最近下拉选项容器
- 连续 6 次未命中终止扫描

### 1.3 found_index 消歧（_disambiguate_duplicate_locators）
- 同一父容器下多 PART_DropDownButton 共享相同 locator
- 通过 siblingsIndex 顺序追加 found_index=N 区分
- 例：访问级别 → `PART_DropDownButton,Button,1`；性质 → `PART_DropDownButton,Button,2`

### 1.4 折叠值文本（_fold_dropdown_value_texts）
- 下拉框内的 TextBlock 显示当前值（如"公共"）
- name 属性随选择变化，不可用作 locator
- 修复：改为 `class_name,control_type` = `TextBlock,Text` 定位
- 同时将 name 复制到下拉框控件的 inspectData.name/value

## 2. 入库与生成阶段

### 2.1 端到端数据链：optionValues 传递路径

```
采集 → normalize_control 提取 inspectData + optionValues
     → merge 合并时高权威优先，低权威保留非空值
     → build_catalog 输出非空 inspectData + optionValues
     → build_control_from_catalog 合并真实 inspectData（不能自造空壳）
     → 运行时 select_dropdown_item_runtime 读取 optionValues
```

### 2.2 merge_standard_control_library.py 修复要点
- `normalize_control`：新增 `inspectData`/`optionValues`/`suggestedControlName`/`displayName`/`relatedLabelName`/`dropdownValueText` 字段
- `merge`：高权威来源 inspectData 优先；即使 low 权威也保留非空值不覆盖
- `build_catalog`：非空字段一并输出，不丢弃

### 2.3 generate_flow_package.py 修复要点
- `build_control_from_catalog` 之前硬编码空 inspectData，完全丢弃标准库数据
- 修复：先以空模板为基底，再逐字段合并真实 inspectData

## 3. 运行时阶段

### 3.1 三层架构

```
Layer 1: 弹窗枚举（主路径）
  └─ iter_dropdown_runtime_candidates()
     ├─ Desktop.windows() 枚举桌面所有顶层窗口
     ├─ element_info.children() 补获 WPF Popup（Desktop.windows() 默认过滤）
     └─ window.descendants() 递归遍历 UIA 子树
     
Layer 2: 键盘导航兜底（虚拟化下拉框的可靠路径）
  └─ 从 inspectData.optionValues 读取选项列表
     ├─ 精确/包含匹配找到目标索引
     ├─ {DOWN} × N 次移动到目标
     └─ {ENTER} 确认选择

Layer 3: 性能优化
  └─ 有 optionValues → 弹窗搜索预算缩至 1.5s + 内层超时退出
     无 optionValues → 保持完整超时
```

### 3.2 性能陷阱

`iter_dropdown_runtime_candidates()` 每次调用需遍历所有桌面窗口的完整 UIA 子树。多窗口环境（浏览器、IDE）下单次 2-5 秒。

**不要**在 while 循环里反复调用完整枚举——先检查 optionValues 是否可用。

### 3.3 薄封装参数漏传

`WT_AUT_recorded.py` 的 `_select_dropdown_item_runtime` 是 `wt_flow_locator.py` 的薄封装。修改底层签名时**必须同步**：
```python
# WT_AUT_recorded.py - 必须包含全部参数
def _select_dropdown_item_runtime(step_id, control_id, timeout_seconds=3,
                                  window_title_hint="", target_option=""):
    return _get_flow_locator().select_dropdown_item_runtime(
        step_id, control_id,
        timeout_seconds=timeout_seconds,
        window_title_hint=window_title_hint,
        target_option=target_option,  # ← 新增参数必须透传
    )
```

## 5. 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| `got unexpected keyword argument 'target_option'` | WT_AUT_recorded.py 封装层未透传参数 | 补充签名 + 透传 |
| step_2 耗时 >15s 才成功 | 弹窗枚举全量桌面窗口浪费在虚拟化下拉框上 | optionValues 存在时缩至 1.5s |
| 流程生成后 optionValues 丢失 | generate_flow_package.py 丢弃标准库 inspectData | 合并真实 inspectData |
| merge 入库后 optionValues 丢失 | normalize_control 未提取 + build_catalog 未输出 | 全链路保留非空字段 |
