# 卷五 · WT 对照借鉴规划

> 前四卷是"它是什么"；本卷是"WT 拿什么"。所有建议为规划稿，落地走 AGENTS.md worktree 流程；与 Airtest 对标（同目录上一套 10 卷）、影刃对标（影刃RPA深度对标_20261002）交叉引用。

## 1. 对照矩阵（12 维）

| # | 维度 | WT 现状 | OpenAdapt | 差距性质 |
|---|---|---|---|---|
| 1 | 事务正确性 | 无（队列重试是唯一防线；`image_appear`=屏读） | 效果契约+独立验证器+故障矩阵实证 | **最大差距**，但可分级补 |
| 2 | 结果分类学 | success/failed + fallback 计数 | VERIFIED/COMPLETED_UNVERIFIED/RECONCILIATION_REQUIRED/HALTED，fail-closed 判定 | 语义深度 |
| 3 | 多实例消歧 | 无（图像域）；控件域吃过 InterestAreas 消歧苦 | 局部性+唯一性+邻位+降级同类四重门 | 算法可直接移植 |
| 4 | 定位阶梯 | UIA 定位与图像兜底并列，无统一阶梯次序 | 结构→局部模板→全局模板→OCR→几何→（可选）模型，基准 21/21 vs 6/21 | 架构统一问题 |
| 5 | 自愈治理 | self-heal + 模板自动更新**直接覆盖** | heal=candidate→8 态门禁→canary→active，合同弱化硬拒绝 | 哲学相反 |
| 6 | 录制数据模型 | 步骤 JSON（控件引用+参数） | 五元组上下文（帧/窗口/浏览器态双引用）+ canonical 键 + 归并痕迹 | 审计深度 |
| 7 | 事件聚合 | 内嵌于转换主流程 | 10 步显式纯函数管线 | 可维护性 |
| 8 | 执行报告 | JSON 结构化+汇总（结构领先） | 每步前后帧+治理门+武装覆盖率+成本+出网透明度 | 展示与诚实性 |
| 9 | 编译期确定性 | Agent 生成流程依赖 LLM，无"编译"概念 | 演示→IR 零模型编译，效果挖掘 $0 | Agent 演进方向 |
| 10 | 修复安全 | 无（AI 改流程直接生效） | 模型永不自晋升 + 对抗电池 + 金丝雀自动回滚 | 随 Agent 深化将变关键 |
| 11 | 隐私边界 | 内网部署（天然屏障） | 脱敏内嵌数据模型+出网显式化+哈希审批过界 | 内网场景部分天然满足 |
| 12 | 平台广度 | Windows 深耕 | 三桌面+浏览器+RDP/Citrix | WT 无需扩展 |

## 2. 可移植机制清单（按优先级）

### T1 多实例消歧门 → `wt_image_matching`（阶段 B 增补，~60 行）★★★

OpenAdapt `vision/match.py:104-242` 的四重门，移植为 `multiscale_locate` 的可选参数 `prefer_near`（由 `region_hint` 派生的预期中心）：

1. 命中阈值后枚举 NMS 峰（模板窗抑制、cap 16）；
2. 有近峰 → 取最近峰（退化真目标胜过远处的干净相似物）；
3. 多峰无近峰 → 返回 None（唯一性拒绝，走 fallback/上报，不猜）；
4. 全局孤峰但存在第二响应 ≥0.7 → 拒绝（降级同类怀疑）。

依据：WT `InterestAreas控件按节点消歧修复记录`（docs/03-专题记录）证明同失败类已发生；Airtest 卷六 B 骨架的"全局最优/早退"逻辑在此门面前会静默点错行。**建议与阶段 B 同批实施**，pytest 用例：合成"每行一个相同图标"底图 + 降质真目标。

### T2 结果分类学 → `wt_run_reporting`（阶段 C 增补，语义级）★★★

四级 outcome 引入：`VERIFIED` / `COMPLETED_UNVERIFIED` / `RECONCILIATION_REQUIRED` / `HALTED`。最小落地形态：

- 队列事务级：写操作类步骤完成后做**后置核对**（WT 场景台账现成可用：产出文件存在性+哈希、结果 CSV 行数、DB 记录数——`wt_business_steps` 已知业务点）；核对不到 → `RECONCILIATION_REQUIRED`，**队列不自动重试**（OpenAdapt 铁律："运行时不重试一个可能已生效的效果，除非有证据"——重试双写正是 WT 最怕的）；
- 报告头增加：身份/效果**覆盖率声明**（"N/M 步骤有后置核对；其余仅屏读证据"）+ model_calls + UI-TARS 是否接线（出网透明度）；
- `COMPLETED_UNVERIFIED` 明确标注"不是生产成功"。

### T3 效果挖掘诚实四分法 → `flow_recorder_converter`（P1，思想级）★★★

录制转换器为每个写操作步骤标注效果处置：`derived`（转换器能从录制上下文确定台账核对方式，如"保存后产生了结果文件 X"）/ `readback`（只能屏读核对）/ `placeholder`（后果性但无法确定核对方式 → 显式标记，运行到该步后置核对缺位时按策略 HALT）/ `none`。**拒绝发明核对方式**——宁可诚实的 placeholder，不要 fabricated green。

### T4 定位阶梯显式化 → 统一目标抽象（P1，架构级）★★

把 WT 现有的"UIA 定位 → 图像兜底 → AI 兜底"从隐式 fallbackChain 升级为**显式阶梯**：每步记录实际命中的 rung 与置信度（OpenAdapt 的 rung histogram 证明这组数据在排障与回归对比中的价值）；结构优先原则量化验证（21/21 vs 6/21）支持"UIA 可用必用 UIA"的既有直觉。

### T5 自愈治理化 → 模板自动更新开关改造（P1，~1 天）★★

现状：`images_are_similar` 判同后**直接覆盖**模板。改为：新模板写入 `image_templates/auto_healed_candidates/<key>/`（含新旧对比 JSON：时间、差异哈希、命中帧引用），运行继续用旧模板 + 记 `heal_candidate` 事件；人工在编辑器一键批准/拒绝，批准才转正。保留回滚=保留旧模板文件。**不引入** canary/资格链（WT 单机规模不需要）。

### T6 录制上下文增强 → 转换器字段（P1，~0.5 天）★

录制转换产物增加两字段：`screenshot_ref`（动作前帧，recorder_captures 已有素材）+ `window_title_at_action`。排障价值："当时在哪个窗口、看到的什么，点的这个控件"。

### T7 repreneurs 级：效果契约+独立验证器（P2，随队列演进）

当 WT 出现真正的多机器人并发写同一台账场景时，按 EFFECT_VERIFIER 协议（`capture_pre_state` + `verify` 三值裁决）为关键业务步骤实现 1-2 个验证器（文件哈希/DB 计数）。当前单机串行队列下收益有限——**标注为触发条件驱动的未来项**。

## 3. 不建议照抄的 6 项

| # | 项 | 理由 |
|---|---|---|
| ① | ProcessContract 哈希链台账/Ed25519 准入/密封 bundle | 企业级多租户治理设施；WT 单机+小队列用不上，照抄是负资产 |
| ② | 8 态修复生命周期全套 | T5 取其"候选+人工批准"内核即可；对抗电池/金丝雀随 Agent 化程度再议 |
| ③ | PHI 脱敏基建（Presidio/spaCy） | WT 内网部署+非医疗数据；保留"出网透明度警告"思想即可 |
| ④ | IR 57 类类型系统 | WT 的 actionConfig+schema 已覆盖同等语义；全量类型化是过度工程 |
| ⑤ | 26 包 meta-package 拆分 | WT 单仓已验证（1457 测试）；拆包动机（可选依赖/独立发版）WT 暂无 |
| ⑥ | FastSAM 分割/SoM 标注 | 属 LEARN/grounding 研究路径；WT 的 UIA 深度使其不必走纯视觉路线 |

## 4. 三套调研的合并视图（终版优先级）

结合影刃对标 P0×6/P1×8 与 Airtest 对标阶段 A-D：

```
图像内核（Airtest 蓝本）
  A 参数入库 ─→ B 匹配内核（早退+细化+两段式置信度）＋ OpenAdapt T1 消歧门
  ─→ C wait_template/类型化错误/失败审计 ─→ （D 可选：BRISK/mss）

事务正确性（OpenAdapt 蓝本，本卷新增）
  T2 结果分类学进 run report（与 C 同批，报告字段共享）
  T3 效果四分法进录制转换器 ─→ T7 独立验证器（触发条件：并发写台账）

输入通道（影刃蓝本为主）
  影刃 P0-1/P0-2 ＋ Airtest 卷八协商三件套 + 扫描码通道

治理与快照（影刃 P1 + OpenAdapt 思想）
  影刃 P1 每步快照（Airtest @logwrap 方案）＋ T5 自愈治理化 ＋ T4 定位阶梯
```

**分工判断**：图像域能抄的 Airtest 已给全；OpenAdapt 的不可替代贡献在**事务正确性与治理**——这两块影刀/Airtest 都没有，是 WT 相对所有已知竞品建立差异化的方向。

## 5. 阅读完 OpenAdapt 后修正的两个早期判断

1. **成熟度**：此前（竞品调查）标"早期项目，借鉴架构而非直接依赖"——修正：flow 引擎工程成熟度高（fail-closed、故障基准、哈希链），模式可按生产级采纳；"早期"仅指其 star 数与 UI 完成度（desktop 舱）。
2. **Skyvern 缓存模式的地位**：OpenAdapt 的"演示→确定性程序→零模型回放"与 Skyvern code-caching 是同一思想的两个实现，且 OpenAdapt 版多了**事务正确性**维度——WT Agent 演进（首跑编译缓存）应以 OpenAdapt 的治理语义为蓝本，Skyvern 提供工程性价比数据（快 3-5x/省 70%）。
