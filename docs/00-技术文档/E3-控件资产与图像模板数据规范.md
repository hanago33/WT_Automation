# E3 · 控件资产与图像模板数据规范

> 本篇是 `control_maps/` 与 `image_templates/` 的**数据格式规范**。
> 读者：手工改控件库的人、写采集/合并工具的人、排"定位不到"的人。
>
> 采集与合并流程在 C3；本篇给**字段级规范**。

---

## 1. 控件库文件

### 1.1 顶层结构

实测自 `control_maps/library/library_WT微尺度模拟_WPF_controls.json`：

```jsonc
{
  "schemaVersion": …,
  "description": …,
  "targetWindow": …,          // 采集的目标窗口
  "scanMeta": …,              // 采集元信息（时间、后端、来源等）
  "controlDefinitions": [ … ],// 控件条目数组
  "lastUpdated": …
}
```

### 1.2 目录与命名

| 子目录 | 内容 | 命名 |
|---|---|---|
| `recordings/` | 录制采集产出 | `*_control_map.json` |
| `library/` | 按窗口组织的控件库 | `library_<窗口名>_<平台>_controls.json` |
| `standard/` | 标准库合并产物 | `standard_control_catalog.json` |
| `_candidates/` | 采集过程中待确认的候选 | — |
| 根目录 | 新采集落盘位置 ⚠️（P1 断点，见 C3 §6） | — |

**外部适配器产物**：`control_maps/*_uiapeek_control_map.json`、`*_axewindows_control_map.json`——格式与自有快照一致（`targetWindow` + `controlDefinitions[]`），由合并工具自动并入标准库。

## 2. 控件条目（`controlDefinitions[]`）

### 2.1 字段表（实测 15 个顶层字段 + `inspectData`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 控件 ID（如 `control_map_97`） |
| `name` | str | 显示名 |
| `role` | str | 角色 / 来源说明 |
| `enabled` | bool | 是否启用 |
| `windowTitle` | str | 目标窗口标题（`*` = 不约束） |
| `targetMethod` | str | 定位方法（逗号成对） |
| `targetValue` | str | 定位值（**段数必须与 method 一致**） |
| `templateKey` | str | 关联模板键 |
| `uiPath` | str | UI 路径（`Window_Main > A > B`） |
| `notes` | str | 备注（常含"定位评分=88"等） |
| `labelText` | str | 标签文本 |
| `relatedLabelName` | str | 关联标签名 |
| `rawInspectText` | str | **原始 Inspect 文本**（完整 UIA 属性快照） |
| `auxChecks` | list[str] | 补充校验，如 `["IsEnabled=True", "FrameworkId=WPF"]` |
| `inspectData` | dict | 结构化属性（§2.2） |
| `helpText` / `functionText` | str | 帮助文本 / 功能语义文本（流程定义侧字段，评分 +12） |

### 2.2 `inspectData` 字段清单

| 分组 | 字段 |
|---|---|
| **身份** | `name`、`automationId`、`className`、`controlType`、`localizedControlType`、`frameworkId` |
| **状态** | `isEnabled`、`isOffscreen`、`isKeyboardFocusable`、`hasKeyboardFocus` |
| **几何** | `boundingRectangle`（如 `[l=1669,t=898,r=1821,b=926]`） |
| **运行时标识** | `processId`、`runtimeId`、`nativeWindowHandle`、`providerDescription` |
| **结构** | `children`（子签名）、`ancestors`（祖先链）、`firstChild`、`lastChild`、`next`、`previous`、`foundIndex` |
| **能力** | `availablePatterns` |
| **MSAA 遗留** | `legacyName`、`legacyRole`、`legacyState`、其余 `legacy*` |
| **推荐** | `recommendedTargetMethod`、`recommendedTargetValue` |
| **其他** | `howFound` |

### 2.3 示例（节选）

```jsonc
{
  "id": "control_map_97",
  "name": "WT微尺度模拟",
  "targetMethod": "name,control_type",
  "targetValue": "WT微尺度模拟,Text",
  "windowTitle": "WT微尺度模拟",
  "uiPath": "Window_Main > MUPHomePageMainView > OpenModule > WT微尺度模拟",
  "notes": "由控件库扫描导入，定位评分=88 | 已自动收录到控件库分类：WT微尺度模拟 / WPF",
  "auxChecks": ["IsEnabled=True","IsOffscreen=True","IsKeyboardFocusable=False",
                "HasKeyboardFocus=False","FrameworkId=WPF","ClassName=TextBlock"],
  "inspectData": {
    "name": "WT微尺度模拟",
    "controlType": "Text",
    "localizedControlType": "text",
    "boundingRectangle": "[l=1669,t=898,r=1821,b=926]",
    "frameworkId": "WPF",
    "className": "TextBlock",
    "automationId": "",
    "ancestors": ["Window_Main","MUPHomePageMainView","OpenModule"],
    "children": [],
    "availablePatterns": [],
    "recommendedTargetMethod": "name,control_type",
    "recommendedTargetValue": "WT微尺度模拟,Text"
  }
}
```

## 4. 标准控件目录 `standard_control_catalog.json`

由 `tools/merge_standard_control_library.py` 生成。

| 项 | 说明 |
|---|---|
| 输入 | `load_all` 读取的采集快照（⚠️ 只 glob `recordings/` 与 `library/` 两个子目录） |
| 归一化 | `normalize_control(c, fwin, ffw, src, scan_time, panel_title)` |
| 分桶 | `_discriminator(rec)` |
| 去重键 | `dedupe_key(rec)` |
| **权威性** | `authority(rec)` → **high / medium / low** |
| 稳健性 | `_locator_robustness(method)` |
| 合并 | `_absorb_bucket(target, source)` |
| 产物 | `standard_control_catalog.json` + `standard_catalog_mismatch_report.json` + master payload（`总控件信息.json`） |
| 控件树 | `build_controls_tree(controls)` |

**mismatch report** 列出"对不上"的低权威项（如 `frameworkId=unknown`、窗口标题为空），供实时抓取校正。

## 5. 图像模板索引 `templates_index.json`

### 5.1 顶层结构

```jsonc
{
  "meta": { … },
  "categories": [ … ],
  "templates": [
    {
      "category": "Icons",
      "file_name": "WT微尺度模拟",
      "image_path": "<绝对路径>",
      "relative_image_path": "Icons\\WT微尺度模拟.png",
      "source_screenshot": "<绝对路径>",
      "region": { "x": 110, "y": 3, "w": 49, "h": 47 },
      "updatedAt": "2026-06-26T15:03:53"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `category` | 分类（对应子目录下的再分层，如 `Icons/projection/`） |
| `file_name` | 文件名（不含扩展名） |
| `image_path` | 模板绝对路径 |
| `relative_image_path` | **相对 `image_templates` 的路径**（推荐使用） |
| `source_screenshot` | 来源截图路径 |
| `region` | 从来源截图中裁出的区域 `{x, y, w, h}` |
| `updatedAt` | 更新时间 |

各子目录**各自维护一份** `templates_index.json`，由 `image_template_index._scan_index_files` 用 `os.walk` 递归读取。

### 5.2 ⚠️ 路径卫生提醒

部分历史 `templates_index.json` 的 `image_path` / `source_screenshot` **写入了本机绝对路径**。按 `AGENTS.md` 的纪律（禁止把本机绝对路径写入被跟踪的文件），新增/重生成条目应优先依赖 `relative_image_path`，避免把环境路径固化进仓库。

### 5.3 模板 key 与解析

`image_template_index` 为每条模板注册**三种 key 写法**，保证不同来源的引用都能命中：

```
<子目录>/<文件名>.png
<子目录>/<category>/<文件名>.png
<category>/<文件名>.png
```

解析顺序（`get_template_path`）：绝对路径 → `image_templates/` 前缀（相对项目根）→ 索引命中 → 相对 `image_templates` 根 → 相对项目根 → 空串。

**详见 B4 §3。**

### 5.4 自动采集路径

`auto_capture_path(window_title, control_name)` → `image_templates/auto_captured/<清洗后的窗口名>/<清洗后的控件名>.png`
（`sanitize_filename` 会清洗非法字符，中文保留。）

## 6. 字段对齐纪律（三路适配器）

| 纪律 | 说明 |
|---|---|
| **新增字段必须三路同步** | 自有采集器 / `uiapeek_client` / `axewindows_client` + `merge` 工具，否则合并时**静默丢字段** |
| 已对齐字段 | `id`、`name`、`controlType`、`localizedControlType`、`isKeyboardFocusable`、`boundingBox`、`ancestors` … |
| 历史补丁 | `localizedControlType` / `isKeyboardFocusable` / `hasKeyboardFocus` 曾是 Axe 桥接漏提的字段，已补 |
| Axe 的局限 | Scan API **只返回触发无障碍规则的元素子集**，不是全树。它的价值在补充 **Pattern**，不是替代全量采集 |

## 7. 排障速查

| 症状 | 先看这里 |
|---|---|
| 运行时"找不到控件" | `targetMethod` 与 `targetValue` 段数是否一致；`windowTitle` 是否还是占位值 |
| 命中了错误的控件 | `notes` 里的定位评分；是否需要补 `label_text` / `ui_path` 消歧（B3 §4.3） |
| 模板兜底不生效 | `templateKey` 是否为空；`image_template_index.summary()` 看索引规模；`reload()` 清缓存 |
| 新采集的库没进标准库 | **P1 断点**：采集落根目录，合并只 glob `recordings/` 与 `library/`（C3 §6） |
| 同一控件信息前后不一致 | 看 `authority` 与 `standard_catalog_mismatch_report.json` |
