## 一、共享 automationId 页签误点（fast 早退缺陷）【定位器核心修复】

### 1.1 现象
step_1 点"元素"页签，日志命中 `name='建模'`（rect 85,118），后续测风点导入全部连锁失败。

### 1.2 根因
- "建模/元素"页签头**同为 TextBlock、共享 automationId `TabItem_Header_Label`**（综合/CFD 是 Button 类型，天然互斥，所以"发送综合计算"流程从未踩坑）；
- 定位器评分有**回退候选链**：完整候选 `automation_id,control_type,name` 失败时回退到 `automation_id,control_type`（110 分 ≥100）；
- fast 阶段"**首个 ≥100 分候选立即返回**"——视觉顺序靠前的"建模"以回退分 119 早退，name 精确命中的"元素"（184 分）根本没机会参与。

### 1.3 修复范式（保留至今）
`wt_flow_locator.py` 新增 `_candidate_strict_full_match(wrapper, control_definition)`：
**targetMethod 含消歧字段（name/label_text/ui_path/class_name/found_index）时，≥100 分早退只允许发生在"完整命中全部消歧字段"的候选上**；纯 identifier 定位行为不变。
- 代码锚点：`_candidate_strict_full_match`（约 3320 行）、fast 循环早退条件（约 7354 行）。

### 1.4 教训
- **控件类型差异是天然消歧器**：Button vs Text 互斥；同类型共享 aid 才会撞车，此时必须靠 name，而 name 消歧依赖早退门。
- **评分体系有回退链**，"高分早退"必须与"定义的完整意图"对齐，否则回退分能劫持结果。

## 二、Win32 打开对话框输入框：放弃相对区域，改 automationId=1148

### 2.1 现象
"打开"对话框(#32770)中键入路径点到"打开(O)"按钮行，文本未进输入框。

### 2.2 根因
`type_text_relative` 的 relativeRegion(x=0.488, y=0.862) 是按窗口分数坐标盲点，对话框尺寸/位置变化即漂移。

### 2.3 修复范式
标准 Win32 文件对话框"文件名(N)"输入框是原生控件 **automationId=1148**：
```json
"targetMethod": "automation_id,control_type,ui_path",
"targetValue": "1148,Edit,打开 > 文件名(N): > 文件名(N):"
```
三段 ui_path 把同 aid 的 ComboBox 父层否决，Edit 唯一命中。
- 控件库来源：`20260715_214310_导入地形图5_control_map.json`（`1148_文件名(N)_Edit`）。

### 2.4 教训
**Win32 对话框优先用原生 control-id（automationId），永远不要用窗口分数坐标**。

## 四、绘图坐标框消歧：四种方案迭代史（最终 label_text + found_index）

### 4.1 场景
MBAElementSingleCreatorView 内 6 个数值框共用 automationId=`textbox`，helpText/LabeledBy 全空；全窗口同 aid 控件 100+（气象/稳定度/风资源视图）。

### 4.2 失败方案与根因（重要：勿重蹈）
| 方案 | 失败根因 |
|---|---|
| 全窗口 found_index（0,2,3,4…） | 全窗口序号随视图增删漂移，命中气象视图 |
| `name=43\,546\,603.1 m` 值绑定 | name 是**当前显示值**，换项目/重跑即失配（用户明确否决"一次性绑定"） |
| `label_text=西北角 X` 复合标签 | 界面是 `西北角`+`X` **两个独立 TextBlock**；Y 框回溯链被交互按钮阻断 |
| view_index（锚容器类名直接子序号） | 运行时 textbox 外层有 **NumericUpDown 包装**，直接父不是视图容器——控件库 controlsTree 是扫描器逻辑树，**不等于运行时 UIA 父链**，据此设计即错（该实验已整体回滚） |

### 4.3 最终范式（20:34 真机验证通过）
```json
"targetMethod": "automation_id,control_type,label_text,found_index",
"targetValue": "textbox,Edit,西北角,0"   // 东南角 / Y+序号 同理；高度、步长仅 label
```
- **label_text 紧邻兄弟硬否决**（进 targetMethod 即 -1 出局）杀掉全部跨视图候选；
- **found_index = 直接父容器内同类型兄弟序号**（实测 0-5 稳定），只区分同标签的 X/Y 两列；
- 锚点全是**静态界面文本 + 布局序号**，与框内数值/项目无关。

### 4.4 兄弟布局实测（消歧设计依据）
```
名称, [名称宿主], 西北角, X, [框0], ±, Y, [框1], ±, 东南角, X, [框2], ±, Y, [框3], ±, 高度, [框4], …, 步长, [框5]
```
回溯规则：Text 兄弟可穿透，遇到交互控件(Button)终止——框0 回溯可及 `西北角`，框1 只可及 `Y`。

## 五、定位性能：label 全树扫描与 plain 候选截断【两处提速修复，保留】

### 5.1 现象
label 方案正确但每步 15-22s；step_14(步长) 曾"卡住"分钟级。

### 5.2 根因链
1. `_find_label_rects_for_wrapper` 全量 `descendants()`（巨大 WPF 窗口 15-36s）；
2. fast 预过滤失败的候选只保留前 16（`PLAIN_FALLBACK_LIMIT=16`），目标框排在气象候选之后被截掉 → fast 空转 → 掉进 8s 整树 FindAll → 分钟级全量 descendants。

### 5.3 修复（两行级，全局受益）
- `_find_label_rects_for_wrapper`：`scope.descendants()` → `scope.descendants(control_type="Text")`（原生条件过滤，毫秒级，异常回退全量）；
- `PLAIN_FALLBACK_LIMIT`：16 → **64**；
- 步骤侧 timeoutSeconds 3 → 10（fast deadline 充足即不落慢路径）。

## 六、PART_ContentHost 名称框：Raw View 宿主的正确写法

### 6.1 现象
step 名称框定位 `PART_ContentHost count=0`，Control View 查询空。

### 6.2 根因
PART_ContentHost 是 TextBox 内部滚动宿主，**IsControlElement=False / IsContentElement=False / controlType=Pane**（录制文件 rawInspectText 有实录）。旧定义写了 `controlType:"名称"`（录制错误值）且走 Control View → 必然空。

### 6.3 修复范式
```json
"targetMethod": "automation_id,control_type,label_text",
"targetValue": "PART_ContentHost,Pane,名称",
"inspectData": { "isControlElement": "False", "isContentElement": "False", "controlType": "Pane", "className": "ScrollViewer" }
```
- isControlElement=False → `control_definition_expects_raw_view` 自动切 Raw View 链；
- 输入时 `type_text_into_wrapper` 会自动从宿主提升到内部 Edit；
- **判别口诀：录制数据里 IsControlElement/IsContentElement=False 的控件，定义里必须如实写 False，targetValue 类型段用真实 controlType**。

### 6.4 同型坑清单
step_18/25（配置名称框）、step_9（绘图名称框）三处同型，逐一修正后全部命中（score 157, Raw View）。

## 七、候选项批量选择 select_list_items（新 action）与 BFS 兄弟遍历 bug

### 7.1 界面结构（map8/9 实录）
MBAElementConfigurationView 直接子层按类别呈三元组：
```
[Category(测风点/风机/绘图, aid=ElementConfigurationView_Label_Category), ItemCount "(N)", PanelBarItem_ScrollViewer(候选容器)]
```
- 候选项 = `ElementConfigurationView_Label_Item` **纯 TextBlock**，无任何 UIA 选择模式（SelectionItem/Toggle/Invoke 全无）→ **唯一选中方式是物理点击**；
- 容器 PanelBarItem_ScrollViewer **IsControlElement=False**（Raw View），三个类别容器 aid/name 完全相同 → 只能按"Category 之后最近的 ScrollViewer"区分；
- **视图无全选控件**，多选 = 首项单击 + 后续 Ctrl+单击。

### 7.2 实现要点（wt_flow_locator.select_list_items_runtime）
1. 类别锚定位（复用 Category 定义）→ 上溯 `MBAElementConfigurationView`；
2. 直接子层中找 Category 之后的最近 `PanelBarItem_ScrollViewer`（Control View 无则 Raw View 兜底）；
3. 容器内 Raw BFS 枚举 Label_Item（按 y 排序）；
4. 名单语义：空/`ALL`=全选；逗号名单=精确匹配（全不中→显式失败）；
5. 逐项 `_scroll_flow_control_into_view` 滚动可见后点击（见 §10）。

### 7.3 踩过的坑：Raw BFS 只遍历第一棵子树
- **现象**：风机候选 JWD1/2/3 只枚举到 1 个，"全选"只选了 JWD1；
- **根因**：`walker.GetFirstChildElement(el)` 只把**第一个**直接子入栈，其兄弟从未入栈（写了 `GetNextSiblingElement` 却是 `pass` 死代码）；
- **修复**：先把容器**全部直接子**入栈（first + 依次 GetNextSiblingElement），再逐层深入；
- **教训**：单候选类别（测风点 1 个、绘图 1 个）会掩盖此类 bug，**必须用多候选项类别（风机 3 个）验证批量枚举**。

### 7.4 挂载链（新 action 的标准接入点）
- locator：`select_list_items_runtime`（约 8830 行）；
- executor：`_SELECT_LIST_ITEMS` hook + `run_action_step` 分支（text 即名单，经 `_RESOLVE_DYNAMIC_VALUE` 后传入）；
- WT_AUT_recorded：`configure_flow_executor(select_list_items=_select_list_items_runtime)` **+ 转发元组 `_FLOW_LOCATOR_FORWARDED` 加名**——两处都要，漏一处 hook 即 no-op（本次真实踩坑：漏注入导致 executor 永远失败）；
- schema：`wt_action_schema.ACTION_SCHEMAS["select_list_items"]`。

## 八、占位符未解析的兜底：默认全选

### 8.1 现象
未选项目文件夹运行时，step 日志 `wanted=["${runtime.mastIdsJoined}"]` 名单未命中失败。

### 8.2 根因
§3.3 的空值保护：runtime_config 无该键 → 解析器**保留字面量** → 字面量被当名单。（flow runtimeConfig 加默认空键**无效**——空串同样走保留分支。）

### 8.3 修复范式（用户确认的总原则）
locator 内兜底：`target_items` 仍含 `${` 前缀 → 记警告日志，**按全选处理**。
即：**未解析 = 未指定 = 默认全选该类别全部候选项并移右**；要部分选择必须给出可解析的真实名单。
