## 1. 执行器 `wt_flow_executor.py`

### 1.1 修复真实 Bug：`_LOG_STEP` 参数个数错误
`_write_feedback_to_flow` 中两处调用传了 3 个参数：
```python
_LOG_STEP(context, f"Warning: Failed to load flow definition for feedback: {e}", step_id)
```
而 `_LOG_STEP` 只接受 1 个参数（默认 `lambda message: None`）。反馈写入路径一旦出错会抛 `TypeError` 掩盖原始异常，而不是降级记录。
- 改为：`_LOG_STEP(f"... (step={step_id})")`，保留步骤上下文，单参数。

### 1.2 合并 4 个几乎相同的点击分支
`run_action_step` 中 `click` / `double_click` / `right_click` / `double_right_click` 原为约 100 行重复代码。
- 用 `click_kind_by_action` 表驱动 + 循环合并为约 25 行。
- `double_right_click` 的两次右击由 `click_count=2` 循环处理，`time.sleep(0.2)` 与错误信息（`第二次右击失败`）完全保留。

### 1.3 抽取共享坐标动作分发
fallback 链（`_execute_fallback_action`）与模板兜底（`run_action_step_with_template_fallback`）各自有一段近似的 pyautogui 动作分发。
- 抽出 `_perform_coordinate_action(action_name, center, text)`，两处共用，行为一致。

### 1.4 新增回归测试 `tests/test_wt_flow_executor.py`
新增 `FeedbackAndClickDispatchTests`（2 例）：
- `test_feedback_logging_handles_corrupt_flow_definition`：损坏 flow 定义时降级日志单参数、不崩溃；
- `test_click_family_dispatches_with_correct_kind_and_count`：点击分发 `click_kind` 与调用次数正确（click→left×1 / double_click→double×1 / right_click→right×1 / double_right_click→right×2）。
