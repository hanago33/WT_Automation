## 3. 现状盘点

### 3.1 已有能力

- 8767 只读监控：运行状态、日志 tail、最近报告。
- 8768 任务队列：Bearer 认证、FIFO 单例调度、提交/列表/详情/日志/报告/暂停/继续/终止/取消。
- SQLite 队列层：WAL、busy_timeout、进度与错误回写、任务日志落盘。
- 客户端窗口：2 秒轮询、任务列表、进度、日志、只看我的任务、查看报告、提交与控制。
- 自动化脚本队列感知：`--task-id/--task-user/--task-db`，步骤间检查暂停/终止。
- 稳定性补强：1MB 请求上限、scope/limit/tail 校验、流程 JSON 校验、服务日志、调度线程 join 与锁。
- 测试：63 个用例覆盖队列、服务、监控、CLI 契约与可观测性（Webhook/审计/保留）。

### 3.2 主要缺口（按价值排序）

1. 无任务超时与自动重试，失败只能人工 resume。
2. 无优先级与定时预约，所有任务严格 FIFO。
3. 无可视化统计（队列深度、成功率、平均时长）。
4. 无通知/告警，任务失败需要人工盯窗口。
5. 无审计日志，无法追溯谁在何时操作了哪个任务。
6. 流程不能上传、无版本管理。
7. 多机部署无节点管理与任务分配。
8. 无用户角色与令牌管理。
9. 无 Web 控制台，运维只能依赖 Tk 客户端。
10. 无流程编排（DAG/依赖/并行）。

## 4. 分阶段增强路线

### 4.1 P0：基础稳定性与可观测性（推荐先做，纯标准库可落地）

目标：让“失败可重试、排队可预约、状态可统计、变化可通知、操作可审计”。

> 落地状态（2026-08-11）：P0 全部落地，P1 第 1/2 项（Simple 远程模式、流程上传版本管理）已落地，并追加 Simple 批量提交确认对话框与本地 JSON 链路直达提交。重试/超时/预约字段、队列统计、日志保留、客户端筛选与退避、Webhook、审计均已实现；调度线程支持运行超时自动 kill、失败自动重排队与预约/重试时间判断，并由 `73 passed` 测试覆盖（含 `test_scheduler_timeout_kills_and_retries`、`test_batch_submit_collects_task_ids_and_calls_callback`、流程版本化用例与内容未变化跳过上传用例）。

1. 任务级超时与自动重试
   - 借鉴：Dramatiq 重试、Sidekiq retry queue、Temporal retry policy。
   - 改动：`tasks` 表新增 `max_attempts`、`retry_delay_seconds`、`next_retry_at`、`timeout_seconds`；调度线程检查运行超时并 kill；失败后若未达上限自动回到 `pending` 并延迟到 `next_retry_at`。
   - 验收：提交可传重试/超时参数；超时任务被自动终止并重试；超过上限标记 `failed` 且错误信息包含原因。

2. 优先级与定时预约
   - 借鉴：Sidekiq scheduled queue、APScheduler、Airflow scheduler。
   - 改动：`tasks` 表新增 `priority INTEGER DEFAULT 0`、`scheduled_at TEXT`；`claim_next_pending` 只取 `scheduled_at <= now` 的任务，按 `priority DESC, created_at ASC` 排序。
   - 验收：高优先级任务先出队；预约任务在时间到达前不执行；客户端可填优先级与预约时间。

3. 队列统计与健康端点
   - 借鉴：Flower、Sidekiq Web UI。
   - 改动：新增 `GET /api/queue/stats`，返回各状态计数、今日提交/完成、最近 24h 成功率、平均排队/运行时长；`/api/health` 增加 uptime、版本、DB 路径与运行任务数。
   - 验收：客户端新增统计栏；接口对空库也能返回全零统计。

4. 日志清理与归档
   - 借鉴：Sidekiq/Flower 清理策略、logrotate。
   - 改动：服务启动参数 `--log-retention-days`（默认 30）；启动与每日定时清理 `logs/tasks/*.log` 及过期任务记录归档。
   - 验收：配置保留 1 天时，超过 1 天的任务日志被清理；数据库任务仍可查询。

5. 客户端可用性补强
   - 借鉴：Flower 页面交互。
   - 改动：断线重连退避（1s/2s/4s/…上限 30s）；列表按状态/用户/流程关键字筛选；统计栏；报告另存为文件。
   - 验收：服务重启后客户端自动恢复轮询；筛选不改变服务端数据。

6. Webhook 通知
   - 借鉴：商业平台告警、Temporal 通知。
   - 改动：提交时可带 `notifyUrl`，或服务端启动参数 `--webhook <url>`；任务进入 `success/failed/terminated` 时回调 JSON（taskId/status/error/progress/runId/reportUrl）。
   - 验收：测试服务器可收到结束事件回调；回调失败不影响任务状态。

7. 审计日志
   - 借鉴：UiPath Orchestrator 审计、Jenkins 审计。
   - 改动：新增 `audit_events` 表（时间、用户、来源 IP、动作、任务 ID、结果、详情）；submit/pause/resume/terminate/cancel 均记录；新增 `GET /api/audit?taskId=&user=&limit=`。
   - 验收：每次控制操作都能在审计接口查到；无令牌访问返回 401。

### 4.2 P1：协同与运维

目标：从“单机可用”到“多用户、多流程、可运维”。

1. Simple 本地排队迁移到远程队列（已落地，2026-08-11）
   - 方案详见《远程任务队列服务技术文档_20260811》12.1：Simple 板块改为提交远程任务、卡片进度轮询、停止映射 terminate，保留本地离线模式作为兜底。
   - 落地内容：Simple 工具栏“远程模式”开关（`simpleModeRemote` 持久化），“运行所选板块”改为批量上传并提交远程任务、轮询进度，“停止”映射 terminate；本地模式保留为离线兜底。2026-08-11 追加：Simple 批量提交确认对话框（可调整勾选、附带本地 JSON 链路文件）、任务队列窗口“提交本地 JSON 链路”直达入口、内容未变化流程自动跳过重复上传。

2. 流程文件上传与版本管理（核心已落地，2026-08-11）
   - 借鉴：UiPath 流程包、影刀流程市场。
   - 落地内容：`POST /api/flows/upload` 校验 JSON 结构、文件名与路径穿越；同名上传自动归档旧版为 `name.vN.json` 并写入 `flow_packages/.flow_versions.json` 台账；`GET /api/flows` 返回 `versionCount/versions` 并排除归档文件；新增只读 `GET /api/flows/version?name=&version=` 读取历史版本；规范文件名与 `flowPath` 保持最新版本不变，上传后立即可提交。
   - 剩余增强：multipart/base64 批量上传与目录打包、`flow_package_registry.json` 版本描述同步、上传权限分级、客户端版本历史与回滚界面。

3. 多机 worker 节点
   - 借鉴：Celery worker、OpenRPA 机器人、UiPath 机器人池。
   - 改动：新增节点注册表（节点名、地址、令牌、能力、心跳时间）；`tasks` 表新增 `assigned_node`；调度线程按节点空闲与容量分配；worker 节点运行 `wt_worker_agent.py` 拉取任务、本地执行、回传状态与报告；心跳超时节点标记离线并重新分配任务。
   - 验收：两个模拟节点可交替领任务；节点离线后其运行中任务被标记并重新排队；报告按 `runId` 回传调度中心。

4. RBAC 用户与令牌管理
   - 借鉴：UiPath、AA Control Room、Jenkins Matrix。
   - 改动：用户表（用户名、角色 admin/operator/viewer、令牌哈希、状态）；提交/控制接口校验角色；viewer 只读；operator 只能操作自己的任务；admin 可管理用户与全量任务。
   - 验收：viewer 调用控制接口返回 403；operator 无法控制他人任务；令牌重置后旧令牌失效。

5. HTTPS 与密钥管理
   - 借鉴：商业平台默认 TLS。
   - 改动：`--cert/--key` 启动参数启用 HTTPS；令牌仅存哈希；`launcher_state.json` 中的令牌可加密存储。
   - 验收：HTTPS 模式下明文 HTTP 请求失败；数据库不出现明文令牌。

6. Web 控制台（只读先行）
   - 借鉴：Flower、Sidekiq Web UI、tasktServer。
   - 改动：基于标准库 `http.server` 增加只读页面（队列概览、任务列表、任务详情、日志、统计），随后再补控制操作。
   - 验收：浏览器可查看队列与任务，无需登录之外的额外配置；页面不暴露令牌。

### 4.3 P2：编排与规模化

目标：面向复杂流程、多团队、大批量任务。

1. DAG 流程编排
   - 借鉴：Airflow/Prefect/Temporal。
   - 改动：新增流程编排定义（节点、依赖、失败策略）；调度器按 DAG 触发下游任务；支持并行分支与合并。
   - 验收：A→B/C 并行→D 的编排可正确执行，B 失败时按策略终止或跳过。

2. 定时任务中心
   - 借鉴：APScheduler、Airflow schedule。
   - 改动：任务可配 cron 表达式或日期日历；调度线程生成下一次运行；支持错过任务补偿。
   - 验收：每分钟 cron 任务在 3 分钟窗口内产生 3 个实例；停机期间错过任务可按配置补偿。

3. 配额与 SLA
   - 借鉴：UiPath Orchestrator SLA。
   - 改动：每用户并发提交上限、队列总长度上限、任务 SLA 时限；超限返回 429；超 SLA 告警。
   - 验收：达到配额后提交被拒；SLA 过期任务触发通知并标记。

4. 统计看板
   - 借鉴：Flower 与商业平台报表。
   - 改动：按用户/流程/日期聚合成功率、平均时长、排队时长；支持导出 CSV。
   - 验收：看板数据与队列 DB 一致；导出文件可被 Excel 打开。

5. 流程市场与资产库
   - 借鉴：影刀流程市场、UiPath 资产。
   - 改动：流程模板参数化、共享/收藏/评分；资产（账号、凭据、文件）加密存储并在任务内安全注入。
   - 验收：模板可实例化提交；凭据不出现在日志与 API 响应。

6. 企业 IM/邮件集成
   - 借鉴：商业平台通知中心。
   - 改动：通知渠道插件化（邮件/钉钉/企业微信/Webhook），按用户订阅。
   - 验收：任务成功/失败按订阅发送；发送失败可重试。

## 5. 架构演进建议

### 5.1 三条可选路线

路线 A：保持 Python 标准库 + 单机 SQLite

- 适合：单台自动化主机、日均任务量不大、以稳定性与可观测性补强为主。
- 推荐执行：全部 P0 + P1（Simple 迁移、上传、权限、只读 Web 控制台）。

路线 B：引入轻量依赖（Redis + RQ 或 Celery）

- 适合：需要多进程/多机、任务量增长、希望复用成熟队列语义。
- 收益：broker/结果后端、worker 多实例、Flower 监控、重试/调度队列开箱即用。
- 成本：引入 Redis 部署与运维；需要改写队列层接口。
- 建议：先完成 P0，再评估是否切换；切换时可保留现有 HTTP API 形态，内部替换实现。

路线 C：引入完整编排平台（Airflow/Prefect/Temporal）

- 适合：复杂 DAG、长时间工作流、跨团队共享调度。
- 收益：调度、重试、心跳、持久化、Web UI 全部成熟。
- 成本：部署复杂度高，WT 自动化需要改造成平台执行器（operator/worker）。
- 建议：仅当业务确实需要多流程编排与多机规模时选择。

### 5.2 存储演进

```text
单机 SQLite（现状） ──▶ 多机 PostgreSQL/Redis（队列与元数据）
                        └──▶ 对象存储/共享目录（任务日志与报告）
```

多机场景下 SQLite 不再适用，建议优先 PostgreSQL（关系数据 + JSONB 进度）+ Redis（轻量队列/锁/心跳），或直接选路线 B/C 的成熟组件。

## 6. 推荐首批落地清单（P0 细化）

### 6.1 数据库变更草案

`tasks` 表新增字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `priority` | INTEGER DEFAULT 0 | 数值越大越先出队 |
| `scheduled_at` | TEXT DEFAULT '' | ISO 时间，空表示立即可执行 |
| `max_attempts` | INTEGER DEFAULT 1 | 最大尝试次数 |
| `retry_delay_seconds` | INTEGER DEFAULT 0 | 失败后延迟重试秒数 |
| `next_retry_at` | TEXT DEFAULT '' | 下次可出队时间 |
| `timeout_seconds` | INTEGER DEFAULT 0 | 0 表示不限制运行时长 |

新增表：

```text
audit_events (
  id, created_at, user, source_ip, action, task_id, result, detail
)
```

### 6.2 API 变更草案

```text
POST /api/tasks/submit            body 增加 priority/scheduledAt/maxAttempts/retryDelaySeconds/timeoutSeconds/notifyUrl
GET  /api/queue/stats             返回队列与成功率统计
GET  /api/audit?taskId=&user=&limit=   审计查询（P0 审计落地后）
GET  /api/health                  增加 uptime/version/queueDb/runningCount
POST /api/flows/upload            （P1 落地）
POST /api/agent/register|heartbeat（P1 多机落地）
```

### 6.3 调度线程变更点

- 取任务时：`scheduled_at <= now` + `next_retry_at <= now` + 按优先级排序。
- 每次 tick：检查运行中任务的 `timeout_seconds`，超时则 kill 并按重试策略处理。
- 任务结束：failed 且 `attempts < max_attempts` 时写 `next_retry_at` 并转 `pending`，不再要求人工 resume。
- 新增统计缓存或直接 SQL 聚合，避免每次统计全表扫描。

### 6.4 客户端变更点

- 提交对话框增加优先级、预约时间、重试次数、超时设置。
- 列表上方增加状态筛选与关键字筛选。
- 底部增加统计栏（排队/运行/成功/失败/24h 成功率）。
- 断线重连采用指数退避。
- “查看报告”增加另存为文件。

### 6.5 测试计划

- 超时自动终止与重试：模拟进程不退出，验证 kill 与重排队；验证达到上限后 failed。
- 优先级与预约：混合提交后断言出队顺序；预约任务提前不出队。
- 统计端点：构造多状态任务后断言计数与成功率。
- Webhook：本地回环测试服务器接收回调并断言负载。
- 审计：控制操作后断言审计记录；无令牌访问 401。
- 日志清理：构造过期文件，断言按保留天数清理。
- 回归：任务队列相关测试当前为 `73 passed`，新增可观测性、Simple 批量提交、流程版本化与内容未变化跳过上传用例全部通过。

## 7. 风险与约束

- 标准库限制：无 WebSocket、HTTPS 需自实现、并发模型为线程；规模过大时需要换路线 B/C。
- SQLite 单机约束：WAL 与 busy_timeout 已缓解并发，但多机场景必须换存储。
- Windows 进程管理：终止任务依赖 `taskkill /F /T` 进程树，跨平台性差。
- 安全边界：v1 共享令牌 + 用户名；HTTPS 与 RBAC 未落地前不应暴露公网。
- 向后兼容：新增字段全部带默认值；旧客户端提交不传新参数时行为不变。
- 数据保留：日志与审计增长需要清理策略，否则磁盘占用持续上升。

## 8. 需要确认的决策点

1. 是否允许引入 Redis/第三方依赖：决定走路线 A、B 还是 C。
2. 首批范围：是否从 P0 的超时重试 + 优先级/预约 + 队列统计三项开始。
3. 通知渠道：Webhook / 邮件 / 钉钉 / 企业微信，先做哪种。
4. 多机规模：预计节点数与任务量，决定何时进入 P1 多机。
5. 安全要求：是否需要 HTTPS 与 RBAC 作为上线前置条件。
6. Web 控制台：先做只读版还是直接做可操作版。
