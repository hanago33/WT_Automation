## 1. 多后端自动协商：TouchProxy / ScreenProxy 模式

### 1.1 设计目标

一台 Android 设备上，截图有 3 种实现（minicap 走 socket 视频流最快、javacap 走 instrument 兼容性好、adbcap 走 adb exec-out 最通用但慢），点击也有 3 种实现（maxtouch/minitouch 走本地 socket 注入最快、adbtouch 走 `adb shell input` 最慢但永远可用）。**哪个能用取决于设备状态，只有跑了才知道**——所以 Airtest 1.1.2 起把选择权从用户手里收走（android.py:173, 213 的 setter 直接 `warnings.warn("No need to manually specify ... airtest will automatically specify a suitable ... method")`），交给代理自动协商。

### 1.2 协商算法（touch_proxy.py:44-83）

```python
@classmethod
def auto_setup(cls, adb, default_method=None, ...):
    # ① 用户指定的默认方法优先（若在注册表中）
    if default_method and default_method in cls.TOUCH_METHODS:
        impl = 构造实例(...)
        if cls.check_touch(impl):          # 真实执行 install_and_setup()
            return TouchProxy(impl)
    # ② 否则按注册顺序逐个探测
    if not default_method:
        for name, touch_impl in cls.TOUCH_METHODS.items():
            impl = ...
            if cls.check_touch(impl):      # check_touch 捕获一切异常，失败仅告警
                return TouchProxy(impl)
    # ③ 全部失败 → 万能兜底（慢但永远可用）+ 显式警告
    adb_touch = AdbTouchImplementation(adb)
    warnings.warn("Currently using ADB touch, the efficiency may be very low.")
    return TouchProxy(adb_touch)

@classmethod
def check_touch(cls, touch_impl):                       # :33-42
    try:
        touch_impl.base_touch.install_and_setup()      # 真实安装+连接，不是假探测
    except Exception as e:
        LOGGING.error(e); LOGGING.warning("%s setup up failed!" % ...)
        return False
    else:
        return True
```

三个组件各司其职：

| 组件 | 机制 | 证据 |
|---|---|---|
| **注册表** | `@register_touch` 装饰器把实现类按 METHOD_NAME 注册进 OrderedDict（:86-88）；MaxtouchImplementation 直接继承 MinitouchImplementation 只换 METHOD_CLASS（:161-177） | 薄继承复用整套行为 |
| **探测** | `check_touch` 不是查能力表，而是**真实执行安装连接**、捕获一切异常——"能装上才算数" | :33-42 |
| **兜底** | AdbTouchImplementation 永远可用（仅依赖 adb），降级时**显式警告性能损失** | :79-83 |

ScreenProxy（screen_proxy.py，117 行）同构，协商顺序文档化为"**自定义方法 > MINICAP > JAVACAP > ADBCAP**"（:73），实现用 `reversed(cls.SCREEN_METHODS.items())` 遍历（:97——注册顺序与优先级相反，倒序扫描）。

代理本体是 `__getattr__` 透明转发（:23-31）：`dev.touch_proxy.touch(...)` 与直调具体实现无异，`method_name` 特判返回当前后端名（供日志/报告展示"本轮实际用了哪个通道"）。

### 1.3 对 WT 输入通道参数化（影刃 P0-1）的设计启示

影刃给出的通道清单（simulate/clipboard/automatic + interception 驱动级 + AutoIt 后台）+ Airtest 给出的协商机制，合并成 WT 的设计蓝本：

```
InputChannelProxy
├─ 注册表（OrderedDict，装饰器注册，顺序即优先级）
│    UIAPattern（Invoke/Value，前台后台皆可、不抢焦点）
│    ForegroundSend（SendInput 虚拟键 + 扫描码，最物理）
│    ClipboardPaste（set_clipboard + ^v，防 IME）
│    WindowMessage（PostMessage WM_KEYDOWN/UP，后台消息）
├─ auto_setup(channel=None)：None 时按序探测（探测=对目标窗口做一次无损试发）
├─ 步骤级 override：actionConfig.inputChannel="clipboard" 强制指定
└─ 兜底 + 显式警告（报告记录实际使用通道——对应 Airtest method_name）
```

关键纪律（两家共同验证）：**①探测必须真实执行一次无害操作，不做静态能力判断；②兜底通道永远存在且降级要告知；③实际通道写进执行证据**。

## 2. 录屏双线程模型（screen_recorder.py，273 行）

```
ScreenRecorder
├─ 采集线程 get_frame_loop（daemon）                :202-230
│    while True: frame = get_frame_func()           # 调用方注入的截图函数
│      失败 → 生成"[warning] get frame error"空白帧兜底（:212-219，录制不断）
│      process_frame() → frame_queue.append((time.time(), frame))   # 帧带墙钟时间戳
│      deque(maxlen=100)                             # 背压：最多缓 100 帧（10s@10fps）
│      sleep(0.5/fps)                                # 采集节奏留 2x 余量
└─ 写线程 write_frame_loop（daemon）                :232-273
     while True: 检查 ffmpeg 进程是否已死（:240-242）
       从队列取 (t, frame)
       帧率对齐：while start_time + step*duration < t: 写 last_frame   # 缺帧补帧
       （:254-260，墙钟网格重采样——采集慢于 fps 时重复上一帧，保证视频时长=真实时长）
       BrokenPipeError → 终止（ffmpeg 已死）        :248-250
```

`FfmpegVidWriter`（:45-139）：rawvideo pipe → libx264（crf=25、preset=veryfast、threads=1）；宽高向下对齐 32 的倍数（:64-65，编码器要求）；帧居中进缓存画布（三横竖屏模式）；**时间戳水印**烧进每一帧（含时区，:118-121）——事后核对执行时间线时逐帧可读。

【WT 启示】对照影刃"30s 分段环形缓冲自动清理"（影刃对标 01 卷）：Airtest 版是单文件全量录制 + maxlen=100 帧背压 + 墙钟帧率对齐 + 错误帧兜底。WT 若做 P0-5 执行录像，建议：分段环形取影刃（防磁盘膨胀），**帧率对齐与错误帧兜底取 Airtest**（:254-260 的补帧逻辑是"录制时长≠执行时长"问题的标准解法），时间戳水印照抄。

## 3. 工程兼容与遗留代码的教训

| 模式 | 实现 | 证据 | 对 WT 的意义 |
|---|---|---|---|
| **deprecated property 兼容层** | `Android.minicap = property(lambda self: self.get_deprecated_var("minicap", "screen_proxy"))`——旧属性访问转发到新代理并打 DeprecationWarning，旧调用 `dev.minicap.get_frame_from_stream()` 依然工作 | android.py:275-294, 1137-1141 | WT 改造 `locate_template_center` 内核时，对外签名保持 + 内部转发的同款手法（卷五阶段 B 兼容红线） |
| setter 直接废弃 | `cap_method.setter` 里 `warnings.warn("No need to manually specify ...")` 后仍执行赋值 | android.py:193-214 | 参数化改造期"允许旧用法但提示新用法" |
| 过程式遗留 | aircv/template.py 的 `find_template()/find_all_template()`（函数版）与 template_matching.py 的类版逻辑重复；aircv/sift.py（284 行）是 keypoint_base 出现前的旧 SIFT 实现，与新链并存 | 全文件 | 同一算法新旧两套并存是负担；WT 移植时只保留一套（类版），别学这个 |
| 双 Enum 常量文件 | constant.py 集中 CAP_METHOD/TOUCH_METHOD/IME_METHOD 字符串常量 | android.py:12 引用 | WT 输入通道名用常量集中定义，避免裸字符串散落 |
