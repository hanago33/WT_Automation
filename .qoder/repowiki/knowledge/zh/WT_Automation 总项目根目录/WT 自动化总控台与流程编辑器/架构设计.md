本模块由三个独立可执行的 Python 脚本组成，通过 JSON 文件与共享包进行松耦合协作：
- `WT_Launcher.py`：tkinter 主界面，负责加载 `flow_definition.json` 与 `flow_packages/flow_package_registry.json`，合并 runtimeConfig/flowPackages/steps，调用 `wt_flow_executor` 驱动步骤执行；内置 `RelativeRegionHelperDialog` 辅助生成相对区域 action，并通过 `subprocess` 拉起 `WT_Flow_Editor.py`、`build_image_template_library.py`、`build_control_map_library.py` 等子工具。
- `WT_Flow_Editor.py`：tkinter 可视化链路编辑器，维护 `DEFAULT_FLOW_DEFINITION`、`STEP_TEMPLATES`、`DEFAULT_STEP_CONTROLS_BY_ID`，将编辑结果同步到 `flow_package_registry.json`（`sync_flow_package_registry`），并写回 `launcher_state.json` 供 Launcher 读取默认定义路径。
- `WT_AUT_recorded.py`：无头/监视器模式执行器，通过 `_load_flow_payload` 合并目标定义与注册表，按步骤策略（script/image/ai）调用 `wt_business_steps`、`wt_projection_helpers`、`wt_window_helpers`、`wt_flow_locator`、`wt_run_reporting` 等子模块；支持 `WT_ENABLE_AI_INTERVENTION` 环境变量触发 UI-TARS 介入。
- `启动WT自动化总控台.bat`：Windows 启动引导，自动尝试以管理员权限重启自身，再依次探测 `py -3.11` / `python` / `pyw` / `pythonw` 解释器并启动 `WT_Launcher.py`。
依赖方向：Launcher ↔ Editor 仅通过 JSON 文件与 `launcher_state.json` 通信；执行器通过 `import wt_*` 调用业务层，不反向依赖 Launcher/Editor。
