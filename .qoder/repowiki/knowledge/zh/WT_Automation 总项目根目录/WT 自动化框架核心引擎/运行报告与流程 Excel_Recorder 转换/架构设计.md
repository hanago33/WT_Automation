本模块由三个职责独立的脚本组成，均通过命令行 `argparse` 暴露入口：
- `wt_run_reporting.py`：纯函数式运行期报告器，维护 `_BASE_DIR`/`_LOG_STEP` 两个全局配置，通过 `start_run_report` → 多次 `report_step_result` → `finalize_run_report` 三段式生命周期生成 `logs/run_reports/wt_run_*.json` 并同步更新 `logs/last_run_report.json`；最终状态经 `_resolve_final_status` 将含失败步骤的 `success` 降级为 `partial_success`。
- `flow_excel_io.py`：基于 openpyxl 的 Excel↔JSON 桥接层，以 `STEP_COLUMNS`/`CONTROL_COLUMNS`/`PACKAGE_COLUMNS` 三张表为核心 schema，提供 `load_flow_payload_from_excel` / `export_flow_to_excel` 双向转换，并通过 `_normalize_payload`、`_filter_payload_by_step_ids` 做字段归一化与子集过滤；内置回灌审计 `audit_flow_excel_roundtrip`，按 `ROUNDTRIP_AUDIT_FIELD_SPECS` 对比基线 payload 的关键字段差异；Excel 输出附带 `_options`（下拉校验）、`action_guide`（动作说明）和 `examples` 三张辅助 sheet，并使用不同 header 填充色区分必填/高频/JSON/可选列。
- `flow_recorder_converter.py`：AST 解析器，读取 pywinauto_recorder 生成的 Python 脚本，把 `click/send_keys/mouse_wheel/drag_and_drop/find/menu_click/set_text/set_combobox` 等调用映射为 WT action step，同时从 UIPath 段推断 a11y 元数据（automationId/className/frameworkId/ancestors），并尝试在 `control_maps/*.json` 控件库中按评分策略匹配最佳候选，未命中时自动注入 `_reviewHints` 提示人工复核。
依赖方向：三者均只依赖上层 `wt_action_schema` / `wt_action_defaults` 提供的动作枚举与默认配置，不反向被 core engine 直接 import，而是作为独立 CLI 工具或运行时辅助模块使用。
