## 2. 十七个可借鉴设计模式（附影刃证据与 WT 落点）

### 模式 1：统一目标抽象（Unified Target）
- **影刃**：UIA/ACC/CV/AI 定位结果全部实现同一 Element 接口（click/input/get_text/get_bounding/parent…），上层指令不关心目标来源；CV 元素对值操作显式抛 `Unsupport` 而不是静默错。
- **WT 现状**：控件目标（controlId）与图像模板（templateKey）是两套参数、两条执行路径，靠 fallbackChain 拼接。
- **落点**：定义 `Target` 抽象（Control/Template/Region 三实现），executor 的动作层只面向 Target。见卷四 P1-2。

### 模式 2：输入三通道参数化
- **影刃**：`input_type: simulate|clipboard|automatic` 一个参数决定注入方式；另有 hardware_driver 后门与浏览器 CDP。
- **WT 现状**：注入方式由代码路径决定（22 处 send_keys、18 处 pyautogui、4 处 click_input/type_keys），步骤配置无法选择。
- **落点**：action schema 加 `inputChannel`。见卷四 P0-1。

### 模式 3：IME 防线组合拳
- **影刃**：force_ime_ENG（强制美式键盘）→ clipboard_input（粘贴法，注释原文"avoid input method problems"）→ click_before_input+focus_timeout（焦点确定性）→ send_key_delay（防丢键）→ contains_hotkey（特殊键转义 `{}`）。
- **WT 现状**：type_text 直敲；屏幕键盘是唯一备选；中文输入法吃键问题在录屏日志中反复出现。
- **落点**：P0-2。

### 模式 4：超时三态语义（0 / -1 / N）
- **影刃**：全库统一"0=不等待，>0=等 N 秒，-1=无限等"，窗口/元素/图像/焦点等待全部一致。
- **WT 现状**：timeoutSeconds 默认 3s，散落几十处函数签名；没有"无限等"的表达方式。
- **落点**：P0-3。

### 模式 5：等待指令输出 bool 而非抛错
- **影刃**：wait 指令族的 `iswait` 开关 + `wait_result` 输出槽——"等到没有"是数据，不是异常。
- **WT 现状**：continueWhen 条件不满足时整步跳过，等待结果不进数据流。
- **落点**：P0-4（与图像等待一起做）。

### 模式 6：锚点单结构（anchor_type + sudoku + offset）
- **影刃**：`anchor_type(center|random|custom) + sudoku_part(九宫格) + offset_x/y`，点击/双击/悬停/拖拽/图像全共用；拖拽另有 release_sudoku_part。
- **WT 现状**：anchor×3 + relativeRegion×6 共九个字段，语义重叠、表单冗长。
- **落点**：P1-1（编辑器字段归并，向后兼容映射旧字段）。

### 模式 7：图像一等公民
- **影刃**：图像库(repository) + 4 条指令(wait/click/hover/exist) + 多图组 + wait_all + 限域(window_kind) + 相似度阈值参数化。
- **WT 现状**：模板匹配只在投影场景和显式 fallbackTemplate 生效；参数全局写死（confidence 0.8、scale [1.0,1.1,0.9,1.2,0.8,1.35,0.7]）；模板按 key 存放无库语义。
- **落点**：P0-4（per-template 参数入库）+ P1-3（图像条件进 continueWhen）。

### 模式 8：版本化选择器库 + 匹配操作符 + 变量注入
- **影刃**：XML repository、V1/V2、regex/wildcard 命名空间操作符、`{{全局变量}}`（支持中文变量名）、ASCII 控制符转义。
- **WT 现状**：控件库 JSON 精确匹配为主（评分匹配兜底），targetValue 不支持变量注入与模糊模式——窗口标题一变（版本更新、分辨率文案）即大面积失效。
- **落点**：P1-4。

### 模式 9：语义字段 + AI 选择器 + 自动修复闭环
- **影刃**：元素带 `semantic()` 语义描述；定位失败 → BuildAiSelector/AiSimilarSelector 语义匹配 → FixSelector 回写（且校验类型一致 `Selector_RepairElementMustBeSameType`）；失败统计含 invalid_reason 与 element_count。
- **WT 现状**：self-heal 只回写 locator；UI-TARS 兜底在流程级最后才介入，且不回写知识。
- **落点**：P1-5（semantic 字段 + 失败时语义定位 + 成功回写，串起 self-heal + control_live_detector + UI-TARS 三个既有资产）。

### 模式 10：执行审计快照
- **影刃**：每指令执行后落 `{blockInfo(processName,lineNumber), inputs[{name,value,type,isFullValue}], outputs[{value,type,displayOutputs}], isSuccess, errorMessage}` → SQLite(gzip, 后台节流)；`mask_sensitive_params` 掩码；`TruncateTools` 5 万字符裁剪保 key。
- **WT 现状**：run report 有成败与耗时，无参数值；排查"当时传了什么"只能翻日志。
- **落点**：P1-6。

### 模式 11：拟人开关（区间级）
- **影刃**：`manual_motion_on(motion_move, motion_click, motion_delay, min_time, max_time)` 一段流程整体拟人；锚点支持 random。
- **WT 现状**：无。WT 场景（内网业务软件）暂无反自动化检测，优先级低，但 random 锚点对"点击不可点区域边缘"有真实价值。
- **落点**：P2。

### 模式 12：进程隔离三件套
- **影刃**：设计器/Python 引擎/定位 Provider 三进程；UIA 查询死在 Provider 里可硬杀重启，主流程不死；本地 HTTP API(:31500) 对外服务。
- **WT 现状**：UIA 全树枚举挂起 742s 的教训已在案（`_window_is_responsive` 探针只是绕行）。
- **落点**：P2-1（定位器子进程化，配 kill+restart 策略）。

### 模式 13：可靠性常驻三件套
- **影刃**：`start_prevent_os_sleep()`（SetThreadExecutionState）+ `StuckChecker`（60s 看门狗 + 主线程栈转储）+ `socket.setdefaulttimeout(30min)`。
- **WT 现状**：无防休眠；无指令级卡死登记；网络调用无进程级兜底。
- **落点**：P0-5。

### 模式 14：分组件日志 + 录屏环形缓冲
- **影刃**：每子进程独立日志文件；录屏 30s 分段、GB 上限、自动清理。
- **WT 现状**：单日志文件（分类标签已做）；无录屏。
- **落点**：P1-7（日志文件按进程/角色拆分）；录屏 P2。

### 模式 15：弹窗守护（出现即处置）
- **影刃**：`add_monitor_record(handle_method, close_button, element_selector, process, package)`——"发现 X 关闭按钮就点掉 / 发现元素就触发流程"。
- **WT 现状**：无。MUP 的各类提示框目前靠流程内前置 wait 处理，漏一个就卡死。
- **落点**：P1-8。

### 模式 16：文档即 API 的分发闭环
- **影刃**：桩代码 docstring = IDE 提示 = 官方文档 = AI 语料；`code.activities.xml` 机器可读总目录；`xbot-sdk` SKILL.md 教 AI 路由；四份产物同源生成。
- **WT 现状**：`wt_action_schema.py` 有 label/description（19 动作），但 Agent 侧的知识库（`WT_AUTOMATION_Agent/knowledge_base`）与 schema 是两套手工维护的文本。
- **落点**：P0-6（目录生成器 + SKILL.md 挂到 skill_bridge）。

### 模式 17：包格式完整性
- **影刃**：package.json(flows/variables/external_dependencies) + sigstore 签名 + 资源文件门面(package.resources) + `.dev` 工作区与调试符号分离。
- **WT 现状**：flow_packages/flow_definition_*.json 单文件流程；无 variables 段、无依赖声明、无签名。
- **落点**：P2-2。

## 4. 不建议照抄的部分（经论证的克制）

1. **CefSharp/DevExpress/.NET 技术栈**：影刃的编辑器体验建立在 178MB CEF + 60MB DevExpress 上；WT 的 Tkinter 债在 docs/01 已有重构任务书，按自己的路线走，不为面板效果换栈。
2. **驱动级输入（interception）**：需要安装内核驱动且有对抗检测的合规风险；WT 的内网业务软件无此对抗需求。
3. **云端市场/账号/统计上报**：与内网部署环境冲突，WT 的任务队列已经够用。
4. **加密字节码（pyb）**：保护 ISV 资产的手段，WT 是自用工具，明文即是可维护性。
5. **AI 云指令（chatgpt/captcha 域）**：内网不可达，且 WT Agent 走自有模型档案体系更可控。
