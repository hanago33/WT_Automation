# Inspect.exe 对标差距调研报告
## ——"控件库维护"控件树查看 与 "悬停采集" 交互差距分析

> 调研日期：2026-07-29
> 依据：Microsoft Learn 官方 Inspect 文档（2025-07-14 更新）+ 本仓库代码逐行核查（带行号引用）

---

## 0. 一句话结论

**Inspect 是"一个窗口内实时联动的三位一体"（实时整树 + 悬停跟随 + 属性/操作面板），而当前项目把这三件事拆散在 3 个互不衔接的工具里，且每个工具都只做了其中一部分。** 最核心的交互差距不是"缺某个按钮"，而是缺 **"悬停 → 树定位 → 高亮 → 属性 → 导航"这条实时闭环**。

---

## 1. Inspect.exe 的交互模型（官方文档核实）

Inspect 的体验由 5 个机制叠加构成：

| # | 机制 | 细节 |
|---|------|------|
| 1 | **实时整树** | 对目标窗口实时枚举 UIA 树，可切 Raw View / Control View / Content View 三种树视图 |
| 2 | **Watch 模式** | Watch Cursor（鼠标悬停即选中树节点）、Watch Focus（跟随键盘焦点，约1秒刷新）、Watch Tooltips；悬停时**树、属性面板、屏幕高亮框三者同步联动** |
| 3 | **屏幕高亮** | Show Highlight Rectangle：选中/悬停元素周围实时画高亮框，跟随移动；另有 Show Information Tooltip 在鼠标旁悬浮显示属性 |
| 4 | **全局热键树导航** | Ctrl+Shift+F6 父 / F7 首子 / F9 末子 / F5 上一兄弟 / F8 下一兄弟 / F4 设焦点 / Ctrl+Shift+5 刷新 / Ctrl+Shift+4 复制全部属性——**Inspect 非活动窗口也能触发**（这就是"冻结"手段：悬停到位后用热键接管，不必再动鼠标） |
| 5 | **属性 + 操作** | 数据面板显示元素全部 UIA 属性 + 支持的 Control Patterns；Action 菜单可直接执行 Invoke/SetValue 等 Pattern，验证"这个控件真的能这样操作" |
| 辅助 | 窗口特性 | Always on Top 置顶；Active Hover Toolbar；属性可配置显示哪些 |

**Inspect 交互闭环**：鼠标滑过目标应用 → 树自动定位到该节点 → 屏幕红框跟随 → 属性面板实时刷新 → 需要细看时用 Ctrl+Shift 热键在树上走父/子/兄弟 → 满意后 Action 验证。全程不需要切窗口、不需要点"开始/停止"。

## 2. 当前项目的实际现状（代码核实）

功能散落在 3 个工具，互不衔接：

### 2.1 WT_Flow_Editor.py「控件库维护」窗口（L2755 起）
- **纯静态库浏览器**：树数据来自 `control_maps/*.json`（L2920-3068），树层级靠 `uiPath` 字符串前缀拆分构造（L3434-3493），**没有任何实时 UIA 枚举能力**。
- 有：列表/树形双视图（L2826-2828）、关键字过滤/排序/时间筛选（L3204-3244）、属性详情面板（L3665-3772）、检验定位+3秒红框（L3995-4032, L4169）、单文件模式编辑/删除。
- **"悬停采集"入口实际不存在**：全文对 `control_live_detector` 引用为 **0**；唯一按钮是 subprocess 启动整个 `build_control_map_library.py`（L3778-3786），采集完还要**手动"刷新控件库"**重读 JSON。
- 无父/子/兄弟导航（双击=导入，容器节点提示"请展开"，L3613）；无 Raw/Control/Content 视图；无自动回流。

### 2.2 control_live_detector.py「实时控件检测器」（独立工具，约1300行）
- 按钮式启停（L947-960），Space 暂停 / Enter 保存 / Esc 停止（L1026-1028），50ms 轮询 `Desktop.from_point`（L1091-1143）。
- 只显示**单个命中控件的平铺属性 + 祖先链前8层文本**（L1181-1189），**无树、无子控件**。
- **无屏幕高亮框**（全文无 overlay/outline 实现）、**窗口不置顶**（无 `-topmost`）、**无全局热键**（快捷键绑定在自己窗口上，焦点在目标应用时全部失效——这是它"没法用"的根因之一）。
- 采集结果只能"导出"为独立 JSON（L1259-1313），**不合并回控件库**。

### 2.3 build_control_map_library.py「控件库采集器」（最接近 Inspect 的一个）
- 有：整树实时枚举（RawViewWalker BFS，L1427-1495）、悬停跟踪补采（350ms tick、稳定0.7s触发、去重，L5725-5820）、层级树增量同步（L5240-5266）、红框高亮（L5462-5499，但**一次性3秒后消失**）、窗口置顶（L5743）、Esc 停止。
- 但它是**采集器**，不是浏览/维护界面；高亮不跟随鼠标；无全局热键树导航；无属性实时面板联动（悬停触发的是"补采写库"，不是"查看"）。

## 4. 根因分析：为什么"差得多"

1. **架构性割裂（最大根因）**：Inspect 的树、悬停、属性、高亮是同一窗口内同一数据源的四个视图；本项目是 3 个进程/窗口 + 2 种数据源（实时 UIA vs 静态 JSON），任何一个环节都要用户手动切换、手动刷新、手动衔接。"控件库维护"里根本没接 A，A 采完的东西也进不了库。
2. **没有全局热键 = 交互瘫痪**：悬停探测类工具的本质矛盾是"鼠标一动目标就变、鼠标去点自己窗口目标就丢"。Inspect 用**系统级热键（非活动窗口可触发）**解决；A 的 Space/Enter 绑定在 Tk 窗口上，目标应用有焦点时全部失效，等于"看得见抓不住"。
3. **高亮不跟手**：Inspect 的高亮框随悬停实时移动，用户靠它确认"探到的就是我想要的"；本项目高亮只在"检验定位/补采完成"这类**事后动作**里出现3秒，探测过程全程盲操作。
4. **树与悬停无联动**：C 有树也有悬停，但悬停触发的是"写库补采"而非"树上定位+查看"；用户想先看清楚再决定采不采——现在是先采了再说，库里全是噪声。
5. **窗口焦点/置顶处理粗糙**：A 不置顶（悬停时自己被目标窗口盖住）；C 靠 `withdraw()` 隐藏自己来避让，体验生硬。

## 5. 改造建议（按优先级，供下一步实施）

### P0 —— 补齐"实时闭环"（做到能用）
1. **在"控件库维护"内嵌一个"实时探测"面板**（或将 C 的整树枚举 + 树控件复用进来）：左树=目标窗口实时 UIA 树，右侧=属性面板，数据源从静态 JSON 扩展为"实时树 + 库内标注叠加"（已入库节点打标记）。
2. **全局热键**：用 `RegisterHotKey`（Win32）或 `keyboard` 库注册系统级热键，最小集合：
   - `Ctrl+Shift+X` 冻结/解冻当前悬停元素（对标 Inspect 的热键接管）
   - `Ctrl+Shift+F6/F7/F8/F5` 父/首子/下兄/上兄导航
   - `Ctrl+Shift+S` 采集当前元素入库
3. **实时跟随高亮**：把 C 的 `_show_locator_highlight`（L5462）改造成**持久 overlay**——不销毁、只随探测结果 `geometry()` 移动，探测停止才销毁；悬停/树选中/热键导航共用同一个框。
4. **悬停→树联动**：悬停命中后在实时树上定位展开该节点（C 已有 runtimeId 反查 L5222-5238，可直接复用），属性面板同步刷新；**默认只看不采**，按热键才入库。

### P1 —— 补齐"可维护"
5. 采集入库后自动增量刷新"控件库维护"树（复用 C 的 `_sync_hierarchy_after_supplement` 思路），去掉"手动刷新控件库"。
6. 探测面板窗口 `-topmost` + 可选半透明，去掉 `withdraw()` 隐藏式避让。
7. 树导航工具栏按钮（父/子/兄弟），容器节点也可查看属性（而非提示"请展开"）。

### P2 —— 补齐"好用"
8. 悬浮 Tooltip（鼠标旁小窗显示 name/type/aid 三要素）。
9. Raw/Control/Content 视图切换；"复制全部属性"按钮。
10. Action 面板：对选中元素动态列出支持的 Pattern 并可执行（Invoke/SetValue），替代目前只能"检验定位"。
11. 淘汰或合并 `control_live_detector.py`：其唯一独有能力（库匹配打分列表）并入新探测面板后可下线，消除三工具割裂。

### 落地路径建议
- **不新建第4个工具**。以 C（`build_control_map_library.py`）已有的整树枚举 + 增量同步 + 高亮为地基，抽出 `live_inspector` 面板组件，同时挂进"控件库维护"（B）和采集器（C），A 逐步下线。
- 第一迭代只做 P0 的 2+3+4（全局热键 + 持久高亮 + 悬停树联动），即可获得 80% 的 Inspect 体验。
