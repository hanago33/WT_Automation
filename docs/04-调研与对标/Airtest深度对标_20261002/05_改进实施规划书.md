# 卷五 · 改进实施规划书

> 状态：规划稿（未经实施）。所有"参考代码"以卷六为准，落地时**必须**按 AGENTS.md 在 worktree 分支重写、`python -m pytest tests/ -q` 全绿后提交人工审查。
> 本规划是影刃对标 P0-4（图像参数入库 + 图像等待条件）的**实现级设计**，同时吸收 P0-3/P0-5 的部分要素。

## 0. 总路线图

```
阶段 A（参数入库）──→ 阶段 B（匹配内核）──→ 阶段 C（等待与审计）──→ 阶段 D（可选增强）
    schema 扩展          wt_image_matching       wait_template/错误/审计        mss 评估/BRISK
    1 个采集器           1 个新模块              2 个模块改造                   2 个独立项
    ~0.5 天              ~1.5 天                 ~1 天                          各 ~0.5-1 天
```

依赖关系：A 是 B 的前置（参数从索引来）；B 是 C 的前置（wait_template 返回结构化结果）；D 两项独立、可随时插队。
兼容性红线：**15 个现有调用点默认行为不变**——索引里没有参数字段的旧模板走现状逻辑（0.8 阈值 + 7 档兜底保留为 fallback 路径）。

## 1. 阶段 A：模板参数入库

**目标**：模板级阈值/彩色校验/缩放参数/捕获分辨率进入 `templates_index.json`，匹配逻辑可按模板取参。

**Airtest 参照**：Template 描述符两级参数（cv.py:127-136）；ST 全局默认（settings.py:15-23）。

**改动文件**：

| 文件 | 改动 |
|---|---|
| `image_templates/*/templates_index.json` | template 记录增加**可选**字段：`threshold`(float)、`rgb`(bool)、`scale_step`(float)、`scale_max`(int)、`capture_resolution`([w,h])；既有 `region`/`source_screenshot` 保持不动 |
| `image_template_index.py` | 新增第二索引 `{key: params_dict}`；`get_template_params(key) -> dict`（无记录返回 `{}`）；`reload()` 同步清两个缓存 |
| `build_image_template_library.py` | 采集保存时写入 `capture_resolution`（当前屏宽高）与默认 `threshold`；`region` 照旧 |

**Schema 扩展示例**（完整 JSON 见卷六附录 E）：

```json
{
  "category": "projection",
  "file_name": "从文件加载",
  "image_path": "image_templates/Icons/projection/从文件加载.png",
  "region": {"x": 226, "y": 780, "w": 356, "h": 53},
  "capture_resolution": [1920, 1080],
  "threshold": 0.78,
  "rgb": true,
  "updatedAt": "..."
}
```

**验收标准**：
1. 三个既有 templates_index.json 不加新字段时，`get_template_params` 返回 `{}`，全部现有测试绿；
2. 加入字段后 `get_template_params` 正确返回；`reload()` 生效；
3. 采集器新生成的记录自动含 `capture_resolution`。

**工作量**：~0.5 天。**风险**：低（纯增量字段，读取端缺省兼容）。**回滚**：删除新字段即可。

## 2. 阶段 B：匹配内核升级（新模块 wt_image_matching.py）

**目标**：用 Airtest 五技巧替换 `_match_template_multiscale` 内核；`locate_template_center_by_path` 退化为薄壳。

**Airtest 参照**：multiscale_template_matching.py 全文 + cal_confidence.py 全文 + template_matching.py 早退语义。

**改动文件**：

| 文件 | 改动 |
|---|---|
| `wt_image_matching.py`（**新增**） | 全部匹配内核：`MatchResult` 数据类、`cal_rgb_confidence`/`cal_ccoeff_confidence`（移植）、`multiscale_locate()`（比例预测+区域裁剪+早退+两段式复验） |
| `wt_projection_helpers.py` | `_match_template_multiscale` 改为调 `wt_image_matching.multiscale_locate`；`locate_template_center_by_path` 增加可选 `params`/`rgb` 透传，返回路径内部改走结构化结果（对外签名与 Point 返回**保持不变**） |
| `wt_action_schema.py` / `wt_flow_executor.py` | （后续批次）图像类 action 暴露 `threshold`/`rgb` 字段——与影刃 P0-4 的步骤级参数化合流 |

**内核行为规范**：

1. 缩放策略：有 `capture_resolution` → 比值预测范围 `[r_min, r_max]`（卷二 2.2）+ `scale_step`（默认 0.005）；无 → 退回现有 7 档列表（兼容路径）；
2. 搜索区：索引 `region` 存在 → 换算预测区（模板当前应有尺寸与 region 半径取大，下限 150px）；调用方显式 `region` 参数优先级更高；
3. 早退：任一尺度灰度 `max_val >= threshold` → **先做局部细化**（在该 scale ±`refine_steps`（默认 8）步内补扫取最优，卷十 E3/E4 实测：纯早退置信度贴线 0.71 而细化后恢复 1.0、中心偏差 ≤1px，代价 40→92ms）→ 两段式复验，通过即返回；总预算 1s；
4. 全部尺度扫完无早退 → 取灰度全局最优做复验，通过才返回（保持"尽力而为"），失败返回 None 并携带 last_best 信息；
5. 复验：`rgb=True`（默认对可参数化的新模板）走 HSV 三通道 min；`rgb=False` 走 ccoeff+锚定；
6. 结果：`MatchResult(center, rectangle, confidence, scale_used, method, elapsed_ms)`。

**验收标准**：
1. 单元测试（卷六附录 F 用例清单）全绿：合成图命中/异色误报拒绝/尺度漂移命中/中文路径/region 复原/边界钳制；
2. 对既有 50 张模板跑回归对比脚本：命中率不低于现状、平均单轮耗时下降（**量化门禁（卷十校准）：命中场景 ≤100ms/轮（现状实测 240ms）、提速 ≥2.4x；同构异色用例在 rgb=True 下必须拒杀（卷十 E1 固化为 pytest 用例）**）；
3. 15 个调用点行为不变（不传新参数时返回值类型与坐标语义一致）。

**工作量**：~1.5 天。**风险**：中——置信度口径变化可能让原本"勉强命中"的场景变严格；缓解：`rgb` 字段默认 False（与 Airtest 一致），只对确认需要的模板开启彩色复验，渐进放量。**回滚**：模块独立，改回 `_match_template_multiscale` 旧实现即可。

## 3. 阶段 C：等待语义、错误类型与失败审计

**目标**：统一图像等待语义；类型化异常；失败自动落证；心跳钩子（对接影刃 P0-5）。

**Airtest 参照**：loop_find（cv.py:40-82）、TargetNotFoundError、try_log_screen、@logwrap 参数快照（logwraper.py:95-164）。

**改动文件**：

| 文件 | 改动 |
|---|---|
| `wt_projection_helpers.py` | 新增 `wait_template(template_key, timeout_seconds, interval=0.5, intervalfunc=None, expect=True) -> MatchResult`：`locate_template_center` 的轮询逻辑迁入；新增 `TemplateNotFoundError(RuntimeError)`（携带 last_best 结构化信息）；超时路径自动 `capture_debug_screenshot` 并把 MatchResult 写入 run report 上下文 |
| `wt_flow_executor.py` | 图像类 action 的等待统一走 `wait_template`；`image_appear` 等待条件（影刃 P0-4 后半句）注册为 continueWhen 谓词，返回 `MatchResult.confidence >= threshold` |
| `wt_run_reporting.py` | 失败步骤记录结构化匹配诊断（threshold/last_best.confidence/scale_used/method/elapsed_ms） |
| 心跳接线 | 影刃 P0-5 的防休眠心跳可注册为 `intervalfunc`（每轮失败喂一次 SetThreadExecutionState/日志心跳），或在 wait_template 内置默认心跳钩子（配置开关） |

**验收标准**：
1. `wait_template` 三态测试：立即命中 / 轮询后命中 / 超时抛 `TemplateNotFoundError` 且异常对象含诊断字段；
2. `intervalfunc` 被调次数 == 失败轮数；
3. 超时场景 logs 目录出现带步骤标识的调试截图；
4. 现有 `locate_template_center` 行为不变（内部改为薄壳调用）。

**工作量**：~1 天。**风险**：低-中（执行器接线面广，需回归 WT_AUT_recorded 全链路用例）。**回滚**：wait_template 独立函数，executor 接线逐 action 切换，可部分回退。
