## 2. 进程模型与运行时协议（实测证据）

### 2.1 启动序列（摘自 `%LOCALAPPDATA%\ShadowBot\log\20261002.log`）

```
12:56:51 Client Config init, WebApi=https://api.winrobot360.com/ ... Culture=Zh_CN
12:56:52 ShadowBot 6.2.23 Start...
12:56:52 python engine started, pid:3328                 ← C# 拉起 Python 引擎子进程
12:56:52 ApiHttpServer started on http://localhost:31500/api/v1 ... ← 本地 HTTP API 服务
12:56:53 StatsServer init success                        ← 埋点统计服务
```

**一图流：**

```
┌─ ShadowBot.Shell（设计器，WPF+CEF）────────────────────────┐
│  HTML 编辑器(CEF) ⇄ JS-Binding ⇄ C# Shell ⇄ Runtime.Development │
└──────┬──────────────────────────────────────────────┘
       │ 启动/回传（进程 stdout + 本地 HTTP :31500）
┌─ python310\xbot_interpreter.py（Python 引擎进程）──────────┐
│  stdin: JSON 参数 → robot.connect(robot管道) → uidriver.connect(uia管道) │
│  → import 流程模块 → mod.main(args) → stdout: 'xbot_out >>'+base64(json) │
│  内嵌：Recorder(执行审计) / StuckChecker(看门狗) / os_sleep(防休眠)      │
│        trigger\websocket_server(触发器) / pdbx(调试器分支)               │
└──────┬──────────────────────────────────────────────┘
       │ 命名管道（uia_pip / robot_pip）
┌─ ShadowBot.UIAutomation.Provider.exe（定位服务进程）────────┐
│  UIA / MSAA(ACC) / SAP / CV(Emgu.CV) / OCR / Web(CEF/CDP) / JavaBridge │
│  DriverInput（SendInput / interception驱动 / AutoIt 后台 / CDP输入）    │
└──────────────────────────────────────────────┘
```

### 2.2 解释器协议（`xbot_interpreter.py`，明文，全文关键行）

```python
params.parse_robot_input(input().encode('utf-8'))   # 第一行 stdin：JSON 启动参数
robot.connect(params.robot_pip())                   # 连接运行时管道
uidriver.connect(params.uia_pip())                  # 连接定位服务管道
os.environ['__SHADOWBOT_ROBOT_FOLDER__'] = ...      # 应用目录（应用加密需要）
mod = importlib.import_module(params.mod())
if params.is_debug():
    pdbx.set_trace()                                # 流程调试入口
...
mod.main(args)
print('xbot_out >>' + base64.b64encode(json.dumps({'xbot_out':...}).encode('utf-8')).decode('utf-8'))
```

设计要点（WT 可借鉴）：
1. **进程隔离执行**：流程跑在独立 Python 进程，崩溃不拖垮设计器；stdout 约定协议 `xbot_out >>` 前缀 + base64 JSON 回传输出变量。
2. **socket.setdefaulttimeout(30*60)**：进程级网络兜底超时，防止任何一次请求挂死整个流程。
3. **`__SHADOWBOT_SLOW_EXIT__`**：SIGINT 处理器可配置"缓慢退出"（先跑完 atexit 清理），避免强杀丢日志。
4. **`stuck_check` / `trace` / `os_sleep`** 三件套随引擎启动常驻（见 §5）。

### 2.3 分组件日志体系（实测 log 目录）

| 文件 | 对应组件 |
|---|---|
| `20261002.log` | 主进程（Shell/Runtime，含 JS 异常绑定转发） |
| `20261002.engine.log` | Python 引擎 |
| `20261002.provider.log` | 定位服务进程 |
| `20261002.launcher.log` | 无人值守启动器 |
| `20261002.bridgeinstaller.log` | 浏览器扩展桥安装器 |
| `20261002.ShadowBotBrowser.bridge.log` | 内置浏览器桥 |
| `20261002.wer.log` | WER 崩溃上报 |
| `cef_main.log` | CEF 子进程 |

**每个子进程一个独立日志文件**——任何一处卡死/崩溃都能单独归因。WT 目前是单文件 `wt_automation.log` + JSONL 事件，子进程复用同一文件。

### 2.4 本地 HTTP API 与触发器

- `http://localhost:31500/api/v1`：本地 REST API，供外部系统（OA/调度器/命令行）触发与查询——机器人即服务。
- 触发器子系统在 Python 引擎内：`xbot\_core\trigger\` 含 `trigger_manager / trigger_server / trigger_executor / websocket_server(6.6KB MIT 改版) / websocket_thread`。触发器事件经 WebSocket 送达引擎，再执行绑定流程。日志字符串中可见触发语义：`发现%close_button%按钮时，关闭弹框`、`发现%element%时，执行流程%process%`（弹窗守护）。

### 2.5 全局热键（`users\client.settings` 实测）

| 热键 | 功能 |
|---|---|
| AddBlock | 编辑器快速加指令 |
| CaptureImage | 全局图像捕获 |
| CaptureElement | 全局元素捕获（随手抓元素入库） |
| OpenShadowBotExplorer | UIA 探测器（类似 Inspect.exe） |
| RDPLockScreen | RDP 会话锁屏保持 |

### 3.1 包结构（解包 `FlowTemplates\blank.zip` 与 `magic_blank.zip` 实测）

```
my_app\
├── package.json          # 包清单
├── package.py            # 包级 API（选择器库/资源/全局变量门面）
├── package.sigstore      # 包签名（sigstore）
├── main.flow.json        # 流程图（kind:'visual'）
├── main.py               # 由 flow 编译生成的 Python 代码
├── selectorsV2.xml       # 元素选择器库
├── imagesV2.xml          # 图像选择器库
├── settings.json
└── .dev\                 # 开发态（不入包分发）
    ├── main.flow.json    # 编辑器工作副本
    ├── main.pdb          # 流程↔代码 行号映射调试符号
    ├── chat.db           # AI"魔法指令"会话库
    └── workspace.state.json
```

### 3.2 package.json 实测

```json
{
  "version": "1",
  "package_version": 2,
  "startup": "main",
  "robot_type": "activity",
  "flows": [{ "name": "main", "filename": "main", "kind": "visual", "opened": true }],
  "variables": [],
  "external_dependencies": []
}
```

要点：`flows[]` 多流程 + 每流程独立文件；`variables[]` 包级全局变量；`external_dependencies[]` 声明依赖的指令包（市场安装）。

### 3.3 选择器库 XML（selectorsV2.xml 实测框架）

```xml
<repository xmlns:x="rpa://selector/core"
            xmlns:regex="rpa://selector/operator/regex"
            xmlns:wildcard="rpa://selector/operator/wildcard">
</repository>
```

- 命名空间即扩展点：`core` 定义元素，`regex`/`wildcard` 是属性匹配操作符，第三方可注册新操作符命名空间；
- 引擎支持的节点类型（`selector.py` 常量）：`web / mac / wnd / uia / acc / java / hlay / sap / cv / mobile / linux`；
- 选择器对象带 `id / name / segments / version / framework / xpath / semantic() / type(xpath|anchor|normal)`，支持 V1/V2 双版本；表格目标用 `TableSelector(base, baseXpath, columns[])`；
- 属性值支持 `{{全局变量}}` 注入（含中文变量名）；ASCII 控制符转义存储（`&#x1E;` → `%_%x1E%_%`，读取时还原——处理真实网页里出现的控制字符）。

### 3.4 package.py 门面（实测注释翻译）

```python
package.selector('Button')            # 取元素库中名为 Button 的选择器
package.image_selector('Img')         # 取图像库中名为 Img 的图像选择器
package.resources.get_text('names.txt')   # 资源文件按文本读取
package.resources.get_bytes('users.xlsx') # 资源文件按二进制读取
package.variables['g_var1'] = 123     # 全局变量读写
```

### 3.5 编译与调试闭环

- flow JSON → Python 源码编译（`main.py`），可视化块一一对应函数调用；
- `.dev\*.pdb` 记录 **流程块行号 ↔ Python 行号** 映射；`pdbx.py` 是 CPython pdb 的完整分支（64KB），支持在设计器里对流程块打断点、单步，栈回溯时用 `XbotPdb.parse_stacktrace()` 把 Python 栈翻译回流程块位置；
- 错误栈按"块"呈现给用户，而不是暴露生成代码——**用户永远面向流程调试，不面向代码调试**。

## 6. 学习边界声明

- `winro.pyb`（5.1MB）为自研加密字节码，配合 `pyb.cp310-*.pyd` 原生扩展加载；`pdbx.py` 经全文检查是纯调试器分支，不含解密逻辑。**真实指令实现不可见**——本调研的指令行为结论全部来自：明文桩代码 docstring、`code.activities.xml`、DLL 内嵌 JSON 元数据、PDB 符号、日志与配置文件，均属产品自带的可见信息。
- 许可/加密体系未做任何逆向或绕过尝试；后续落地亦无此必要——影刃的可借鉴价值在架构与语义，不在代码本身。
- `web.pak`（46MB）为自定义加密包（头魔数非 CEF 标准），未继续解析；设计器 UI 层细节通过 DLL 字符串与日志佐证。

## 7. 本卷小结（WT 视角的三个"第一印象"差距）

1. **进程拓扑**：影刃是"设计器 / Python 引擎 / 定位服务"三进程 + 两管道 + 本地 HTTP API；WT 是单进程（加任务服务器）。UIA 挂起在影刃架构里只死一个 Provider 进程，在 WT 里会拖死整个运行（WT 已实测 742 秒挂起，只能靠探针绕）。
2. **元数据驱动程度**：影刃的 168 条指令面板、参数编辑器、文档、AI 语料全部由同一份 schema 生成；WT 的 19 个动作 schema 已走在这条路上，但指令的"参数语义"（超时三态、执行后延迟、通道选择）尚未沉淀成全库统一约定。
3. **可观测性分层**：影刃有"分组件日志 + 每指令参数快照 + 失败截图 + 录屏环形缓冲 + 卡死栈转储"五层证据链；WT 有结构化 run report + JSONL（骨架好），但缺每步输入值快照与录屏。

> 下一卷 → `02_影刃PC自动化指令体系全解.md`：168 条指令全目录、关键指令参数 schema 实录、元素/窗口/图像 API 逐个拆解。
