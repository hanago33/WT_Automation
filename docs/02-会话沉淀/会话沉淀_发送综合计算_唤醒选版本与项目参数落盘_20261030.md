## 2. 问题一：配置区"未唤醒"（preScrollToTop）

### 现象
日志反复出现：

```
[FlowLocator][preScrollToTop] step=step_copy_wait_editor 编辑器空白唤醒点击 (1728,260)
[FlowLocator][preScrollToTop] step=step_copy_wait_editor 未找到'风电场参数'Expander (FindAll=0)
[FlowLocator][preScrollToTop] step=step_copy_wait_editor 前台非 MUP，跳过空白唤醒点击
```

### 根因
1. `_prescroll_wake_blank_click` 在找不到 `WRAAnalysisEditorView_ScrollViewer_Edition` 时退到**整窗矩形**取 `(0.9W, 0.25H)`；1920×1040 窗口即 `(1728,260)` —— 落在右侧地图/顶部工具栏，从未碰到左侧配置区。现场实测：必须点输入框/下拉框这类实体控件才能唤醒控件树。
2. 等待步骤每 4 秒的"补唤醒"只调这个空白点击，等于空转。
3. 唤醒点击对同一 step 只执行一次（`_PRESCROLL_TOP_DONE_GLOBAL`），首次没点对就再没有机会。

### 修复（`wt_flow_locator.py`，同名逻辑同步到 `tools/generic_flow/generic_flow_locator.py`）
唤醒顺序重排为"真实控件优先"：

1. 配置指定控件：`preWakeControlId`（本步骤 controls 内的 id）或 `preWakeAutomationId`（+ 可选 `preWakeControlName` 名称包含匹配）
2. WRA 编辑器**当前激活页签头**（`MUPWRAAnalysisMainView_TabControl_MainTabs` 下浅层 BFS 找 TabItem，按 `SelectionItem` 选中态 / 键盘焦点判定；点已选页签不切页、不改表单值；只有一个页签时才允许在无法判定选中态时点击）
3. 编辑器滚动容器 `SetFocus`（程序化聚焦，零副作用）
4. 编辑器容器内空白点击——容器未实体化时**直接跳过**，绝不落到整窗坐标

配套：等待步骤的 4 秒周期补唤醒改成调用同一套 `_prescroll_wake_editor`。

### 代码位置（行号仅作参考，以函数名为准）

| 函数 | 作用 |
|---|---|
| `_step_config_text` | 读 actionConfig 文本项（`preWakeControlId` / `preWakeAutomationId` / `preWakeControlName`） |
| `_prescroll_foreground_ready` | 统一前台校验（非 MUP 先激活，仍不行则放弃点击） |
| `_prescroll_click_wrapper` | 点真实控件（退化矩形自动改走 UIA Invoke） |
| `_prescroll_iter_tab_items` | 页签条浅层 BFS 取 TabItem（限制深度，避免整树遍历 200s+） |
| `_prescroll_wake_selected_editor_tab` | 点当前激活页签头 |
| `_prescroll_wake_configured_control` | 按配置点指定控件 |
| `_prescroll_editor_rect` | 只返回编辑器容器矩形（不再退化成整窗） |
| `_prescroll_wake_editor` | 唤醒总入口（上面四步的顺序编排） |
| `_prescroll_wake_blank_click` | 兜底空白点击（仅容器矩形内） |

### 现场日志对照

| 修复前 | 修复后 |
|---|---|
| `编辑器空白唤醒点击 (1728,260)` | `已点击唤醒目标(真实控件): 编辑器页签[综合2]` |
| — | 容器未实体化时：`编辑器容器未实体化，跳过空白唤醒点击` |

```json

"preWakeControlName": ""
```
或 `"preWakeControlId": "<本步骤 controls 里的 id>"`。

## 3. 问题二：step_10 版本下拉选错（且假成功）

### 控件结构实证（`control_maps/standard/总控件信息.json`）

```
Button | PART_DropDownButton（名字"版本 下拉框"，运行时 UIA Name 为空）
       rect [1242,480]-[1665,522]；supportedPatterns 无 ValuePattern
Text   | WindTurbineTypeCurveParameter_TextBlock_Value（名字 "Cp0.429"）
       rect [1252,484]-[1622,517]    ← 真实显示值在这里（同行叠加）
optionValues = ["Cp0.429"]           ← 扫描只采到"当前值"一项
```

### 三个根因
1. **读不到显示值就报成功**：`_read_dropdown_display_text` 只读 ValuePattern / window_text / 子 Text，该按钮三者皆空 → `verify_value=""` → 走"显示值不可读，保留点击证据"直接 `return True`。
2. **反向包含被当成命中**：候选评分与点扫掠都用 `tt in text_norm or text_norm in tt`，`Cp0.4` 作为 `Cp0.429` 的子串可拿到 72 分越过 70 阈值并被点击。
3. **单元素 optionValues 驱动 HOME 导航**：`["Cp0.429"]` 只被当作当前值，index 算成 0 → 发 `{HOME}` 归零 + `{ENTER}`，高亮落到真实列表首项。

### 修复
| 措施 | 函数 |
|---|---|
| 支持读"同行值文本"作为显示值（中心落在下拉框矩形内的 Text，排除控件自身标签） | `_read_dropdown_row_value_text` |
| 显示值读取加父级类型守卫（父级是 Window/Desktop 时放弃，避免遍历桌面） | `_read_dropdown_display_text` |
| 目标匹配：等值或**正向包含**；尾随是数字视为更长编号（`Cp0.4291 ≠ Cp0.429`） | `_dropdown_display_matches_target` |
| 候选前置否决 / 点扫掠统一严格匹配（显式目标时禁止反向包含） | `_dropdown_candidate_token_matches`、`_sweep_dropdown_option_by_point` |
| 扫掠弱命中只记录（`weakHitText`）不点击，交回键入搜索 | `_sweep_dropdown_option_by_point` |
| 索引导航仅在 `optionValues` 可信（资产注入或 ≥2 项）时启用；包含匹配要求唯一命中 | `select_dropdown_item_runtime` |

### 影响面（已逐一核对）
- 其它下拉步骤（`step_18` / `step_24a` / `step_mt_refpoint` / `step_mt_extreme_ref`）目标都是**等值**或"目标⊂候选"，严格化不影响；只有"候选⊂目标"这条错误分支被掐掉。
- 值检查捷径只读 ValuePattern（不读同行文本），避免把控件自身标签当当前值。

### 流程侧调整（`flow_definition_发送综合计算.json`）
- `step_10`：`timeoutSeconds 3→6`、`retryCount 0→1`（首次校验失败会重新展开再选一次），notes 记录成因。
- 跑完看日志：成功为 `已通过运行时下拉候选点击控件并校验显示值 … value=Cp0.429`；失败会明确打 `expected=Cp0.429 actual=…`，不再假成功。

## 4. 问题三：GoBack 连续误报"未命中控件"

### 现象
```
流程控件定位失败: step=step_copy_goback_scan3_44, control=ctrl_close_editor, seconds=2.99 … 未就绪
步骤执行失败但继续: … error=action click 未命中控件
```
scan3 / scan4 / scan5 各一次，均发生在 HPC 之后。

### 根因
`MUPHeaderedClosableContentControl_Button_Close` 在扫描里有多处同名实例；且 HPC 提交后 MUP 常已自动回到综合列表，关闭按钮随编辑器一起消失 → 再点必然失败。

### 修复
1. 执行器新增前置条件 `skip_if_gone`（`wt_flow_executor.py` + `tools/generic_flow/generic_flow_executor.py`）：
   - `controlId` 存在 → 正常执行动作；
   - `controlId` 缺席 **且** `alsoGoneControlId`（编辑器容器 `WRAAnalysisEditorView_ScrollViewer_Edition`）也缺席 → 按幂等跳过（`status=skipped`，不计失败）；
   - 只缺席动作控件、容器仍在 → 不跳过，让真实失败暴露。
2. `step_copy_goback`：加 `precondition={"condition":"skip_if_gone","controlId":"ctrl_close_editor","alsoGoneControlId":"ctrl_editor_container","timeoutSeconds":6}`，新增控件 `ctrl_editor_container`（`WRAAnalysisEditorView_ScrollViewer_Edition,Pane`）；`timeoutSeconds 2.5→20`、`retryCount 1`。
3. `WT_Flow_Editor`：保存时条件未变则**保留 precondition 扩展键**（否则编辑器保存一次就会把 `alsoGoneControlId` / `timeoutSeconds` 裁掉）；下拉选项补 `wait_visible` / `wait_exists` / `skip_if_gone`。

## 6. 问题五：项目参数（Cp 版本）不生效

### 设计原意（不写流程文件）
项目参数**不进流程 JSON**，而是运行期注入后覆盖 `stepParams`：

```
项目参数弹窗「保存」→ self.project_params（launcher_state）
  → parse_project_work_dir(work_dir, project_params)      # 人工值覆盖解析值
  → runtime_config["cpVersion"]
  → GM_RUNTIME_CONFIG_JSON（本地 WT_Launcher；远程 wt_task_server 启动 worker 时）
  → WT_AUT_recorded：if _rt_cp and "cpversion" in _sp: _sp["cpversion"] = _rt_cp
  → step_10 的 ${stepParams.cpversion}
```
所以流程/参数表里始终显示 `Cp0.429`（参数表的值）是正常的。

### 三个断点与修复（`35f229f`）

| 断点 | 现象 | 修复 |
|---|---|---|
| `<项目>/project.params.json` 只读不写 | 参数只存本机，换会话/换机器/worker 拿不到 | 新增 `save_project_params_to_work_dir()`（原子写、空值不入库、清空即删文件），项目参数弹窗保存时同步落盘 |
| 重选项目文件夹清空手填值 | 同一目录再选一次，Cp 版本就"消失" | `_simple_select_work_dir`：文件存在用文件；文件缺失且**同目录**保留手填值；换项目才清空 |
| 非 Simple 入口提交的任务 runtimeConfig 为空 | worker 无从覆盖 | `WT_AUT_recorded._fill_runtime_from_project_params()`：有 `projectWorkDir` 就用项目目录的 `project.params.json` 补缺失项（只填空缺、不覆盖已有非空值） |

### 入口矩阵（现在谁能拿到项目参数）

| 入口 | 提交时带 runtimeConfig | 运行期兜底 |
|---|---|---|
| Simple 本地运行 | ✅ `parse_project_work_dir` | ✅ |
| Simple → 提交到远程队列 | ✅ `_prepare_remote_sections` | ✅ |
| 队列窗口「本地 JSON / 提交任务」 | ❌ 无项目目录概念 | 若任务带 `projectWorkDir` 则 ✅，否则无 |

### 现场核对用日志
```
项目计算参数已保存（6 项），并已写入项目目录 project.params.json
[projectParams] 项目目录参数补齐（1 项）：cpVersion
[paramTable] 项目解析值覆盖参数表默认（1 处）：cpversion:Cp0.429->Cp0.425
```
第三条缺失 → 注入链断了（弹窗没保存 / 项目目录没选 / 走的入口不带参数）；有第三条但下拉仍不对 → 选择逻辑问题（见第 3 节）。

### 补充：参数表 vs 项目参数，谁是准？
- **参数表**（`flow_packages/param_table_发送综合计算.json` 的 `cpVersion` 列）：决定"流程文件里写的是什么"，给不同项目复用同一份流程时它是默认值；
- **项目参数**（界面弹窗 + `project.params.json`）：运行期覆盖，只影响本机/本次任务。
- 两者都为空时：`${stepParams.cpversion}` 会被替换成空串，该步退化为"按控件名找选项"，基本选不上——create/copyfull 行必须填。
